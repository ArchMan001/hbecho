# 产品方向

- hbecho 的目标是把账号与内容采集、活动考核规则、统一指标和受控数据访问串成可追溯的平台能力。
- 当前优先交付 `data-foundation-tracer`：先证明一个账号从主页入口到稳定身份、归属、主页快照、首屏内容、检查点和媒资进度的纵向链路。
- AI Master 是数据底座内部供应商适配器，不单独建设大而全的 API 平台。
- 主依赖顺序为：数据底座 → 规则引擎 → 指标与看板；访问控制、审计、成本与配额是横切关口。
- 首版以抖音和小红书 tracer 为验收样本；未实测的平台或 action 必须能力门控，不得因枚举存在就宣称支持。
- 不创建覆盖全项目的巨型 Spec。每个 Spec 应形成一个可独立验收的纵向结果。
- 产品目标、阶段、模块地图和未决项以 `HBECHO设计方案/prd-platform.md` 为准；文档导航与权威顺序以 `HBECHO设计方案/INDEX.md` 为准。
