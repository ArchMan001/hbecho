# hbecho 项目宪法（constitution）

**版本**：v1.0 · 2026-11-04 · 整理：Claude（定位调整：刘学奎）
**状态**：`current（索引）`——**不要求逐条确认**。本文件是跨模块条款索引，不新增事实、不裁决冲突；冲突时以 `HBECHO设计方案/INDEX.md` §3 的权威顺序与原文为准。
**本版性质**：不新增任何决策，只从既有文档中提取规则。

**权威关系**：本表是索引，不裁决冲突；规则的有无与边界以 INDEX §3 的权威顺序与原文为准。两者不一致时，必须在同一次变更里修改本表与原文，不许只改一处。

**收录标准**：同时满足四条才进本表——不可协商、违反会静默失败或不可逆、可判定、跨模块。不满足的留在原文，不搬进来。

## 当前守护能力（先读这一节）

「守它的地方」只写**今天真实存在**的手段。没有脚本或测试守的写「人工审查」，不把规划中的机制写成防线。

| 已存在 | 不存在（因此相关条款当前只能靠人工） |
|---|---|
| `.githooks/pre-commit` 密钥扫描（文件名 + 内容特征，四种拦截已实测） | 应用代码、DDL 与迁移脚本 |
| `.gitignore` 凭证与本地文件忽略规则 | 测试套件、fixture |
| MySQL 8.0.46 + `STRICT_TRANS_TABLES`（CHECK 约束已实测生效，但**尚无任何业务 CHECK 落地**） | CI 门禁、静态检查脚本 |
| OSS 四桶 RAM 权限边界（media/backup 无删除权限，已实测） | 长事务告警、逻辑备份 |
| OSS 生命周期规则（media 无过期规则，已实测） | 自动化的文档/规格一致性检查（本文件落地时新增 `scripts/verify.sh`） |

**环境定位（2026-10-25 用户确认）**：现有唯一实例 `i-2zef8qpi1d2mldntjgrv` 是**测试环境**，不是生产环境；生产 ECS 未购买。因此测试允许在该实例上运行，但必须使用一次性库容器（见 `.kiro/steering/server-access.md` 第 5 条）。C16 的「生产机不跑测试」在购买并登记生产 ECS 后生效。

## 条款

| # | 条款 | 规则（违反会怎样） | 原文 | 现在谁在守 |
|---|---|---|---|---|
| C1 | 平台与数据供应商是两个维度 | `platform_id` 与 `provider_code` 必须分列，任何表、查询或能力门控不得互相替代、推导。合并后同一平台账号会在换供应商时被拆成两个身份，或不同平台的数据被归到一起，且不报错。 | `CONTEXT.md` 领域不变量 1；`database-design-v2.md` §6 | 人工审查；v2 表结构落地后由复合外键守 |
| C2 | 组织与业务实体不得压成一行 | Brand、Region、Branch、Sector、Dealer、Store、MediaStaff、ExternalAccount 各自独立主档；不得用名称、手机号、昵称或旧模型字段合并。一个人承担多个品牌身份时，必须是不同 `MediaStaff`，不能共用一个自然人档案。 | `CONTEXT.md` 不变量 2、3、4；`.kiro/steering/tech.md` | 人工审查；DDL 落地后由唯一键与复合外键守 |
| C3 | 外部标识按原始文本与命名空间解释；账号不合并 | 外部 ID 不得经过 JS 安全整数或其他有损数值转换；写入与查找必须同时带 platform 与 `identifier_namespace`，哈希命中后复核原文。昵称、头像、主页 URL 变化不改变账号身份；账号合并首版不允许。昵称不能作为绑定证据。 | `CONTEXT.md` 不变量 7、8；v2 §8.1–§8.2；tracer R5 | 人工审查；tracer 任务 2/5 的跨实现 fixture（待实现） |
| C4 | 归属是账号上的当前单一事实，不抢占、不物理删除 | 一个账号只有一条当前归属，归属与账号是同一业务记录；采集不得抢占；改绑只能由受审计的管理员操作；离职账号停采、归属不变；门店停用则账号停采；组织、人员、账号不物理删除，业务主档不使用 `ON DELETE CASCADE`。 | `CONTEXT.md` 不变量 5、19；PRD D-16～D-18、D-28 | 人工审查；DDL 落地后由唯一约束守 |
| C5 | 业务状态与监控开关相互独立 | 实际监控由完整归属链（品牌/大区/分公司/经销商/门店/专员/归属）的业务状态与各自开关共同计算；停用不等于暂停监控；上级恢复后不得改写下级开关值。把两者合并会导致恢复时意外开启采集并产生费用。 | `CONTEXT.md` EffectiveMonitoring；v2 §12.3 | 人工审查；同步计划实现后的测试（待实现） |
| C6 | raw-before-parse | 每次供应商提交、轮询、分页或重试，必须先把 request bytes 与 prepared intent、再把完整 response bytes 或传输错误原文写入私有 ODS 并验证，之后才允许适配器解析。ODS 写入或完整性验证失败时，不得解析、不得产出业务事实。 | `CONTEXT.md` RawPayload；v2 §12.4；tracer R2 | 人工审查；tracer 任务 3 的 fake OSS 故障注入（待实现） |
| C7 | 网络 IO 期间不持有数据库事务 | 供应商 HTTP、媒资下载、OSS 上传全部在事务外；用 `prepared → in_flight → terminal` 的短事务分段。把 HTTP 写进事务会造成锁堆积，并在崩溃时丢失已付费调用的意图记录，通常不会立刻报错。 | v2 §12.4；`.kiro/steering/tech.md` | 人工审查；长事务告警（runbook §12.2，未配置） |
| C8 | 已返回的每一页必须完整处理 | 不得按本地 `initial_content_limit` 截断已返回页；检查点只在整页全部 entry 到达结构化终态后推进；任一 entry 投影失败不得推进检查点。截断会让第 21 条永久缺失，而检查点已经越过它。 | `CONTEXT.md` 不变量 11；tracer R9、R10 | 人工审查；tracer 任务 5/6 的 20/21 条 fixture（待实现） |
| C9 | 真实 0、缺失、显式 null、非法值互不转换 | 四种状态必须分别保留；同批次后到的有效值（含真实 0）覆盖先前值，后到的缺失、空值或非法值**不得擦除**先前有效值。跨批次由逻辑上较新的批次优先。把 0 当成缺失会静默改变指标分母。 | `CONTEXT.md` ValueState、LaterValidValueWins；`.kiro/steering/tech.md` | MySQL 严格模式（已启用）；业务 CHECK 与投影测试（待 DDL）；人工审查 |
| C10 | 每账号每批次单份最终快照，current 不得倒退 | 同一账号下的同一内容必须先汇集本批次该账号的列表来源与所需详情结果，再形成唯一 `finalized` 快照；仍在合并的快照不得成为 current；旧批次迟到只保留历史，不得回退 current 或检查点。 | `CONTEXT.md` 不变量 12、18；v2 §12.5–§12.6 | 人工审查；受限写入过程与复合外键（待 DDL） |
| C11 | 评论只存最新态；部分分页不得判删除 | 只有完整获取全部一级评论并自然结束分页后，先前存在但本次未出现的评论才可标为疑似删除；部分分页、限流或失败绝不能作为删除证据；重新出现后恢复有效。 | `CONTEXT.md` SuspectedDeletedComment | 人工审查（tracer 首版不含评论） |
| C12 | 临时 URL 不是媒资身份 | 正式媒资按完整下载字节的 SHA-256 判同，相同字节的多个引用共享同一资产；签名 URL 只作下载线索，不得写入长期业务事实；本轮下载失败可以续用旧资产，但必须记录本轮失败，不得表示为本轮归档成功。 | `CONTEXT.md` MediaAsset、MediaReference；v2 §11；tracer R12 | OSS RAM 权限（media/backup 无删除权限，已实测）；人工审查；tracer 任务 7（待实现） |
| C13 | 保留期与清理边界不可混淆 | ODS 调用元数据与原始载荷一年后按 payload → call → task → 无引用 object 的顺序清理；结构化快照、历史归属、正式媒资不随之删除；`media` 桶不得配置任何过期规则。生命周期规则抢在应用清理之前，会造成「数据库说证据在、实际字节已删」。 | `CONTEXT.md` OdsRetention、FormalMediaRetention；v2 §12.7；runbook §7.4 | OSS 生命周期实配 + runbook §13.3 验收（已执行）；清理器 fake clock 测试（待实现） |
| C14 | 幂等、租约与 fencing | 同一 idempotency key + canonical payload 在一年内必须返回同一 root；任务重试不得制造重复业务事实；陈旧 worker 不得提交 current、检查点、归属或媒资终态。重复重试可能造成重复付费调用。 | `CONTEXT.md` SyncTask；tracer R1、R18；v2 §9.3 | 人工审查；tracer 任务 2/8 的 fake clock 与 fence 测试（待实现） |
| C15 | 未验证的 capability 不得启用 | platform × action × mode × environment 必须有明确证据等级；`fixture_observed` 不得激活 production；`raw3` 只能证明 fixture 行为，不能外推为供应商长期合同。把未验证的异步模式当成生产可用会导致调用失败或计费失控。 | 总纲 §5.9、§8.2；tracer R13、R17 | 人工审查；tracer 任务 1/8/9（待实现） |
| C16 | 默认测试离线；生产机不跑测试 | 默认测试使用 fixture、fake transport、fake clock、fake OSS，网络禁用，不需要 AI Master secret；CI 禁止任何真实付费调用；生产 ECS 永不运行测试、`verify`、`pytest` 或迁移演练。一次误跑就可能清空生产库。 | `.kiro/steering/tech.md`；tracer R16；runbook §8.2 | 人工纪律（当前）；CI 与测试机隔离（本文件落地时开始建立） |
| C17 | 服务器只走 Workbench；生产写操作逐步确认 | 读状态、跑命令、传文件、部署、看日志一律用 Workbench CLI；禁止 `ssh`、`scp`、`sftp`、`rsync -e ssh` 与任何 SSH 端口转发。部署、迁移、改配置、删数据、改安全组必须先说明并得到明确同意，不批量执行。 | `.kiro/steering/server-access.md`（2026-10-14，明确适用于 hbecho）；runbook §3.4、§4 | 人工纪律；runbook 流程 |
| C18 | 未决项不得被默认值静默冻结 | `HBECHO设计方案/INDEX.md` §10、产品总纲 §12、v2 与各 spec 的未决项必须在实现、示例与配置中保持显式；没有结论时使用 capability gate 或默认拒绝。一个示例值变成事实标准后，后续模块会基于错误前提开发。 | `HBECHO设计方案/INDEX.md` §10；总纲 §12；`.kiro/steering/tech.md` | 人工审查；spec 评审 |

## 与「暂缓 / 规划中」有关的说明

- **静态门禁与测试**：C3、C8、C9、C10、C14、C15 的自动化守护依赖 tracer 任务 1–8。在它们落地之前，上表的「守它的地方」如实写着人工审查，不要把这些条款当成已被机器守住。
- **DDL 尚未存在**：v2 的 30 表是文字基线，仓库里没有迁移脚本。因此所有「由 CHECK/唯一键/复合外键守」的条款，当前实际守护力为 0，直到第一版 DDL 合入并在 §13.1 的破坏性验收下通过。
- **本文件不含决策**：18 条全部来自既有文档。若确认过程中要新增或修改条款，必须按 C18 与项目惯例写明决策人、日期，以及它推翻了什么旧写法。
