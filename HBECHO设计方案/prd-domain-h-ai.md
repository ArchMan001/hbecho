## 一、这个域管什么

### 1.1 四个问题

```text
模型怎么统一出去   →  Key 托管、模型路由、成本计量、审计、降级
Prompt 怎么管      →  模板、变量、版本、谁能启用（仅超管）
内容怎么看         →  超管/总部对单条可见内容做脚本分析
业务 AI 怎么用     →  1.0 只保留 D 第三层的 ASR + 大模型判定
```

### 1.2 不管什么

| 事情 | 归谁 |
|---|---|
| 识别信号的语义、ASR/图片/视频理解的输出 schema | C 识别能力（H1 只提供模型调用通道） |
| 规则执行、判定、发布、重算 | D 规则与考核 |
| 内容、账号、媒资的事实与采集 | A 数据底座 |
| 登录、Capability、DataScope、审计可见性 | B 访问控制 |
| 指标口径、点检表、看板与导出 | E 指标与看板 |
| 配额、预算、账单、部署 | I 运维与成本 |
| 知识库、RAG、Agent、评测、微调 | 2.0 或不做 |

### 1.3 一条主线

```text
H5（超管/总部）：可见内容快照 → H1 检查能力/预算 → 模型分析 → 结构化建议
D 第三层（业务）：ASR + 大模型判定 → 经 H1 计量/审计 → C 产信号 → D 判定
超管：查看 AI 调用与成本、启用/回滚 Prompt 版本
```

**H 的职责到"可复核的 AI 结果"为止。** 它不替 C 定义信号，不替 D 发布规则，不替 A 存内容，也不替 I 管预算。

### 1.4 1.0 的边界

| 模块 | 1.0 | 说明 |
|---|---|---|
| H1 AI 网关 | ✅ | 模型调用、Key、路由、降级、缓存、成本、审计 |
| H2 Prompt 管理 | ✅ 极简 | 版本化模板，研发发布、**仅超管**启用 |
| H5 脚本分析与仿写 | ✅ 单条 | **仅超管与总部人员**；只分析可见内容快照；不粘贴文本 |
| H8 规则辅助生成 | ❌ 2.0 | 1.0 不做 |
| H3 知识库 / H4 知识审核 | ❌ | 2.0 |
| H6 合规审核（RAG） | ❌ | 2.0 |
| H7 营销 Agent | ❌ | 2.0 |
| H9 评测闭环 | ❌ | 2.0 |

## 二、用户与场景

### 2.1 谁在用

| 角色 | 在 H 域做什么 | 依据 |
|---|---|---|
| `platform_admin` | 使用 H5；查看全部 AI 调用与成本；启用/回滚 Prompt 版本 | `ai.content.assist`、`config.manage`、`audit.read` |
| `hq_manager` | 使用 H5 分析授权品牌内可见内容；**看不到**全局 AI 调用与成本；不能启用 Prompt | `ai.content.assist` |
| `branch_manager` | **不使用 H5/H8**；只在 D 的监控判定计划第三层参与判定配置/执行（以 B 的 Capability 为准） | D 的 `rule.definition.*` |
| `store_staff` | **不使用 H5/H8** | — |
| 系统（C） | D 第三层的 ASR + 大模型判定，经 H1 计量与审计 | 服务身份，无用户 Grant |

> **H5 不开放给分公司与门店。** B 域 `ai.content.assist` 在 1.0 只授予 `platform_admin` 与 `hq_manager`（B v1.19）。
>
> **业务侧的 AI 只有一条**：D 第三层的 ASR + 大模型判定。它由 D 的监控判定计划触发，C 拥有信号语义与标准，H1 负责 Key、成本、审计与降级。

### 2.2 两条真实路径

1. **总部审脚本**：`hq_manager` 在授权品牌内打开一条可见内容，点「AI 分析」，看到亮点、结构、问题与改写建议；结果只是建议，不会自动改内容或发布；`hq_manager` 看不到全局 AI 成本。
2. **D 第三层判定**：监控判定计划进入第 3 层，D 用表单标准触发 ASR + 大模型判定；每次调用经 H1 记录 Key、模型、Prompt 版本、token、估算成本与审计；业务用户只看到判定结果与"未获取成功"原因，不看到成本。

### 2.3 规模

- H5：超管与总部人员按需使用，单条、低频；不做批量。
- D 第三层：按监控判定计划候选集调用，量级由 D/C 的候选控制。
- 具体模型单价、token 上限与预算数值见 §11，不在本文冻结。

### 2.4 1.0 的边界

| 做 | 不做 |
|---|---|
| H1 统一出口、Key、成本、审计、降级 | 模型训练、微调、私有化部署 |
| H2 Prompt 版本化与超管启用 | 业务自由编辑 Prompt、Prompt 市场、A/B 实验 |
| H5 超管/总部单条脚本分析 | 分公司/门店使用、批量分析、任意 URL、粘贴文本、自动发布 |
| D 第三层 ASR + 大模型经 H1 | H8 规则辅助（2.0）、多轮对话（2.0）、Agent、知识库 |
| 超管看 AI 调用与成本 | 总部/分公司看 AI 成本、完整成本看板（I2 2.0） |

## 三、概念

### 3.1 模型能力（ModelCapability）

一个可调用的模型 = **供应商 + 模型标识 + 版本 + 能力标签 + 价格 + 证据等级**。

- 能力标签至少区分：文本生成、结构化输出、ASR、图片理解、视频理解；
- 证据等级：`declared` / `fixture_observed` / `smoke_verified` / `production_approved`；
- **未达到 `production_approved` 的模型 tuple 不得在 production 启用**；未验证的模型只能用于默认离线测试或人工批准的 smoke。

### 3.2 Prompt 模板（PromptTemplate）

- 固定 `prompt_id`、用途、变量清单、输出 schema、兼容模型集合；
- **版本不可变**；修改产生新版本，旧版本保留可查；
- 启用版本与回滚**仅超管**可操作，记审计；
- Prompt 内容不得包含 secret、真实个人数据或未脱敏业务数据。

### 3.3 一次 AI 调用（AICall）

每次调用至少记录：

```text
call_id
caller（用户或服务身份）
purpose（H5 / D-ASR / D-LLM）
model（供应商 + 模型 + 版本）
prompt_id + prompt_version
input_sha256 + input_kind
output_sha256
scope_fingerprint
tokens（输入 / 输出）
estimated_cost
latency_ms
status（success / failed / rejected / budget_exceeded）
error_code
```

- **不记录原始内容副本、secret、完整 Prompt 正文、临时 URL**；
- 输入/输出只留哈希与必要摘要；需要复核时由调用方按自己的 DataScope 重新取原文；
- **AICall 与成本仅超管可查**（B v1.19 `audit.read`）。

### 3.4 脚本分析（ScriptAnalysis）

H5 的输出，不是 A 的内容事实，也不是 D 的判定。字段：

| 字段 | 含义 |
|---|---|
| `summary` | 一句话概括 |
| `hook` | 开头钩子 |
| `structure` | 内容结构（开场 / 主体 / 结尾） |
| `highlights` | 亮点 |
| `issues` | 问题与风险 |
| `suggestions` | 改进建议 |
| `rewrite_draft` | 可选的改写草稿 |
| `model` / `prompt_version` | 可复核信息 |

> 成本不在业务结果里展示；只在超管可见的 AICall 中记录。

### 3.5 DataScope 继承

- H1 **不直接查数据库**，不持有业务数据；
- H5 在发起调用前，由调用方按 B 的 Capability + DataScope 取到可见内容快照，并把 `scope_fingerprint` 传给 H1；
- 返回结果前，H5 再按当前范围复核一次；撤权后不得返回；
- 模型不得以"模型需要"为理由扩大范围，也不得把超范围数据拼进 Prompt。

## 四、H1 AI 网关

### 4.1 唯一模型出口

1.0 的模型调用默认经 H1 出去：H5，以及 D 第三层的 ASR + 大模型判定。Key、路由、成本、审计、降级只有一处实现。

- **D 拥有判定语义**：第三层的标准、Prompt 内容、输出 schema、判定结果仍归 D；
- **C 拥有 ASR/识别信号的语义**：转写文本、信号五态仍归 C；
- **H1 拥有调用通道**：模型选择、Key、超时、重试、成本、审计、降级；
- 边界写进 `h-ai-min` spec；D/C 的 Prompt 版本由各自定义、由 H2 存版本，H1 执行。

> **2026-11-04 已定**：D 第三层的 ASR 与大模型调用 **100% 经 H1**；Key、成本与审计只有 H1 一处承担。

### 4.2 Key 托管

- 模型 Key 只放服务端密钥管理，不进仓库、日志、Prompt、前端；
- 每个供应商独立 Key，按环境隔离；
- 轮换 Key 不需要改业务代码；轮换记录审计；
- 应用容器不持有长期 Key；运行时按需取短期凭证或由网关代理。

### 4.3 模型能力门控

- H1 维护 ModelCapability 注册表；
- 只路由 `production_approved` 的模型；未验证的模型返回 `UnsupportedCapability`，不发真实请求；
- 模型版本升级视为新 tuple，必须重新验证；
- 降级模型也必须已验证；
- 具体模型、价格与上下文上限在 `h-ai-min` spec 与 ADR 中冻结，本文不选型。

### 4.4 路由与降级

- 按用途（H5 / D-ASR / D-LLM）选择模型；
- 主模型超时、限流或供应商 5xx 时，可按预先验证的 fallback 规则降级；
- 降级必须记录 `fallback_from` / `fallback_to` 与原因；
- 没有已验证 fallback 时返回稳定错误，不伪造结果；
- 不在一次调用中无限重试；重试次数、间隔与预算由 I7 与 spec 定。

### 4.5 成本与预算

- 每次调用记录输入/输出 token、估算成本、供应商与模型版本；
- 单次调用有硬上限；超过上限在下一次调用前停止；
- 日/月预算与并发上限由 I7 配置；H1 在调用前检查，超限返回 `budget_exceeded`，不发请求；
- 成本是**估算值**，最终以云账单为准；
- **AI 成本与全部调用仅超管可见**；总部/分公司不看到 AI 成本；
- 成本记录供 I2 最小成本视图与 B 审计使用，H 不自己做完整看板。

### 4.6 缓存

- 缓存键 = `prompt_id + prompt_version + model + input_sha256 + 参数`；
- 命中缓存也要重新检查调用者范围指纹；范围不同不得直接返回；
- 缓存 TTL、可缓存用途由 spec 定；含敏感内容的输出默认短 TTL 或不缓存；
- D/C 的信号缓存仍按各自复用键，不与 H1 缓存混用；
- 缓存命中不重复计费，但仍记一条 `cache_hit` 调用记录。

### 4.7 审计

- 每次调用写一条 AICall；记录 §3.3 的字段；
- 不记录原始输入/输出、secret、完整 Prompt；
- 审计保留期随 B 域（1.0 一年）；成本记录随 I 域；
- 审计写失败按 B 域策略处理；高风险调用优先保证审计；
- **AICall 与成本仅超管可查**。

### 4.8 范围与数据边界

- H1 不查 A/B/D/E 的库；输入由调用方按范围取好再传入；
- H1 不提供"给我一个账号/内容"的通用取数接口；
- H5 的输入在调用前和返回前各查一次范围；
- D 第三层的输入由 D 按计划范围提供，H1 不扩大；
- 模型输出不得包含调用者范围外的数据；发现即拒绝返回并记质量问题。

### 4.9 失败语义

| 情形 | 行为 |
|---|---|
| 模型超时 / 限流 / 供应商 5xx | 按 fallback 规则；无 fallback 返回稳定错误 |
| 模型拒绝生成 / 内容安全拦截 | 返回 `refused`，不伪造建议 |
| 输出 schema 不合法 | 返回 `invalid_output`，不把半成品交给业务 |
| 超出预算 / 并发 | 调用前返回 `budget_exceeded` / `rate_limited` |
| 模型未验证 | 返回 `unsupported_capability`，不发请求 |
| D/C 的调用失败 | 信号记 `failed` / unknown，不写成 0 或空值 |

### 4.10 服务身份

- H1 是内部服务，不直接对业务用户暴露；
- 只有 H5、D 第三层、C 可调用；
- H1 不继承任何用户 Grant；调用者必须显式传 `caller` 与 `scope_fingerprint`；
- H1 不提供导出、下载、原始数据查询。

## 五、H2 Prompt 管理

### 5.1 模板与版本

- 每个 Prompt 有 `prompt_id`、用途、变量清单、输出 schema、兼容模型；
- 版本不可变；修改产生新版本；
- 启用版本、回滚到旧版本都记审计；
- 旧版本保留可查，但不再用于新调用（除非显式回滚）。

### 5.2 1.0 极简

- 1.0 **不做业务人员自由编辑 Prompt**；Prompt 由研发随版本发布，**仅超管**通过 `config.manage` 启用/回滚；
- 不提供 Prompt 市场、A/B 实验、变量可视化编辑器；
- H5 / D / C 的 Prompt 内容分别由 H / D / C 负责，H2 只存版本与启用状态；
- Prompt 变更不得改变已有判定结果；需要重算时按 C/D 的显式重算规则。

### 5.3 权限与审计

- 查看 Prompt 版本与 AI 调用：仅超管；
- 启用/回滚：`config.manage`（仅超管）；
- 研发发版：走代码与迁移，不在业务界面；
- 审计记录 Prompt ID、旧版本、新版本、操作者、时间、原因。

## 六、H5 脚本分析与仿写

### 6.1 输入

- **单条内容**：调用者可见的内容快照 ID；H5 通过 A/B 的范围接口取原文，不自己爬平台；
- **不允许粘贴任意文本**（H-D03）；
- 不接受任意 URL、短链、视频文件上传或批量列表；
- 分公司与门店**不开放 H5**（H-D02）。

### 6.2 权限与范围

- Capability：`ai.content.assist`；B v1.19 只授予 `platform_admin` 与 `hq_manager`；
- 数据范围：`platform_admin` 全部品牌；`hq_manager` 只限授权品牌；
- 返回前再查一次范围；撤权后不得返回结果；
- 不返回其他品牌的内容或标题。

### 6.3 输出

- 使用 §3.4 的结构化字段；
- 输出是**建议**，不是内容事实，不是判定，不自动改写或发布；
- 必须带模型与 Prompt 版本；**不在业务结果里展示成本**；
- 不允许自由散文替代结构化字段；`rewrite_draft` 可选，但不得直接写回 A。

### 6.4 存储与审计

- 1.0 **不保存分析历史的正文**；结果只返回给调用者；
- 审计记录 AICall（§3.3），保留一年，**仅超管可查**；
- 用户可对同一内容重新分析；重复调用按 H1 缓存与计费规则处理；
- 2.0 若需要历史，再单独设计。

### 6.5 失败

- 模型失败、拒绝、schema 不合法时显示错误，不返回空建议或伪造建议；
- 内容不可见、快照缺失、账号不可访问时，按 A 的失败语义提示，不发起模型调用；
- 超预算/限流时提示稍后再试，不自动降级到未验证模型。

### 6.6 不做

- 分公司/门店使用、批量分析、跨账号对比、自动生成内容并发布、任意 URL、粘贴文本、图片/视频理解（C 的识别能力，不在 H5）、评分/排名。

## 七、H8 规则辅助生成（2.0，不在 1.0）

## 八、成本、配额与门控

### 8.1 默认离线

- 默认测试使用 fake model / fixture transport，网络禁用，不需要供应商 secret；
- CI 禁止真实付费调用；
- H5 与 D 第三层的自动化测试只验证请求构造、schema 校验、范围检查、失败语义与成本计数，不验证模型质量。

### 8.2 真实 smoke

- 真实调用必须人工批准、显式开关、固定预算与 deadline；
- smoke 只验证最小 tuple（H5 单条、D 的 ASR 单条、D 的 LLM 单条），不批量；
- 输出 audit summary：模型、Prompt 版本、调用数、tokens、估算成本、延迟、结果类别；不含 secret 与完整内容；
- 未通过 smoke 的模型 tuple 保持 disabled。

### 8.3 预算与限额

- 单次调用、单用户/日、单品牌/日、全局/月都有硬上限；
- 超限在下一次调用前停止，不"先调用再告警"；
- 预算、并发、重试上限由 I7 配置；H1 执行；
- 成本视图归 I2；H 只提供计数与审计；**仅超管可见**。

### 8.4 审计与追溯

- 每次调用可追溯到调用者、用途、模型、Prompt 版本、成本、范围指纹；
- 审计不写 secret、原始内容、完整 Prompt；
- 高成本调用与拒绝记录审计；审计可见性随 B（1.0 仅超管）。

## 十二、验收标准

### H1 网关

- [ ] `[自动]` 模型 Key 不出现在仓库、日志、Prompt、前端与响应中
- [ ] `[自动]` 未达到 `production_approved` 的模型 tuple 调用被拒绝，且不发真实请求
- [ ] `[自动]` 每次调用产生一条 AICall，含 caller、purpose、model、prompt 版本、tokens、估算成本、延迟、范围指纹；不含原始内容与 secret
- [ ] `[自动]` 超过单次/日/月预算时，在下一次调用前返回 `budget_exceeded`，不发请求
- [ ] `[自动]` 主模型失败且无已验证 fallback 时返回稳定错误，不伪造结果
- [ ] `[自动]` 缓存命中不重复计费，但仍记 `cache_hit`；范围指纹不同不复用
- [ ] `[自动]` H1 不提供通用取数接口；所有输入由调用方按范围提供
- [ ] `[自动]` 默认测试使用 fake model，网络禁用，不产生付费调用

### H2 Prompt

- [ ] `[自动]` Prompt 版本不可变；修改产生新版本，旧版本可查
- [ ] `[自动]` 只有超管能启用/回滚 Prompt 版本，操作记审计
- [ ] `[自动]` 业务人员不能自由编辑 Prompt 正文

### H5 脚本分析

- [ ] `[自动]` 只有 `platform_admin` 与 `hq_manager` 能调用；分公司与门店被拒
- [ ] `[自动]` 只能分析调用者可见的单条内容；跨品牌内容被拒绝
- [ ] `[自动]` 粘贴文本、URL、批量输入被拒绝
- [ ] `[自动]` 返回结构化字段（summary / hook / structure / highlights / issues / suggestions），带模型与 Prompt 版本
- [ ] `[自动]` 业务结果不展示 AI 成本；成本只在超管可见的 AICall 中
- [ ] `[自动]` 结果不写回 A 的内容，不自动发布
- [ ] `[自动]` 模型失败/拒绝/输出不合法时显示错误，不返回空建议或伪造建议
- [ ] `[自动]` 撤权后下一次请求不再返回结果

### D 第三层

- [ ] `[自动]` D 的 ASR + 大模型判定经 H1 记录 Key、模型、Prompt 版本、tokens、估算成本、范围指纹
- [ ] `[自动]` 模型失败时信号记 `failed` / unknown，不写成 0 或空值
- [ ] `[自动]` 业务用户看不到 AI 成本与全部调用；仅超管可查

### 成本与审计

- [ ] `[自动]` 每次真实调用有人工批准、显式开关、固定预算与 deadline；未批准不发请求
- [ ] `[自动]` 审计里没有原始内容、完整 Prompt、secret
- [ ] `[手工]` 超管能按调用者、用途、模型、Prompt 版本与时间查 AICall
- [ ] `[自动]` 1.0 没有任何 H8 入口、接口或验收项
