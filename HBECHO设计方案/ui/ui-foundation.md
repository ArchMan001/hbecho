# hbecho UI 全局基线

> **状态**：`draft`（2026-11-04 初稿，待评审）
> **作用**：所有带页面的 spec 共用的界面约定：角色导航、1.0 页面地图、页面骨架、通用状态、组件约定、文案与格式、适配边界。
> **不写什么**：单个页面的字段、流程与线框（写在对应 spec 的 design.md「界面」一节）；业务规则（以各域 PRD 为准）。
> **技术前提**：Next.js App Router + React 19 + Tailwind 4 + shadcn/ui + Radix（ADR-0005），代码在 `src/app/`（ADR-0013）。

## 1. 怎么用

1. 写任何带页面的 spec 之前，先读本文件；
2. 该 spec 的 design.md 增加「界面」一节，按 §8 的模板写；
3. 规则最复杂的页面先做可点击原型，请业务按真实任务走一遍，再写 tasks.md；
4. 某个 spec 需要偏离本文件时，先改本文件，不在页面里各自发明。

## 3. 1.0 页面地图

每个页面归一个 spec；页面细节在该 spec 的 design.md 里写。

| 区域 | 页面 | 归属 spec | 原型优先级 |
|---|---|---|---|
| 账户 | 登录（密码 / 短信）、激活、忘记密码、修改密码 | `b-access-control` | 低 |
| 用户与权限 | 用户列表、新建用户、批量导入用户、编辑角色与范围、停用 / 恢复 | `b-access-control` | 中 |
| 系统 | 审计日志 | `b-access-control` | 低 |
| 主数据 | 组织与门店浏览、专员列表、权威主档导入（F5 路径 1）、单条纠错、结构变更（超管） | `a-master-data-import` | 中 |
| 活动计划 | 计划列表、新建计划、计划详情（基本信息 / 参与分公司 / 名单 / 下游判定计划 / 变更记录）、名单导入（F5 路径 2）、负责人 | `a-activity-plan` | **高** |
| 账号与监控 | 账号列表（综合状态列）、五级监控开关、单账号手工补抓 | `a-activity-plan`、`a-full-sync` | 中 |
| 同步 | 批次列表、账号级同步结果、数据质量问题 | `a-full-sync` | 低 |
| 系统 | 外部监控账号清单（超管） | `a-full-sync` | 低 |
| 判定计划 | 三页向导（圈定 / 比对 / 理解与执行）、执行记录与结果 | `c-signals`、`d-rule-engine` | **最高** |
| 报表与看板 | 组织点检表、专员明细、命中内容、计划看板、指标字典与自定义指标 | `e-metrics` | **最高** |
| 下载中心 | 本人导出任务列表 | `e-metrics` | 低 |
| 学习 | 课程管理、学习中心（列表 / 播放 / 预览）、学习汇总、标签管理（超管） | `g-learning-min` | 中 |
| AI | 单条内容 AI 分析（入口在命中内容与内容详情）、AI 调用与成本（超管） | `h-ai-min` | 低 |
| 系统 | 系统配置（同步计划等，超管） | 横切（I 域） | 低 |

**最先做原型的两个页面**：判定计划三页向导与组织点检表。它们承载 D-71（内容逐层过滤）与 E 的口径，用原型请总部按「建一个 618 活动的判定计划 → 执行 → 看点检表 → 下钻到未达标专员」走一遍，比读 PRD 更容易发现规则问题。

## 4. 页面骨架

| 类型 | 结构 | 用于 |
|---|---|---|
| 列表页 | 标题 + 主操作按钮 → 筛选栏 → 表格 → 分页；右上角「导出」（有权限才显示） | 计划、账号、用户、批次、课程 |
| 详情页 | 标题与状态 → 关键数字（只计数） → 标签页 | 活动计划、判定计划、批次 |
| 导入流程 | 下载模板 → 上传 → 预检报告（分类计数 + 可筛选明细） → 确认写入 → 批次详情 | F5 两条路径、用户批量导入 |
| 向导 | 顶部步骤条；只能按顺序前进、每次回退一步；回退前弹窗写明会删除什么 | 判定计划 |
| 报表页 | 筛选（计划 / 品牌 / 板块）→ 表格（多级表头、冻结首列）→ 页脚口径说明 | 点检表、专员明细、命中内容 |

所有异步动作（确认写入、执行判定、导出）提交后立即返回，页面显示「已提交」并给出去处（批次详情 / 执行记录 / 下载中心），不让用户停在转圈页面。

## 5. 通用状态

每个页面都要设计下列状态，spec 的状态矩阵逐项填写：

| 状态 | 显示 | 注意 |
|---|---|---|
| 加载中 | 骨架屏 | 不用全屏遮罩 |
| 空：确实没有数据 | 说明 + 下一步动作（如「去导入名单」） | 与「无权限」分开（G 域要求） |
| 无权限 | 「无权访问」页 | 直接访问 URL 也显示这个，不显示空列表 |
| 错误 | 一句人话 + 稳定错误码 + 重试 | 不显示堆栈 |
| 部分成功 | 成功数与失败数同时显示，失败可下载回流文件 | 导入、批量操作 |
| 处理中（异步） | 进度或「排队中 / 执行中」，可离开页面 | |
| 数据过期 | 页脚显示数据截止时间，`stale` 时加「当前显示上一版」 | E 域投影 |

**判定结果的三态**（D §1.4）统一用同一组颜色与文案：成功（绿）、不达标（红）、未获取成功（灰，必须附原因）。

**数值的四种显示**：真实 0 显示 `0`；无数据或分母为 0 显示 `—`；没有参与显示「未参与」；部分覆盖显示数字加覆盖标记。不得用 0 代替 `—`（CONTEXT 不变量 14）。

## 6. 组件、文案与格式

**组件**：只用 shadcn/ui 默认主题加一个品牌主色，不自建设计系统。表格、表单、弹窗、步骤条、标签页、Toast 都用 shadcn 现成组件；需要新增第三方组件库时，按 `no-reinventing-wheels` 先登记。

**术语**（界面文案以此为准，代码命名以 CONTEXT 为准）：

| CONTEXT | 界面 |
|---|---|
| `MediaStaff` | 专员 |
| `ExternalAccount` | 平台账号 |
| `ActivityPlan` | 活动计划 |
| `MonitoringJudgementPlan` | 判定计划（界面简称） |
| `Unobtained` | 未获取成功 |
| `Participant` | 考核人数 |
| `ContentDiscovery` | 不在界面出现 |

**格式**：

- 时间按北京时间显示，精确到分钟；导出文件同样；
- 内部 ID 不在界面出现；需要时以字符串显示，不做数字运算；
- 数字千分位；比率保留一位小数，例如 `62.5%`；
- 手机号明文显示（D-42），随行可见。

**确认弹窗**：删除、回退、全局关闭监控、停用用户必须弹窗，写明影响范围（例如「下面有 3 个判定计划、共 1,284 条结果将被删除」），按钮文字写动作本身（「删除计划」），不用「确定」。

## 7. 适配与可访问性

- **管理端**（除 `store_staff` 外的全部页面）：桌面浏览器，最小宽度 1280px；手机能打开但不专门优化；
- **门店端**（我的考核、学习中心）：移动优先，兼容微信内置浏览器；微信内不能下载时提示「在浏览器打开」（G-D35）；
- 所有表单控件有可见标签；只用颜色区分的状态必须同时有文字；键盘可以完成主要操作。

## 8. spec 中「界面」一节的模板

```markdown
## N. 界面

### N.1 页面清单
| 页面 | 角色 | 入口 | 主要操作 | 对应 Capability |

### N.2 用户流程
（一到两条主流程，箭头或时序图）

### N.3 线框
（低保真截图放在 spec 目录的 wireframes/，这里只放链接）

### N.4 状态矩阵
| 页面 | 加载 | 空 | 无权限 | 错误 | 部分成功 | 处理中 |

### N.5 字段可见性
| 字段 | platform_admin | hq_manager | branch_manager | store_staff |
```
