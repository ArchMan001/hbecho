## 一、A 能提供的事实

### 1. 账号主页快照 `AccountProfileSnapshot`

| 内容 | 说明 |
|---|---|
| 账号标识 | 平台 + 账号 ID（抖音 `user_id` / 小红书 `user_id`） |
| 文本 | 昵称、签名 |
| 计数 | 粉丝、关注、获赞与收藏、作品数 |
| 媒资 | 头像、背景（**仅抖音**） |
| 观察信息 | 批次、观察时点、来源 |

**粒度**：一个账号 × 一个批次 × 一份快照。

### 2. 内容快照 `ContentSnapshot`（按账号）

| 内容 | 说明 |
|---|---|
| 身份 | 平台 + 平台内容 ID + **所属账号** |
| 文本 | 标题、正文、话题文本 |
| 时间 | 发布时间 |
| 属性 | 内容形态（视频 / 图文 / 未知）、时长 |
| 互动 | 点赞、评论、收藏、分享 |
| 作者 | 返回作者 ID / 名称 / 主页；可能不等于所属账号（共创/异作者） |
| 列表位置 | 第几页、第几条、是否可能置顶 |
| 媒资 | 封面、图文图片、视频、音频的引用 |
| 观察信息 | 批次、观察时点、来源 |

**粒度**：一个账号 × 一条内容 × 一个批次 × 一份最终快照。同一作品出现在两个账号时，各有一份。

### 3. 媒资 `MediaAsset` / `MediaReference`

| 类型 | 1.0 是否归档 |
|---|---|
| 主页头像、背景 | ✅（仅抖音） |
| 内容封面 | ✅ |
| 图文图片、视频、音频 | ✅（视频/音频由规则圈定） |

- 按完整字节 SHA-256 判同，同一字节只存一份；
- 临时 URL 不是资产身份；
- C 通过 A 的正式媒资读取，不直接用临时 URL。

### 4. 评论 `Comment`

- 一级评论与回复最新态：内容 ID、评论 ID、父评论 ID、作者、正文、点赞数、回复数、评论时间；
- **保存评论作者标识与昵称**（平台返回 ID 时存 ID，没有时存昵称），用于监控官号评论（2026-10-28 决策）；
- 评论作者**不建为 `ExternalAccount`**，不保存头像媒资与完整回复树；
- 评论与回复在同一个列表里，用 `parent_id` 区分；
- 评论数量可能不完整，A 会标记数据质量问题。

> **待验证**：评论作者的平台 ID 与 `external_accounts` 的账号 ID 是否同命名空间。未验证前，C/D 不得假设二者可直接相等比较。

### 5. 归属与组织上下文

内容出现或账号归属时，可提供当时的：

```
账号 → MediaStaff → Store → Brand / Branch / Sector / Dealer
```

按采集当时冻结，不随当前主数据变化改写。

### 6. 质量状态

- 值状态：有效 / 缺失 / 显式 null / 非法 / **不支持**；
- 数据质量问题：身份冲突、连续性缺口、字段异常、媒资失败、评论不完整；
- 批次状态：成功 / 部分成功 / 失败。

## 二、C 应该以什么粒度产出信号

| 规则型输入 | 建议键 |
|---|---|
| 内容型（文本、画面、口播） | `content_snapshot_id`（或 `content_id` + `batch_id`） |
| 账号型（主页背景、头像） | `profile_snapshot_id` |

**不要**以"平台内容 ID"做全局键——A 是按账号保存的，同一作品在两个账号下是两份事实。

**只读 finalized 快照**；`building` 只用于同步期内部，不进入特征计算。

**信号状态**：`ready` / `waiting` / `unavailable`。技术失败不能变成"未命中"。

**版本**：每条信号带 capability、算法版本、参数指纹。

## 三、A 不提供什么

| 不提供 | 归谁 |
|---|---|
| OCR、ASR、视觉、向量等派生特征 | C 自己产出 |
| 业务判定（是否达标、是否合规） | D 规则 |
| 指标口径与聚合 | E 指标 |
| 临时 URL 作为长期身份 | 永不 |

|---|---|---|---|---|
| 主页快照 | ✅ | ✅ | ✅（无头像/背景/位置） | —（无主页数据） |
| 内容列表 | ✅ | ✅ | ✅ | — |
| 内容详情 | ✅ | ✅ | ✅ | ✅ |

| 头像/背景媒资 | ✅ | — | — | — |

## 五、数据可得性说明

| # | 情况 | 对 C 的影响 |
|---|---|---|
| 1 | 小红书主页没有头像与背景 | 小红书账号型视觉信号无输入 |
| 2 | 列表不返回播放数（抖音返回 0 作占位，小红书无字段） | 播放相关信号使用详情快照的 `play_number`；小红书详情也可能为空 |
| 3 | 封面与下载地址可能有多条 | 使用 A 已选定的正式资产，或按角色选一条 |
| 4 | 同一条目的字段不保证齐全（如部分条目没有 `text`） | 信号计算允许字段缺失 |
| 5 | 评论可能只返回部分 | 评论类信号要允许 `unavailable`，以 A 的数据质量问题为准 |
| 6 | 视频 URL 是临时的 | 通过 A 的正式媒资读取，不直接用临时 URL |

## 六、C 现在就能做的三件事

1. 定义**信号目录**：信号键、输入对象类型、依赖字段、成本档位、版本策略；
2. 用 `aimaster接口文档/测试结果/raw3/` 与 `raw4/raw5/` 的样本做输入样例；
3. 设计特征存储键：`对象 ID + 信号键 + 算法版本 + 参数指纹`。

## 七、需要与 A 对齐的三件事

| # | 待对齐 | 说明 |
|---|---|---|
| 1 | 读取接口形态 | 批量流式读取 finalized 快照，还是按 ID 查询；在 A 域 spec 中定 |
| 2 | 媒资读取方式 | 短期签名 URL 还是内部流；在 A 域 spec 中定 |

## 八、一句话总结

**A 给 C 的是"某个账号在某次同步中看到的、已定稿的内容与媒资事实"，不是"平台上的一条内容"。**
C 的所有信号都应绑定到具体快照，并允许字段缺失与媒资未归档。
