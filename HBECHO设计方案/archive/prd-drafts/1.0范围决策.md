## 二、1.0 / 2.0 能力边界

| 域 | 1.0 做 | 1.0 不做 |
|---|---|---|
| **A 数据底座** | 主数据导入、账号与归属、每周同步（抖音 + 小红书 + 快手）、ODS、主页/内容快照、详情与按规则采集的评论、头像/背景/封面归档、按规则归档视频源与音频轨 | 存量迁移、视频号/快手、内容识别、图文图片、血缘 |
| **B 访问控制** | 登录、邀请激活、Capability、DataScope、最小审计 | 个人权限覆盖、动态角色、SSO/MFA |
| **C 识别** | C1 文本信号、**C2 档1 模板匹配**、C4 特征存储 | OCR、视觉大模型、ASR、向量检索、pHash |
| **D 规则** | D1–D6，只开放 **0 档算子**（含 `profile_bg.matches_template` / `avatar.matches_template`） | 付费算子、跨对象聚合 |
| **E 指标** | E1/E2/E4/E6 + E3 固定模板 | 自助分析、自由看板设计器 |
| **F 业务应用** | **只有 F5 导入** | F1–F4、F6–F9 |
| **G 学习** | G1 内容管理 + G2 学习中心（资料、播放、进度） | AI 出题、题库考试、积分、学习任务、效果分析 |
| **H AI** | H1 网关、H2 Prompt 版本、H5 单条脚本分析、**H8 规则辅助生成** | 知识库、知识审核、RAG 合规、Agent、评测闭环 |
| **I 运维** | I1 部署、I3 备份、I4 安全 + I2 最小告警 | OSS 分级存储（只做 ODS 一年清理） |

## 三、决策带出的新问题（待定）

1. **标准图的归属与入口**。C2 档1 与 `profile_bg.matches_template` 需要「活动 × 板块」的标准图；F2 活动管理不在 1.0，因此标准图由谁上传、存在哪里、如何版本化必须先定。
2. **Python 能力的运行形态**。模板匹配是本地计算但需要 Python；设计大纲明确反对旧系统 `spawn python3` + 正则解析 stderr 的做法，需要决定独立服务还是进程内库。
3. **监控账号数**。6,000 是账号总量，实际纳入每周同步的数量尚未确认，直接影响配额与媒资下载预算。
4. **四类角色是否在 1.0 定稿**。B 域的最小闭环需要角色到 Capability 的映射，角色不定则 B 无法实施。
