# AI Master 返回字段与特殊情况

> **依据**：`测试结果/raw3/`（25 个成功样本）与 `测试结果/raw4-2026-10-28/`（11 个用例，14 次调用）。
> **范围**：只覆盖 1.0 使用的抖音与小红书四类能力。
> **边界**：这是**实测观察**，不是供应商合同。未观察到的字段不代表不存在；字段语义未验证的会明确标注。
> **计费与能力矩阵**：以 [`AI Master 能力与计费清单.xlsx`](AI%20Master%20能力与计费清单.xlsx) 为准。

## 一、主页信息 `media_user_info`

### 抖音（15 个字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | 抖音号，如 `HITACHI1` |
| `nickname` | string | 昵称 |
| `signature` | string | 签名，可含换行 |
| `location` | string | 地区 |
| `avatar` | string | 头像 URL，单条 |
| `cover` | string | 主页背景 URL，单条 |
| `follower_count` / `follower_number` | string / int | 粉丝数，两种类型同值 |
| `following_count` / `following_number` | string / int | 关注数 |
| `like_count` / `like_number` | string / int | 获赞数 |
| `post_count` / `post_number` | string / int | 作品数 |
| `updated` | int | 毫秒时间戳 |

### 小红书（12 个字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | 如 `49328995493` |
| `nickname` | string | 昵称 |
| `signature` | string | 签名 |
| `follower_count` / `follower_number` | string / int | 粉丝数 |
| `following_count` / `following_number` | string / int | 关注数 |
| `like_count` / `like_number` | string / int | 获赞与收藏 |
| `post_count` / `post_number` | string / int | 笔记数 |
| `updated` | int | 毫秒时间戳 |

### ⚠️ 特殊情况

1. **小红书主页没有任何图片字段**：没有 `avatar`，也没有 `cover`。**从主页接口无法归档小红书头像与背景。**
2. 抖音主页有 `avatar` 与 `cover`，各是一条 URL。
3. 同一个指标同时给 `*_count`（字符串）与 `*_number`（整数），值相同。实现只能选一个，不能两个都当独立指标。
4. 主页接口**不返回** `sec_uid`；`sec_uid` 只出现在内容列表的每条作品上。

## 二、内容列表 `user_video_list`

### 外层

| 字段 | 抖音 | 小红书 | 说明 |
|---|---|---|---|
| `result` | list | list | 作品数组 |
| `has_more` | **bool** | **bool** | 是否还有下一页 |
| `cursor` | string（空） | string（空） | raw4 仍返回，但值恒为空 |
| `max_cursor` | **int** | **string** | 下一页游标，类型必须保真 |

### 每条作品（抖音）

| 字段 | 类型 | 说明 |
|---|---|---|
| `post_id` | string | 作品 ID |
| `user_id` | string | **作者**的抖音号，可能不是被采集账号 |
| `sec_uid` | string | **作者**的 sec_uid |
| `author_name` | string | 作者昵称 |
| `created` | int | 发布时间（毫秒） |
| `publish_location` | string | 发布地 |
| `title` | string | 标题 |
| `tag_text` | string | 话题文本 |
| `related_search_terms` | list | 空数组（实测） |
| `related_search_str` | string | 空字符串（实测） |
| `stats` | dict | `play_count` / `like_count` / `comment_count` / `collect_count` / `share_count`，均为 int |
| `cover` | **list[string]** | 实测 3 条 URL |
| `audio` | dict | `urls`（list）+ `url`（string）+ `name` + `duration`（int）+ `type`（null） |
| `video` | dict | `urls`（list）+ `url`（string）+ `name` + `duration`（float 秒）+ `type`（mime） |
| `images` | list | 视频作品为空数组 |
| `share_url` | string | 分享页地址 |
| `download_urls` | **list[string]** | 实测 10 条 URL |

### 每条作品（小红书）

| 字段 | 类型 | 说明 |
|---|---|---|
| `post_id` | string | 笔记 ID |
| `user_id` | string | **作者**的小红书 ID，如 `5decba…`，**不是主页的 `49328995493`** |
| `red_id` | string | 实测为空 |
| `author_name` | string | 作者昵称 |
| `created` | int | 发布时间（毫秒） |
| `title` | string | 含 `## 标题` / `## 正文` 标记的整段文本 |
| `tag_text` | string | 话题文本，实测可能为空 |
| `stats` | dict | `like_count` / `comment_count` / `collect_count` / `share_count`（**没有 play_count**） |
| `cover` | **string** | 单条 URL（与抖音不同） |
| `audio` | dict | `url` / `name` / `duration`（float），实测为空/0 |
| `video` | dict | `url` / `name` / `duration`（int），实测为空/0 |
| `images` | list[string] | 图文笔记的图片，实测 2 条 |
| `download_urls` | list | 实测空数组 |
| `text` | dict | `text.content` 为正文纯文本 |

### ⚠️ 特殊情况

1. **播放数在列表里不可用（供应商已确认）**：列表接口不返回播放数，只有视频详情接口返回。抖音 `stats.play_count` 固定为 `0` 作为占位；小红书**根本没有这个字段**。
   - **不能把抖音的 0 当成真实 0**，必须记为"不支持"。
2. **同一作品可能由其他作者发布**：raw3 抖音列表 20 条中，19 条属 `HITACHI1`，1 条属 `HITACHI2023`（`author_name` 为"日立变频中央空调"）。列表条目自带作者身份。
3. **封面可能有多条 URL**：抖音 3 条，小红书 1 条。
4. **下载地址可能有多条**：抖音 `download_urls` 10 条，另有 `video.urls` 与 `video.url`；小红书为单条或空。
5. **小红书列表没有播放数，也可能没有 `tag_text`**。
6. `cursor` 字段存在但恒为空；翻页只能依赖 `max_cursor` + `has_more`。
7. **置顶证据（2026-10-28）**：抖音与小红书的主页列表前 2 条发布时间都早于第 3 条，验证了"前三条可能置顶"。
8. **空账号**：0 作品的账号可正常返回主页；列表返回 0 条、`has_more=false`、`max_cursor=0`。
7. **条目字段不保证齐全**：同一接口不同条目可能缺少某些字段（如第二页部分条目没有 `text`）；解析必须按条目容错，不能假设固定 schema。

## 三、内容详情 `media_stats_number`

**请求动作是 `media_stats_number`，返回动作是 `media_stats`。**

### 抖音（25 个字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `post_id` | string | 作品 ID |
| `platform` | string | `douyin` |
| `play_count` / `like_count` / `comment_count` / `collect_count` / `share_count` / `duration` | **null** | 实测全部为 null |
| `play_number` / `like_number` / `comment_number` / `collect_number` / `share_number` / `duration_number` | int | 实际有值的指标 |
| `author_homepage` | string | **raw4 新增**，raw3 没有 |
| `user_id` | string | 作者抖音号 |
| `author_name` | string | 作者昵称 |
| `created` | int | 发布时间（毫秒） |
| `title` | string | 标题 |
| `tag_text` | string | 话题文本 |
| `publish_location` | string | 发布地 |
| `related_search_str` | string | 多行搜索词 |
| `cover` | **string** | 单条 URL（与列表的数组不同） |
| `download_urls` | **string** | 单条 URL（与列表的数组不同） |
| `updated` | int | 毫秒时间戳 |

### 小红书（23 个字段）

结构同上，差异：

- `play_number` 在图文笔记上为 **null**；
- `duration_number` 为 0；
- `cover` 与 `download_urls` 都是 **string**；
- 实测 `share_number=740` 而 `like_number=71`，**分享数高于点赞数，语义可疑**，需向供应商确认该字段是否映射错了。

### ⚠️ 特殊情况

1. **`*_count` 全是 null，`*_number` 才是值**。同一指标在列表、详情、主页三处的字段名和可空性都不同。供应商可能已把详情接口统一为 `number`；解析时优先取有效值，另一类型作为回退。
2. **`cover` / `download_urls` 在详情是字符串，在列表是数组**。
3. `author_homepage` 是新增字段；raw3 没有。
4. 详情的 `user_id` 是作者，不一定是被采集账号。
5. 小红书的 `share_number`：自有笔记实测 `share_number=15`、`like_number=200`、`collect_number=190`、`comment_number=6`，数值合理；`出伏倒计时` 的 `740` 仍需在后台核对。暂按"分享数"使用。

## 四、评论

**三个接口**：

| 接口 | action | 用途 |
|---|---|---|
| `POST /openapi/v1/media/comments/list` | `post_comments_list` | 完整评论列表；1.0 使用这个 |
| `POST /openapi/v1/media/comments` | `media_comments` | 评论摘要；实测只返回 `comments_str`（如"暂无评论"）与 `cursor` |
| `POST /openapi/v1/media/hot_comments` | `media_hot_comments` | 热门评论；未测 |

### `post_comments_list`

### 外层

| 字段 | 类型 | 说明 |
|---|---|---|
| `result` | list | 评论数组 |
| `max_cursor` | **string** | 下一页游标，如 `"20"` |
| `has_more` | **int** | 0/1（与列表接口的 bool 不同） |
| `total` | int | 平台报告的总评论数 |
| `post_id` | string | 作品 ID |
| `reply_page_count` | int | 实测 0（传 `reply_pages=-1`） |
| `cursor` | — | **raw4 已不存在**，raw3 有 |

### 每条评论

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 评论 ID |
| `post_id` | string | 所属作品 |
| `content` | string | 评论正文，含表情占位 |
| `author` | dict | `id` / `name` / `avatar` |
| `stats` | dict | `like_count` / `reply_count` |
| `is_liked` | bool | 当前账号是否点过赞 |
| `download_urls` | list | 实测空数组 |
| `download_urls_str` | string | 实测空字符串 |
| `created` | int | 毫秒时间戳 |
| `updated` | int | 毫秒时间戳 |

### ⚠️ 特殊情况

1. **`total` 与返回条数不一致，且 `total` 包含回复**：
   - 抖音：total=125、本页 20；
   - 小红书 `出伏倒计时`（https://xhslink.cn/o/3FgtGUlhO8s）：截图显示 1 条一级评论 + 作者 1 条回复，页面"共 2 条评论"；接口 `total=2`，`reply_pages=-1` 只返回 1 条一级评论；
   - 小红书自有笔记：详情显示评论 6，接口 `total=6`，但 `result` 为空数组（`reply_pages=-1` 与 `-2` 都一样）。
   - 小红书 `大二菜鸟做竞赛`：`total=28`，第 1 页只返回 2 条、`has_more=0`；`reply_pages=-2` 返回 6 条。
   - 小红书 `Evolo 竞赛笔记`：`total=31`，第 1 页 4 条、`has_more=0`。
   - 自有笔记页面实际有 6 条评论（4 条他人 + 2 条作者回复），`total=6`，但 `post_comments_list` 的 `result` 为空；改用 `media_comments` 返回 `comments_str="暂无评论"`；改用 explore 链接同样为空。
   - 抖音 `盛夏抗暑`：total=98，第 1 页 20 条、游标 `"20"`；第 2 页 20 条、游标 `"40"`，**可正常翻页**；`reply_pages=-2` 返回 44 条，含 `parent_id`，`reply_count=11`。
   - 小红书 `Evolo 竞赛笔记`：total=31，但只返回 4 条、`has_more=0`，**无法翻页**；`reply_pages=-2` 返回 5 条，含 `parent_id`。
   - **结论**：`total` 是评论总数（含回复），不是本次可获取条数；**`total>0` 不等于有可获取评论**，必须记数据质量问题。

**回复的结构**：回复与一级评论在**同一个数组**里，用 `parent_id` 区分；不是嵌套。

实测抖音一条视频 `reply_pages=-2` 返回 **44 条 = 20 条一级 + 24 条回复**，其中**同一条评论下有 14 条回复**。所以一次返回的 20 条，完全可能大部分甚至全部来自同一条评论的对话串。
2. **`has_more` 是整数**，不是布尔。
3. **游标是字符串**，如 `"20"`；最后一页为空字符串。
4. **不取回复**时 `reply_page_count=0`；回复内容需要 `reply_pages=-2` 或 N 页。
5. 评论作者**不建账号**，只作为内容事实保存。
6. 小红书第一次调用曾返回 `result: null` 并报 `RESULT_VALIDATION_FAILED`，重试成功——**可重试**。

## 五、同步 vs 异步

| 项 | 结论 |
|---|---|
| 抖音主页 | ✅ 15 个字段一致；数值随时间变化 |
| 抖音视频详情 | ✅ 25 个字段一致 |
| 抖音内容列表 | ❌ 失败（raw7/raw8，结果被序列化为字符串） |
| 抖音评论 | ❌ 失败（raw7/raw8） |
| 小红书主页 | ✅ 12 个字段一致 |
| 小红书笔记详情 | ✅ 23 个字段一致，数值也一致 |
| **小红书内容列表** | ❌ **稳定失败**（raw4、raw5、raw7、raw8）；供应商把结果序列化为字符串 |
| 小红书评论 | ✅ 2 条，`total=28` |

**实现要求**：同步与异步必须产出**同一份规范化结果**；异步按 tuple 门控。8 个 tuple 中 5 个可用，失败的只有抖音列表、抖音评论、小红书列表。

## 六点五、错误表现（2026-10-28 实测）

| 输入 | HTTP | code | 说明 |
|---|---|---|---|
| 无效抖音链接 | **500** | `RESULT_VALIDATION_FAILED` | `result` 为 null；不是 404 |
| 错误 API Key | **400** | `INVALID_REQUEST` | 不是 401；message 为 "Expecting value..." |

**不能只按 HTTP 状态码分类**：认证失败与输入错误都可能表现为 400；无效链接表现为 500。

## 七、对实现的硬要求

1. **一个接口一个 Adapter**：主页、列表、详情、评论的字段名、类型、可空性都不同，不能共用一套映射。
2. **四种值状态**：真实 0、缺失、显式 null、不支持，必须分开；列表的播放数是"不支持"，不是 0。
3. **URL 是候选集不是单值**：封面、下载地址可能有多条；先保留全部，再按角色与优先级选一条，不能默认取第一条。
4. **作者与目标账号分列**：列表条目的 `user_id` / `sec_uid` 是作者；可能不等于被采集账号。
5. **游标按接口区分**：抖音列表 int、小红书列表 string、评论 string；不得互相转换。
6. **不依赖已移除字段**：评论不再有 `cursor`。
7. **容忍新增字段**：未知字段保留在 ODS，解析层忽略。
8. **同步与异步同构**：规范化后的结果必须一致；异步按 tuple 门控。
