## 一、这个域管什么

### 1.1 四个问题

```text
怎么上线       →  环境、编排、反向代理、迁移、回滚
怎么知道坏了   →  日志、指标、告警、数据鲜度、成本视图
怎么恢复       →  MySQL / OSS 备份、恢复演练
怎么不花超     →   Capability 门控、预算、限流、硬上限、人工止损
```

**I 不是业务功能，是让系统能上线、能观测、能恢复、能止损的横切底线。**

### 1.2 不管什么

| 事情 | 归谁 |
|---|---|
| 组织、账号、内容、媒资的事实 | A 数据底座 |
| 登录、Capability、DataScope、审计可见性 | B 访问控制 |
| 识别信号、模型调用语义 | C 识别能力 / H AI 能力 |
| 规则、判定与重算 | D 规则与考核 |
| 指标口径、点检表、看板与导出 | E 指标与看板 |
| 业务页面与用户旅程 | F 业务应用 |
| 课程内容与学习进度 | G 学习平台 |
| 具体部署命令、参数、排障步骤 | runbook（本文只定义能力与验收） |

### 1.3 一条主线

```text
代码与迁移进仓库
  → 测试 ECS 部署（Docker Compose + 宿主 Nginx）
  → 日志 / 指标 / 告警 / 成本视图
  → 备份与恢复演练
  → 付费调用前过 capability gate、预算与硬上限
  → 超限或故障时人工止损
```

### 1.4 1.0 的边界

| 模块 | 1.0 | 说明 |
|---|---|---|
| I1 环境与部署 | ✅ | 测试 ECS；生产 ECS 未购买；Docker Compose + 宿主 Nginx；迁移单一来源 |
| I2 可观测性 | ✅ 最小 | 日志、队列/同步指标、最小告警、最小成本视图 |
| I3 备份与恢复 | ✅ | MySQL 全备 + binlog、OSS 备份桶、恢复演练 |
| I4 安全与合规 | ✅ | 最小权限、密钥、HTTPS、审计留存、Workbench-only |
| I5 数据生命周期 | ✅ 部分 | ODS 一年清理、临时/导出/备份期限；**OSS 分级存储 2.0** |
| I6 配置中心 | ❌ | 1.0 走环境变量与配置文件；**配置中心 2.0** |
| I7 配额与成本 | ✅ 部分 | 硬上限、预算、限流、人工开关；**完整成本看板 2.0** |

## 二、用户与场景

### 2.1 谁在用

| 角色 | 在 I 域做什么 | 依据 |
|---|---|---|
| `platform_admin` | 看告警、成本视图与审计；改配额/预算；执行止损 | `config.manage`、`audit.read` |
| 运维（人） | 部署、备份、恢复、排障 | Workbench + runbook |
| 业务用户 | 不直接使用 I；只看到系统可用/不可用 | — |

- 1.0 **不新增 Capability**：配额与开关走 `config.manage`（仅超管）；成本视图与审计走 `audit.read`（1.0 仅超管）。
- 运维操作一律走 Workbench，不用 SSH / SCP / 端口转发（`.kiro/steering/server-access.md`）。

### 2.2 三条真实路径

1. **测试环境部署**：代码与迁移合入后，按 runbook 在测试 ECS 上 `docker compose` 部署；Nginx 配置从仓库同步；应用容器只绑 `127.0.0.1`。
2. **故障止损**：某供应商调用量异常，超管在配额页把该 provider 的开关关掉或把预算调到 0；下一次调用前被拒绝，已发出的请求不再扩大。
3. **恢复演练**：运维从 `hbecho-backup` 桶取 MySQL 逻辑备份与 binlog，在一次性库容器里恢复并记录耗时；失败则告警并保留现场。

### 2.3 规模与现状

- 当前只有**一台测试 ECS**（`i-2zef8qpi1d2mldntjgrv`，华北2，8 vCPU / 32 GiB）；**生产 ECS 未购买**（2026-10-25 确认）。
- MySQL 8.0.46（Docker）；OSS 五桶：`hbecho-ods` / `media` / `temp` / `backup` / `course`。
- 快照策略 `hbecho-daily`（北京 03:00，保留 7 天）；四条基础告警；邮件告警仍 `PENDING`。
- 应用代码与部署 compose 尚未落地；本文的 I1/I2 验收多数为 `[待部署]` / `[环境]`。

### 2.4 1.0 的边界

| 做 | 不做 |
|---|---|
| 测试 ECS 部署、Nginx、迁移、回滚 | 生产 ECS 采购与部署（未购买） |
| 日志、队列/同步指标、最小告警、最小成本视图 | 完整可观测平台、APM、链路追踪 |
| MySQL 全备 + binlog、OSS 备份、恢复演练 | 跨地域容灾、双活 |
| 最小权限、密钥、HTTPS、审计留存 | SSO/MFA、WAF、堡垒机 |
| ODS 一年清理、临时/导出/备份期限 | OSS 分级存储、冷归档 |
| 环境变量与配置文件 | 配置中心、热更新、灰度配置 |
| 预算、限流、硬上限、人工开关 | 自动扩缩容、自动降级编排 |

## 三、概念

### 3.1 环境（Environment）

- 1.0 只有 **test** 与未来的 **production** 两种定位；当前只有 test ECS。
- 环境之间配置、密钥、数据库、OSS 前缀/桶、域名与预算隔离。
- 生产环境未购买前，不存在"生产配置"；不得把测试凭证或测试数据带到未来生产。

### 3.2 配置项（ConfigItem）

- 有稳定键名、类型、默认值、适用环境、是否敏感、变更审计；
- 1.0 存在环境变量与配置文件里，不建配置中心；
- 敏感值（密码、Key、Token）只放密钥管理，不进仓库、不进普通配置文件、不进日志；
- 未决项不得被配置默认值静默冻结。

### 3.3 配额与预算（Quota / Budget）

- **配额**：并发、QPS、单次调用上限、重试上限；
- **预算**：单用户/日、单品牌/日、全局/月；
- **硬上限**：超过即停止，不是"告警后继续"；
- **人工开关**：按 provider / action / 环境关闭的能力开关；
- 用量按 provider、action、品牌/计划、调用者归因，至少精确到能回答"谁花的多"。

### 3.4 告警（Alarm）

- 有明确阈值、持续时间、通知渠道、责任人、恢复条件；
- 1.0 至少覆盖：磁盘、内存、CPU、公网流出、服务存活、队列积压、同步失败、数据鲜度、成本阈值、备份失败；
- 邮件告警当前 `PENDING`（阿里云侧问题），1.0 验收标 `[环境]`；短信可用。

### 3.5 成本视图（CostView）

- 1.0 只做**最小成本视图**：本轮供应商调用数、模型调用数、媒资下载量、估算费用；
- 数据来自 A/H/C 的 ProviderCall / AICall / 媒资记录与 I7 的计数，不另建一套账单；
- **估算值，不是精确账单**；最终以阿里云账单为准；
- 完整成本看板、按品牌/计划/供应商的趋势与分摊在 2.0。

### 3.6 备份与恢复（Backup / Restore）

- MySQL：逻辑全备 + binlog；恢复粒度到库/表/时间点；
- OSS：`hbecho-backup` 桶保存 MySQL 备份；正式媒资与课程素材依赖云多副本，不做独立备份（G-D32）；
- 快照与逻辑备份是两件事：快照恢复整盘，逻辑备份恢复单表/误删；
- 恢复演练必须记录：备份版本、恢复开始/结束、耗时、校验结果、失败原因。

## 四、I1 环境与部署

### 4.1 环境

- 1.0 只部署**测试 ECS**；生产 ECS 未购买，未购买前不做生产部署验收。
- 测试与未来生产必须在配置、密钥、数据库、OSS、域名、预算上隔离；不得用测试凭证访问生产资源。
- 测试 ECS 允许跑测试，但必须使用一次性库容器；生产 ECS 未来**永不运行测试或迁移演练**。

### 4.2 编排与反向代理

- Docker Compose 编排；应用容器只绑 `127.0.0.1`，不直接对外；
- 宿主 Nginx 监听 80/443，反代到应用容器；
- Nginx 配置放仓库，部署脚本同步；**不允许手工改 `/etc/nginx/`**；
- 证书续期由宿主机定时任务完成，续期后 reload；证书到期必须告警。

### 4.3 迁移

- 迁移脚本是结构唯一来源；不使用 `db:push` 这类绕过迁移的手段；
- 迁移在部署流程中按顺序执行；失败停止部署并保留现场；
- 迁移执行记录版本、时间、结果；生产迁移未来必须人工批准。

### 4.4 回滚

- 应用镜像保留上一版；回滚只切镜像，不反向执行数据库迁移；
- 数据库迁移必须向前兼容至少一个版本，或提供显式回滚脚本与演练记录；
- 回滚操作记审计。

### 4.5 访问

- 服务器访问一律走 Workbench CLI；禁止 SSH / SCP / SFTP / `rsync -e ssh` / SSH 端口转发；
- 安全组只放必要端口；22 已收紧，3389 已移除；
- 不把 AccessKey 写到机器、仓库、日志或回复里；用实例角色与短期凭证。

## 五、I2 可观测性与最小告警

### 5.1 日志

- 结构化日志；至少含时间、服务、环境、级别、请求/任务 ID、结果；
- **不写 secret、raw body、临时 URL**；手机号按 B 域明文口径；
- 日志保留期按 I5；错误日志与审计分开。

### 5.2 指标

1.0 至少采集：

| 类别 | 指标 |
|---|---|
| 主机 | CPU、内存、磁盘、网络流出 |
| 服务 | 存活、重启次数、请求错误率、P95 延迟 |
| 队列/任务 | 排队数、运行数、失败数、最老任务等待时长 |
| 同步 | 批次成功率、失败原因分布、数据鲜度（最近成功同步时间） |
| 付费调用 | ProviderCall 数、AICall 数、tokens、媒资下载量、估算费用 |
| 导出 | 排队、运行、失败、文件大小 |
| 备份 | 最近成功时间、失败次数、恢复演练结果 |

### 5.3 最小告警

- 主机：磁盘 80% / 内存 85% / CPU 90% / 公网流出 24Mbps（现有四条）；
- 服务：存活失败、连续 5xx、队列积压超阈值；
- 同步：连续失败、数据鲜度超过阈值；
- 成本：单日/单月预算 80% / 100%；
- 备份：失败或超过 24 小时未成功；
- 证书：到期前 14 天；
- 通知渠道：短信可用，邮件 `PENDING`；告警必须有责任人组。

### 5.4 最小成本视图

- 仅 `platform_admin` 可见；
- 显示本轮/当日：供应商调用数、模型调用数、媒资下载量、估算费用；
- 可按 provider / action 拆分；按品牌/计划的拆分在 2.0；
- 页面注明"估算值，最终以阿里云账单为准"。

## 六、I3 备份与恢复

### 6.1 备份对象

| 对象 | 方式 | 保留 |
|---|---|---|
| MySQL | 逻辑全备 + binlog | 备份桶 `mysql/` 前缀 30 天；binlog 保留期见 §11 |
| OSS 正式媒资 | 云多副本，不独立备份（G-D32） | 长期 |
| OSS 课程素材 | 云多副本，不独立备份（G-D32） | 课程存续期 |
| 配置与密钥 | 配置入仓库（不含 secret）；密钥由密钥管理负责 | 按变更历史 |
| 审计 | 数据库内，随备份 | 一年 |

### 6.2 恢复目标

- 1.0 在测试环境完成一次恢复演练，记录耗时与校验结果；
- 未来生产的 RPO / RTO 在购买生产 ECS 前必须明确（§11）；
- 恢复演练使用一次性库容器，不覆盖现有测试库；
- 恢复失败保留现场并告警，不反复重试覆盖证据。

### 6.3 告警与演练

- 备份失败、超过 24 小时未成功、恢复演练失败均告警；
- 演练记录进入 runbook 变更记录；至少每季度一次（生产上线后）。

## 七、I4 安全与合规

### 7.1 最小权限

- RAM 角色按用途拆分；应用用实例角色与短期凭证，机器上零长期 AccessKey；
- `media` / `backup` 桶无 `DeleteObject`；`course` 桶只对课程资料开放删除；
- 数据库账号按用途拆分，应用账号不做 DDL；
- 服务器访问只走 Workbench；SSH 密码认证关闭。

### 7.2 密钥与敏感信息

- 密码、模型 Key、供应商 Key、Token、Cookie 不进仓库、日志、Prompt、前端与普通配置文件；
- 密钥轮换有记录；离职/交接时轮换；
- 密钥扫描在提交前与 CI 中执行；发现即阻断。

### 7.3 HTTPS 与域名

- 生产必须 HTTPS；证书续期与到期告警；
- 域名与 ICP 备案是生产上线前置（当前未完成）；
- 备案前测试环境不开放公网 80/443；开发访问按 runbook 的隧道方式。

### 7.4 审计留存

- 审计保留一年；到期按 B 域策略批量删除并记系统审计；
- 审计不可覆盖；高风险管理操作与外发操作审计失败时 fail closed（按 B 域）。

- 清理不得删除长期业务事实；
- OSS 分级存储（冷归档）2.0，不在 1.0。

## 九、I6 配置

- 环境变量 + 配置文件；按环境分离；

### 9.2 纪律

- 未决项不得被配置默认值静默冻结；
- 生产配置变更必须人工批准并记审计；
- 配置读取失败启动即失败，不带默认值猜；
- 配置变更与代码版本一起可追溯。

## 十、I7 配额与成本

### 10.1 覆盖对象

- AI Master 供应商调用（A）；
- 模型 / ASR 调用（H1 / C）；
- VOD 上传、转码、播放（G）；
- OSS 存储、流量、请求（A/G）；
- 短信（B）；
- 导出与后台任务（E/F）。

### 10.2 硬上限与预算

- 单次调用、单用户/日、单品牌/日、全局/月都有硬上限；
- 超限在**下一次调用前**停止，返回稳定错误，不发请求；
- 并发、QPS、重试上限可配置；
- 预算阈值 80% 告警、100% 停止（可人工临时放宽，记审计）；
- 短信：同一手机号 60 秒 / 每天 10 条（B 域）；全局每日上限由 I 域配置，超限告警并暂停发送（2026-11-04）；
- **D 第 3 层的 ASR 与大模型调用必须有全局每日硬上限**（2026-11-04）：1.0 不向业务展示费用预估（D-72），业务连续执行时由这条上限兜底；超限后第 3 层记「未获取成功」并告警，不排队补跑；
- 人工开关按 provider / action / 环境关闭。

### 10.3 归因与视图

- 用量按 provider、action、品牌/计划、调用者归因；
- 1.0 最小成本视图见 §5.4；完整成本看板、趋势与分摊 2.0；
- 成本是估算值，最终以云账单为准；
- 成本数据不能反过来改写业务判定或指标。

## 十四、验收标准

每条都必须能被业务人员或运维判断真假；`[自动]` 指可由脚本验证，`[手工]` 指需要人操作确认，`[环境]` 依赖云资源。

### I1 环境与部署

- [ ] `[自动]` 应用容器只绑 `127.0.0.1`，不直接对外监听
- [ ] `[自动]` Nginx 配置来自仓库；手工改 `/etc/nginx/` 后下次部署会被覆盖或告警
- [ ] `[自动]` 迁移按顺序执行，失败停止部署并保留现场
- [ ] `[自动]` 回滚只切镜像，不反向执行数据库迁移
- [ ] `[自动]` 测试环境使用一次性库容器，不连接现有 `hbecho` 库
- [ ] `[环境]` 生产 ECS 未购买前，不存在生产部署记录

### I2 可观测性与告警

- [ ] `[自动]` 日志不含 secret、raw body、临时 URL；手机号按 B 口径
- [ ] `[自动]` 队列积压、同步失败、数据鲜度、备份失败、成本阈值均能触发告警
- [ ] `[自动]` 单日/单月预算 80% 告警、100% 停止
- [ ] `[手工]` 超管能看到最小成本视图：供应商调用数、模型调用数、媒资下载量、估算费用
- [ ] `[环境]` 邮件告警 `PENDING` 时，短信或控制台能看到同等信息

### I3 备份与恢复

- [ ] `[自动]` MySQL 逻辑全备写入 `hbecho-backup`，失败告警
- [ ] `[自动]` 备份桶 `mysql/` 前缀 30 天保留，正式媒资桶无删除权限
- [ ] `[手工]` 在一次性库容器完成一次恢复演练，记录耗时与校验结果
- [ ] `[环境]` 生产 RPO/RTO 在购买生产 ECS 前明确

### I4 安全与合规

- [ ] `[自动]` 仓库、日志、配置、响应中无 secret；提交前与 CI 密钥扫描通过
- [ ] `[自动]` `media` / `backup` 桶删除被拒；`course` 桶只对课程资料开放删除
- [ ] `[自动]` 服务器访问只走 Workbench；SSH 密码认证关闭
- [ ] `[环境]` 生产 HTTPS 与证书续期、到期告警（依赖域名/备案）

### I5 生命周期

- [ ] `[自动]` ODS 一年清理任务有日志、计数、失败告警与重试上限
- [ ] `[自动]` 临时桶 3 天、备份 30 天、导出 7 天规则生效
- [ ] `[自动]` 清理不删除长期媒资、判定结果、学习进度

### I6 配置

- [ ] `[自动]` 配置项有键名、类型、默认值、环境与敏感标记
- [ ] `[自动]` 敏感值不在普通配置文件；配置缺失启动失败，不猜默认值
- [ ] `[自动]` 配置变更与代码版本可追溯；生产变更记审计

### I7 配额与成本

- [ ] `[自动]` 超单次/日/月上限时，在下一次调用前停止，不发请求
- [ ] `[自动]` 人工开关能按 provider / action / 环境关闭能力
- [ ] `[自动]` 用量可按 provider、action、品牌/计划、调用者归因
- [ ] `[手工]` 超管能临时放宽预算并留下审计
- [ ] `[自动]` 成本视图标注"估算值，最终以阿里云账单为准"
