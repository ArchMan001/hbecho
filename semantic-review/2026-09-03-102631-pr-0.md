# Tracer command aggregate 与 task projection schema 分离

本次仅复核上一轮唯一 OPEN Major。当前 v2 已为五字段 canonical aggregate 与两字段 `task_parameters` projection 分配不同 schema，并明确 validator 不得混用；tracer design §4.3 与 task 2 保持同一边界。§5.5 的 command JCS 向量仍对应五字段 aggregate，离线重算 SHA-256 仍为 `7dcf255d17be6de663a23e92310bb0f835e00b6cb223d46a9a2c8abd0bf8ec36`。限定在这次修改内，未发现直接相关的新 Major。

**Targeted result**: CLOSED + PASS

Watch for: 无；**confirmed** 原 schema 身份冲突已消除，validator 与 JCS vector 归属均无歧义。

**Verdict**: APPROVED

## High-level view

`data-foundation-tracer-command.v1` 现在唯一表示 platform、MediaStaff、原始 HomeLocator 与 effective limit 组成的五字段 canonical aggregate；`data-foundation-tracer-task-parameters.v1` 唯一表示 `schema_version` 与 effective limit 组成的两字段 persistence projection。

根任务先以 projection validator 校验 `task_parameters`，再将 limit 与显式根任务字段组装为 aggregate，交给独立 command validator 校验并计算 JCS 摘要。v2 §5.5/§9.3、tracer design §4.3、task 2 和验收向量对此一致。

## 两个 schema ID 各自固定一种 closed shape

v2 §5.5 将 `data-foundation-tracer-command.v1` 固定为五字段全必有且非 null 的 canonical schema。v2 §9.3 将根任务 `task_parameters` 固定为两字段 `data-foundation-tracer-task-parameters.v1`，并明确该 projection 不是完整 command、不得复用 command v1 validator；完整 aggregate 只能由显式 platform/staff/locator 字段和 projection 的 limit 组装后进入 command validator。因此上一轮“单一 schema ID 对应两种 closed shape”的 Major 已闭合。

```text
root task explicit fields ─┐
                           ├─> command.v1 validator ─> JCS SHA-256
task_parameters limit ─────┘
          │
          └─> task-parameters.v1 validator
```

## Design、task 与 JCS vector 沿用同一职责边界

Tracer design §4.3 与 task 2 都要求 projection 和 aggregate 分别校验，没有让任一 validator 接受另一种 shape。§5.5 的 command vector 含且仅含五个 aggregate 字段，`schema_version` 为 `data-foundation-tracer-command.v1`；按所示 UTF-8 JSON bytes 重算所得摘要与文档值一致。指定四处未出现同名异形、validator 复用、projection 直接参与 canonical hash 或 vector 指向错误 schema 的直接相关新 Major。
