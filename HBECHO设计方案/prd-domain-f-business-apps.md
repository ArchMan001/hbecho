## 一、这个域管什么

### 1.1 四个问题

1. **业务人员每天打开的页面在哪？** 他们要做的动作，哪些还没有界面？
2. **一个活动从开到收尾，经过几手？** 谁建、谁报名单、谁配规则、谁看结果、谁下发任务？
3. **名单怎么安全地进系统？** 传错了能不能撤回？冲突行怎么回到业务手里？
4. **F 与 A–E 的线划在哪？** 哪些东西 F 永远不该自己算、自己存？

### 1.2 不管什么

| 事情 | 归谁 |
|---|---|
| 组织、账号、归属、内容、媒资这些事实 | A 数据底座 |
| 谁能登录、能做什么、能看哪些行 | B 访问控制 |
| 从文本与图像抽信号、模板匹配 | C 识别能力 |
| 什么算达标、哪条内容命中、判定结果与证据 | D 规则与考核 |
| 指标口径、点检表模板、看板与导出 | E 指标与看板 |
| 活动计划本身（创建、加入、名单归属） | A 数据底座 §11 |
| 部署、配额、成本、备份 | I 运维与成本 |
| AI 调用、Prompt、脚本分析 | H AI 能力 |

### 1.3 一条主线

**1.0（只有导入）：**

```text
总部/分公司备好名单
  → 在导入中心下载模板
  → 上传 → 文件级校验 → 预检报告（主数据六类 / 名单三类）
  → 确认写入 → 异步批次写入
  → 冲突与错误行回流 → 业务修正后重传
  → 账号进入解析与采集（由 A 执行，F 不参与）
```

**2.0（活动闭环）：**

```text
活动建起来（F2）→ 名单进来（F5）→ 规则判定（D）
  → 点检表与看板（E）→ 任务下发与核销（F6）
  → 四角色工作台收口（F1）
```

### 1.4 一条硬边界：只编排，不复制

F 域**不允许**出现以下三类东西：

1. **不新建平行的业务主档**。不在 F 里建"活动账号表""内容库副本""用户画像表"；要展示就查 A 的事实。
2. **不重算 D 与 E 的结论**。页面上出现的"达标 / 未达标 / 完成率 / 粉丝增长"，必须是 D 或 E 已经算好并存下的值；F 只做筛选、排序、展示与跳转。
3. **不自己判权限**。F 的每个查询、导出与下载出口都走 B 的 Capability × DataScope，不在业务代码里写角色条件。

违反这三条的表现形态通常是"为了页面快一点，先存一份到 F 的表里"。这份副本一旦出现，两个数字迟早不一致，且没人能判断哪个是对的。

## 二、用户与场景

### 2.1 谁在用

| 角色 | 在 F 域做什么 | 1.0 |
|---|---|---|
| `platform_admin` | 权威主档导入与纠错、结构变更；外部监控账号清单；看全部品牌与全部批次 | ✅ |
| `hq_manager` | 创建活动计划（A 域入口）；导入与纠错**本品牌**主数据；看本品牌批次 | ✅ 主数据（授权品牌） |
| `branch_manager` | 加入活动计划、提报本分公司名单；处理回流行 | ✅ |
| `store_staff` | 1.0 无动作；2.0 看工作台、领任务、看本人账号档案 | ❌ |

### 2.2 三条真实路径

1. **年度名单刷新**：`hq_manager` 上传权威主档导出，看到「新增 210 / 更新 46 / 未变 8,071 / 错误 9 / 待确认撤店 12」，确认后写入；非授权品牌的行被跳过并报数。分公司不再上传固定信息。
2. **新门店开号**：`branch_manager` 在「五一活动」计划里下载名单模板，填 40 行（门店编码、专员姓名、手机号、主页链接）上传；3 行门店编码不属于本分公司被拒，2 行链接解析失败回流；其余 35 行进入采集，提交人成为本分公司负责人。
3. **传错了要纠正**：`branch_manager` 把别的分公司的名单误传进本计划。1.0 没有回滚（F-D06）：他打开批次详情拿到本批新增的账号清单，到 A 域的名单与监控开关里把这些账号撤出；已采集到的数据按 A 域保留规则留在库里。

### 2.3 规模

| 参数 | 数值 | 来源 / 状态 |
|---|---|---|
| 跨平台账号 | 6,000 | D-02、D-30 |
| 经销商 / 门店 / 专员 | 2,000 / 3,000 / 3,500 | 沿用旧总纲，待确认 |
| 单次平台级导入行数 | 数千级（权威主档导出） | 按门店规模推导，待实测 |
| 单次分公司名单行数 | 数十至数百 | 业务估算，待实测 |
| 单文件与单批上限 | 路径 1：10 MB / 10,000 行；路径 2：10 MB / 2,000 行（F-D12） | 已定 |

### 2.4 1.0 的边界

| 做 | 不做 |
|---|---|
| 两条导入路径的模板下载、上传、预检、确认写入 | 组织/账号的单条录入界面（属 A 域 §5.1） |
| 异步批次、进度查询、批次历史 | 定时导入、API 导入、邮件导入 |
| 冲突与错误行回流 Excel、人工重试 | 导入时直接修改已有记录（D-34） |
| 批次详情里列出本批新增的账号，供业务到 A 域纠正 | 按批次回滚、批量撤销（F-D06） |
| 平台级与分公司级的权限与范围隔离 | 自定义字段、模板编辑、多文件合并成一批 |

## 四、F5 · 数据导入中心（1.0）

### 4.1 两条导入路径

| | 路径 1 · 平台级主数据 | 路径 2 · 分公司活动名单 |
|---|---|---|
| 谁做 | `platform_admin` 与 `hq_manager`（授权品牌） | `branch_manager`（`hq_manager` 也可，名额豁免） |
| 什么时候 | 初次上线、每期刷新、新门店新专员 | 加入活动计划时、活动期间补报名单 |
| 传什么 | 一个文件：**权威主档导出**（11 列） | 一个文件：**名单**（门店编码 / 专员姓名 / 手机号 / 主页链接） |
| 能新增什么 | 授权品牌内：已有门店改名 / 改级 / 撤店确认；在已有经销商 / 板块 / 分公司下新增门店。跨品牌对象与关系变更回流超管（F-D08） | 只新增"某活动计划下的名单引用"，**不新增组织** |
| 规则出处 | A 域 §4.2 | A 域 §11.2、§11.2.2 |
| 范围校验 | 只能写入授权品牌，越品牌行被拒 | 门店必须属于本计划品牌与板块，且属于提交人分公司（A 域 §11.2.2 第二层） |

**两条路径的区别只有三件事**：谁能传、能新增什么、范围怎么校验。**其余流程完全一致**——同一个上传组件、同一套预检、同一个批次列表、同一套回流与纠错。不做两套界面。

### 4.2 一个导入中心，两个入口

- 导入中心是 1.0 唯一的 F 域页面，从导航直接进入，不依赖工作台（F1 不在 1.0）。
- 页面首屏是**入口选择**：选"平台主数据"或"活动名单"。选活动名单时，必须先选活动计划——**名单永远属于某个计划**，没有"游离名单"。
- 分公司选计划时**只能选本分公司已加入的活动计划**；总部按**授权品牌内**的计划；活动计划是消费侧统一入口（`prd-platform.md` §6.11）。F 不创建监控判定计划，也不读取判定结果。
- 两个入口共用一份批次列表；列表用「路径」列区分，不分成两个页面。
- 看不到某个入口的人，**只看到另一个入口**，而不是看到一个点了报错的按钮。

### 4.3 模板

- 模板由系统提供下载，**列名与顺序固定，不做别名兼容**（A 域 2026-10-29 决定）。
- 每份模板带**模板版本号**。文件里的版本号与当前模板不一致时整批拒绝，并提示重新下载（A 域 §11.2.2 第一层）。
- 模板里带表头与一行示例数据；上传时自动跳过表头，示例行单独标出、不进入数据，其余行照常预检（F-D10）。
- 格式为 **CSV**，GBK 与 UTF-8 都要能识别（D-08）。
- 模板说明里写清两个容易踩的坑：用 Excel 编辑后要**另存为 CSV**，不能直接改扩展名；门店编码、手机号这类字段**先把列设为文本格式再填**，否则前导零会被吃掉。

### 4.4 上传与文件级校验

上传后**先做文件级检查，整批通过才进入逐行处理**（A 域 §11.2.2 第一层）：

| 检查 | F 侧表现 |
|---|---|
| 模板版本号 | 不匹配 → 拒绝，给下载链接 |
| 必填列齐全 | 缺列 → 拒绝，展示正确列名与顺序 |
| 表头行 | 首行等于列名 → **自动跳过**，不要求用户删除（F-D10） |
| 示例行 | 识别为示例 → 标为「示例行」不进数据，其余行照常预检（F-D10） |
| 编码识别 | BOM（UTF-8/UTF-16）→ 严格 UTF-8 → 严格 GB18030 → 拒绝并给样本；提示另存为 UTF-8 CSV（F-D11） |

文件级失败**不产生批次、不落任何数据**。F 侧只负责把错误说清楚并给出下一步动作，校验规则本身以 A 域为准。

**名单模板没有平台列**（2026-11-02 决策）：平台由活动计划带出；逐行校验「解析出的平台 = 计划平台」属于 A 域 §11.2.2 第二层，不在这里做。

### 4.5 预检报告

预检是**只读的**：跑完全部行级校验，出一份报告，**此时库中没有任何新增**（A 域 §11.2.2 原则 1）。

报告按路径给不同的分类：

**路径 1 · 权威主档（六类）**

```text
新增 N         ——  可以写入
更新 M         ——  已有门店的非结构字段更新（名称 / 等级等）
未变 K         ——  与现有记录一致
错误 J         ——  不符合规则，附原因
待确认撤店 P   ——  本期导出未出现，需人工确认是否撤店
需超管处理 Q   ——  行本身合法，但涉及跨品牌对象或关系变更（新经销商/板块/分公司/大区、换经销商/板块），回流给超管
```

**路径 2 · 活动名单（三类）**

```text
新增 N   ——  可以写入
冲突 M   ——  已存在，按 D-34 不覆盖，需要人工处理
错误 K   ——  不符合规则，附原因，需要人工处理
```

- 报告可下载为 CSV，列与原文件一致，**追加「结果」「原因」两列**；
- 报告里能按结果筛选，能点进某一行看到具体原因（哪个字段、哪个规则）；
- **冲突不等于错误**：冲突是"系统里已经有"，错误是"这行本身不合法"；`需超管处理` 也不是错误，是权限边界；
- 预检结果**只对当前文件有效**；改文件后必须重新上传，不做"在页面上改几个单元格再提交"。1.0 不提供在线编辑。

### 4.6 确认写入与批次

- 预检通过后，业务点**确认写入**。写入是**异步任务**，立即返回批次号。
- 批次列表显示：批次号、路径、文件名、提交人、提交时间、状态、新增/冲突/错误数、可执行动作。
- 状态至少区分：`排队中` / `写入中` / `完成` / `失败`。**写完但有部分行失败**是一个正常终态，不是"失败"——必须能同时表达"新增成功 800、失败 20"。
- **幂等**：同一文件重复提交不重复建记录（A 域 §4.2）。账号按全平台判重，归属相同则直接引用，不重复采集（A 域 §11.2）。
- 写入期间可离开页面；进度与结果事后可查。

### 4.7 失败回流与重试

- 冲突行与错误行**不写入、不覆盖**，生成同格式 CSV 回流（A 域 §4.2）。
- 回流文件是"原文件的一个子集 + 原因列"，业务改完后**作为新文件重新上传**，产生新批次。1.0 不做"在原批次上补传"。
- 失败记录**不删除，保持可重试**（A 域 §11.2.1 教训 2）。旧系统"僵尸 pending"的根因就是失败行无人接管。
- 1.0 **不做自动重试**：解析失败可以人工重试，但系统不自己反复调供应商（付费调用须过 capability gate 与配额）。

### 4.8 传错了怎么纠正（1.0 不做回滚）

1.0 **没有「回滚批次」这个动作**（F-D06），三条理由：

1. 导入只新增（D-34），纠错需求集中在"这批不该进"。这件事在 A 域已有现成手段——**名单撤出**与**监控开关**（A 域 §4.3、§11.2 ⑦），不需要在 F 再建一套撤销。
2. 撤销的边界在 A/D 已经有完整设计：哪些账号被移出名单、已采集数据是否保留、判定按执行时的名单锁，这些在 A 域 §11 与 D 域 §2.0.1 定过。F 再定义一遍就会出现两个口径。
3. 业务实际很少遇到：导入前有预检，冲突与错误行都被拦下；真正会传错的是"整份文件传给了错的活动"，而这类错误的正确处置是撤名单，不是删数据。

**F5 在纠正路径里只做两件事**：

- 批次详情列出**本批新增的账号清单**（账号 ID、专员、门店、平台），可导出；
- 页面指明纠正入口在 A 域（活动计划名单 / 监控开关），**不提供就地撤销按钮**。

**代价要说清楚**：传错之后没有"一键恢复现场"。账号会在库里留下痕迹（主档、主页快照、供应商调用记录），只是被撤出名单、不再采集。这是 A 域"停用不删除"与"原始证据不可删"的直接结果，不是缺陷。

### 4.9 批次历史与审计

- 批次永久可查：谁、什么时候、传了什么文件、写了多少、失败多少。
- 记审计的动作：**确认写入**、**下载回流/预检文件**。审计口径随 B 域（1.0 保留一年，仅 `platform_admin` 可见）。
- 下载回流文件属于 B 域出口 4（导出文件），**提交时与交付前各查一次范围**，撤权后不得交付。

## 五、F1–F9 简版场景（2.0 方向，不构成合同）

> 这一章只写"这个模块做什么、什么时候需要它、边界在哪"，**不写验收标准**。任一模块进入 2.0 排期时，必须重新评审并另立 spec（F-D04）。

### F1 四角色工作台

- **做什么**：四类角色各自的首页——待办、趋势卡片、快捷入口。
- **什么时候需要**：业务开始每天登录，且"今天该干什么"需要系统提示时。
- **边界**：卡片只取 E 已算好的指标与 D 已出的判定；待办是对 F6 任务与 A 域同步异常的聚合视图。
- **不做**：自定义布局、拖拽看板、消息中心、IM 提醒。

### F2 活动管理与点检

- **做什么**：活动的新建、修改、关闭；绑定 D 的规则版本；指定参与范围；下发标准图。
- **什么时候需要**：开活动的人不再是技术角色、且活动数量超过一两个时。
- **边界**：**活动计划本身在 A 域**（F-D01），F2 只做活动的业务壳与配置界面；判定在 D、点检表在 E。
- **不做**：活动模板库、审批流、活动预算与费用结算。

### F3 账号台账与档案

- **做什么**：单账号的详情页——画像趋势、装修历史、同步状态、归属变更入口。
- **什么时候需要**：分公司要判断"这个号最近怎么样了"，而不是只看到一张汇总表。
- **边界**：只读 A 的事实；改绑、停用、改监控开关都调用 B/A 已有动作，F 不写自己的账号表。
- **不做**：账号质量评分（属 F7）、跨账号对比排名。

### F4 内容库

- **做什么**：内容广场（全量检索与筛选）、优秀内容池（人工挑选）、案例库（编集成专题）。
- **什么时候需要**：业务要"找几条好内容做示范"，而不是只看达标结果。
- **边界**：内容快照仍归 A；F4 只加**挑选与编集**这一层业务标注。
- **不做**：内容二次分发、版权管理、自动生成内容。

### F6 任务与执行闭环

- **做什么**：下发任务 → 执行 → 自动核销 → 完成率。
- **什么时候需要**：活动要求"某门店本周必须发 2 条"，而不是月末只看结果。
- **边界**：核销依据来自 D 的判定，F6 不自己判定；完成率口径来自 E，F6 不自己定义分母。
- **不做**：工单审批流、IM 通知矩阵、跨活动任务依赖。

### F7 账号质量评分

- **做什么**：多维评分与改进建议（内容质量、更新频率、互动健康度等）。
- **什么时候需要**：需要"给账号打分并排序"这类运营抓手时。
- **边界**：评分是 F 域的一次独立计算，**不是 D 的判定，也不进 E 的考核口径**；两者混用会让"考核不达标"和"评分低"变成同一件事。
- **不做**：评分影响考核结果。

### F8 热点与选题

- **做什么**：热榜聚合、选题建议。
- **什么时候需要**：内容团队需要选题输入时。
- **边界**：热榜数据的外部来源须单独定（自采违反"不自研爬虫"），F 只做聚合与呈现。
- **不做**：自动生成内容、热点预测。

### F9 投放记录

- **做什么**：投放登记（投了什么、花了多少、投给谁）、效果汇总。
- **什么时候需要**：投放费用要与内容效果对账时。
- **边界**：登记是 F 的动作，效果指标来自 E；不接广告平台。
- **不做**：广告平台对接、自动出价、预算审批。

## 九、验收标准（F5）

每条都必须能被业务人员判断真假；`[自动]` 指可由测试脚本验证，`[手工]` 指需要人在界面上操作确认。

### 路径 1 · 权威主档

- [ ] [自动] 权威主档导出分别以 GBK 与 UTF-8 保存后上传，均正确识别；编码识别不出时整批拒绝，库中无任何新增；
- [ ] [自动] 列名或顺序不符、模板版本号不符时整批拒绝；首行是列名时自动跳过，示例行单独标出，且不产生批次；
- [ ] [自动] 预检报告给出「新增 / 更新 / 未变 / 错误 / 待确认撤店 / 需超管处理」，此时库中业务写入为 0；
- [ ] [自动] 确认写入后产生批次号，批次状态可从「预检中」推进到终态，进度可见；
- [ ] [自动] 同一文件重复提交，所有行为「未变化」，不产生额外数据；
- [ ] [自动] 品牌、板块、大区不在文件中，由映射产生；映射缺失的行报错；
- [ ] [自动] `撤店情况` 不是「无撤销」或 `是否数字门店` 为「是」的行不写入，并说明原因；
- [ ] [自动] 经销商编码为 `--` / `#N/A` / 空的行回流，不静默丢弃；
- [ ] [自动] 本期未出现的门店不会自动停用，只生成待确认项；
- [ ] [自动] 失败行与原文写入导入批次，可按批次重试；
- [ ] [自动] 总部人员只能写入授权品牌，越品牌的行被拒并在报告中计数；
- [ ] [自动] 回流文件列与原文件一致并追加原因列，可下载。

### 路径 2 · 分公司活动名单

- [ ] [自动] `branch_manager` 只能导入本分公司门店；他分公司门店编码被拒并提示联系管理员；
- [ ] [自动] 门店编码不属于本计划品牌或板块时，整行失败；
- [ ] [自动] 链接解析出的平台与计划平台不一致时，整行失败，**不默认成抖音**；
- [ ] [自动] 分公司看不到同计划下其他分公司报的名单与批次；
