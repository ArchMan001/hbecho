# Tracer 五项合同修复定向复审

本轮只以 [`2026-09-03-094249-pr-0.md`](2026-09-03-094249-pr-0.md) 的 5 个 Major 为基线核对当前快照，没有重审已关闭且未受影响的历史问题。原问题 #1、#3、#4、#5 已形成对应合同；#2 的物理字段已补齐，但此前指出的 `initial_content_limit` 固定值与 P0 状态冲突仍存在。交叉复核另发现 ProviderCall response-action 语义、reconciliation 证明关系和两类 canonical JSON 摘要字节规范三个 Major 级缺口。

Watch for: **confirmed** Requirements 要保存 expected response action，而 v2 同一字段只允许保存实际响应值；**confirmed** reconciled 终态可由相关 ID 而非终态证据“证明”；**confirmed** `initial_content_limit` 的默认值/上限同时被固定和标为 P0；**confirmed** command 与 dominant-author evidence 的 SHA-256 都没有可复现的 canonical bytes 规范。

**Verdict**: NEEDS_CHANGES

## High-level view

基线逐项结论为：**#1 CLOSED · #2 OPEN（Major）· #3 CLOSED · #4 CLOSED · #5 CLOSED**。#1 的状态、时间、payload 和转换矩阵已经存在，但 **confirmed** 两个新发现的 ProviderCall 合同缺口仍阻塞该区域实施。

Canonical command 已落到 root SyncTask 的 subject 字段、版本化 task parameters 和摘要输入，root idempotency/status 也统一收窄到一年。**confirmed** design 仍把 v2 已固定的 limit 默认值和上限列为 P0，而该值又进入 canonical hash，因此 #2 尚未关闭。

已捕获 profile payload 已统一为强制复用；未决的只是哪些 locator strategy 会产生该 payload。Dominant-author 成功和拒绝路径都有长期载体，FK 清理不会随 operational lineage 删除它们；但 **confirmed** accepted evidence 与 command 摘要共享一个未定义 canonical serialization 的缺口。

<details>
<summary>Issues (4)</summary>

1. **Expected/actual response action 冲突（Major, confirmed）** — R2.2 要持久化 expected action，v2 仅有且只允许保存 actual evidence 的 `response_action`；新增独立字段并纳入矩阵，或删除该 SHALL、把 expectation 留在版本化 Adapter 合同。
2. **Reconciliation correlation 被当作结果证明（Major, confirmed）** — 任一 provider ID 或未受语义约束的 call FK 即可终态化 ambiguous call；要求非自引用、同一 logical effect、captured terminal evidence 与 outcome 映射，否则保持 ambiguous。
3. **`initial_content_limit` 同时固定与未决（Major, confirmed）** — v2 已固定默认 20/范围 1～20，design 仍列为 P0，且 effective value 进入 canonical hash；同步删除 P0 冲突或共同修订全部合同。
4. **Canonical JSON digest 无字节规范（Major, confirmed）** — command 和 accepted dominant-author evidence 都要求 SHA-256，却未定义或引用 canonicalization 标准；固定版本化 bytes 规则并增加跨实现 digest vectors。

## ProviderCall 原矩阵缺口已补齐，但 action 与 reconcile 合同仍不可实施

**基线 #1 — CLOSED，原 Major 已消除。** [`database-design-v2.md` §9.5–§9.6](../docs/domains/data-foundation/database-design-v2.md) 已逐状态定义必填/必空时间字段、metadata、payload role 和合法转换，包含发送前 `terminal/not_sent`、完整响应、known non-delivery `transport_error`、unknown remote outcome `ambiguous` 及 reconciled 终态。[`requirements.md` R14.6](../.kiro/specs/data-foundation-tracer/requirements.md)、[`design.md` §8.3](../.kiro/specs/data-foundation-tracer/design.md) 和 task 3/8 采用同一分流。

**Major — confirmed.** [`requirements.md` R2.2](../.kiro/specs/data-foundation-tracer/requirements.md) 要求每个调用保存 expected response action；v2 §9.5 只有 `response_action`，并明确它只能来自已捕获响应，不能由预期值回填。`prepared/in_flight/transport_error/ambiguous` 没有合法字段满足 R2.2。应新增 `expected_response_action` 并纳入矩阵，或从 R2.2 删除持久化要求、把 expectation 固定在版本化 capability/Adapter 合同中；不能复用 actual evidence 字段。

**Major — confirmed.** v2 §9.5 允许 `provider_task_id`、`provider_request_id` 或 `reconciled_by_provider_call_id` 任一非空即满足 reconciled 终态证明。前两者只是 correlation；后者没有要求目标调用与原调用同 provider/task/action、包含完整终态响应，或其 outcome 能映射到 `reconciled_succeeded/reconciled_failed`，自引用与无关调用也未排除。应由受限写入事务校验非自引用、相关性、目标 call 的 captured terminal evidence 与 outcome 映射；没有终态证据时原 call 保持 ambiguous。

v2 §9.5 对 reconcile 自引用使用 `ON DELETE SET NULL` 并规定同到期时先删原调用，§12.7 再按 payload→call→task 清理。删除顺序已闭合，但不能弥补引用对象缺少语义约束。

## Canonical TracerCommand 字段已落地，但 limit 仍有双重权威

**基线 #2 — OPEN，Major — confirmed.** v2 §9.3 已固定 manual SyncBatch + root `resolve_account` SyncTask、`subject_type='media_staff'`、`subject_id=media_staff_id`、原始 locator `subject_key` 与 `data-foundation-tracer-command.v1`；[`design.md` §4.3](../.kiro/specs/data-foundation-tracer/design.md) 和 task 2 已同步。v2 §9.1/§9.3 同时把 setting 默认设为 20、范围设为 1～20，并规定缺省命令复制冻结 setting，而 design §18 P0(7) 仍称默认值和最大值未决。

该冲突会改变进入 `canonical_command_sha256` 的 `effective_initial_content_limit`。应从 P0(7) 删除默认值/最大值，只保留 per-command override 与是否请求第二页等未决项；若 20/1～20 仍要开放，则需一起修订 v2、Requirements、design 和 task 2。

## Root 幂等与 status 已统一为一年窗口

**基线 #3 — CLOSED，原 Major 已消除。** [`requirements.md` R1.2–R1.3/R1.7](../.kiro/specs/data-foundation-tracer/requirements.md) 只在一年内承诺返回原 root 或 key conflict，到期后允许新命令且不承诺旧 status；R15.5 对 expired status 返回 non-disclosing 结果。v2 §9.3/§12.7、design §4.3/§6.2 和 task 2 的 fake-clock 验收均采用该边界，长期业务事实不随 task 删除。

## 已捕获 profile payload 现在只有强制复用一种行为

**基线 #4 — CLOSED，原 Major 已消除。** [`requirements.md` R3.6](../.kiro/specs/data-foundation-tracer/requirements.md)、[`media-platform-3.0-overview.md` §12.1(2)](../docs/product/media-platform-3.0-overview.md)、design §18 P0(5) 和 tasks 1/4/5 都要求 target homepage 已有 captured terminal `media_user_info` 时不得再发 profile 请求。P0 只负责识别哪些 locator strategy 会产出 payload 及锁定各策略调用数，没有二次付费分支。

## Dominant-author 长期载体已建立，accepted/rejected 与 FK 路径一致

**基线 #5 — CLOSED，原 Major 已消除。** v2 §8.2 在 `external_account_identifiers` 增加 policy、evidence、digest 和长期 batch FK；`dominant_list_author` 要求四字段同非空，`evidence_batch_id` 指向长期 `sync_batches` 并 `ON DELETE RESTRICT`，成功 evidence 首次写入后不可覆盖。拒绝路径把同版 evidence 放入不自动删除的 `data_quality_issues.detail` 并要求长期 `batch_id`；design §4.3/§10.3 和 task 5 覆盖 accepted/rejected、负向 fixture 与一年后解释性。

v2 §5.3/§12.7 仅置空长期表指向一年 call/task 的 FK，并保留 identity、batch 和 quality issue，因此 operational lineage 清理不会删除两条决策路径。

## Command 与 evidence 的 canonical SHA 没有可执行的字节合同

**Major — confirmed.** v2 §9.3 要求对 command 的 “canonical JSON” 求 SHA-256，§8.2 又称 `dominant-list-author-evidence.v1` 规定确定性 canonical JSON bytes，但当前只有对象示例、字段约束和 `author_counts` 排序；复核范围内没有命名 RFC 8785/JCS，也没有定义 key order、字符串 escaping、Unicode normalization、数字编码及 absent/null 规则。相同 locator 或 exact external ID 可被不同 serializer 产出不同 bytes，task 2/5 无法建立跨实现稳定 digest fixture。

应为两个 schema 固定版本化 bytes 规则或引用明确 canonicalization 标准，并补充覆盖 Unicode、转义、字段顺序、整数和空值的摘要 test vectors。外部 ID 与 locator 必须保持 exact text，不得为了摘要做 Unicode normalization。
