# ADR-0006 · 反向代理部署形态

- **状态**：accepted
- **日期**：2026-10-28
- **决策人**：刘学奎
- **关闭**：ADR README 未决选型 #4「反代形态（宿主 Nginx or 容器）」、runbook §16 #9

## 背景

- 当前只有一台测试 ECS（8 核 32G），生产 ECS 未购买；首版单站点、内部渐进开放。
- 应用采用 Docker Compose 编排（2026-10-28 决定），应用容器只绑 `127.0.0.1`，不直接对外。
- 备案期间域名不解析到公网 IP，开发访问走隧道（runbook §3.1）。
- hbdam 尚无可参考的生产反代：它的 `docker-compose.yml` 里没有 nginx 服务，`app` 绑 `127.0.0.1:3100`，runbook 只留下一段限流配置片段。

## 决定

**宿主 Nginx 作为反向代理。**

- Nginx 装在宿主机上，监听 80 / 443；
- 反代到绑定在 `127.0.0.1` 上的应用容器端口；
- 配置放仓库 `deploy/nginx/`，部署脚本同步到 `/etc/nginx/conf.d/`，执行 `nginx -t` 通过后 `systemctl reload nginx`；
- 证书续期用 acme.sh 或 certbot，放在宿主机 crontab，续期后 reload；
- **不允许手工改 `/etc/nginx/`**，配置的唯一来源是仓库。

## 备选与不选理由

| 备选 | 优点 | 不选的原因 |
|---|---|---|
| 容器内 Nginx | 配置随镜像版本化，环境一致 | 单站点收益低；证书目录挂载与容器内 reload 多一层；排查要先进容器；多维护一个镜像与一个 compose 服务 |

宿主 Nginx 常被担心的"配置不进版本控制"，用"配置入仓库 + 部署脚本同步"即可消除。

## 后果

- 服务器需要安装并配置 Nginx，纳入 runbook 的部署章节；
- 配置变更必须走部署脚本，不能 SSH 手工改（与"部署单一来源"一致）；
- 证书续期是宿主机定时任务，需要监控到期时间；
- 应用容器继续只绑回环，暴露面维持在 Nginx 一处。
- **转发客户端 IP 的约定**（2026-11-10，`b-access-control` 补）：对 Web 应用的反代配置必须用 `proxy_set_header X-Forwarded-For $remote_addr;` **覆盖**客户端自带的头，不用 `proxy_add_x_forwarded_for`；应用侧用 `HBECHO_TRUSTED_PROXIES`（生产必填）声明哪些地址是受信代理。否则应用的请求限流取不到可信 IP（所有人共用一个桶）或可被客户端伪造绕开。
