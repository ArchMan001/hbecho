## 一、这个域管什么

### 1.1 四个问题

```text
算得对不对     → 一个指标只有一个口径，改口径留版本
谁算在里面     → 参与名单与分母由 D 冻结，E 不反推
看到哪一层     → 从大区到专员逐级上卷，比率按组件算
看到的是哪一版 → 每个数字都带投影、截止时间与观测时点
```

### 1.2 不管什么

| 事情 | 归谁 |
|---|---|
| 内容、账号、评论、媒资怎么采 | A 数据底座 |
| 一条内容 / 一个账号算不算达标 | D 规则与考核 |
| 谁能看、谁能导 | B 访问控制 |
| 活动计划怎么建、名单怎么报 | A 域活动计划；名单导入界面属 F5（1.0），活动管理界面属 F2（2.0） |
| 队列、同步健康、供应商成本看板 | I 运维与成本（I2） |
| 课程学习数据 | G 学习平台（1.0 不进指标） |

### 1.3 一条主线

```text
业务触发一次判定执行（D）
  → D 输出：参与名单、每条内容的判定结果、每个专员的达标结论
  → E 冻结输入，生成一次投影
  → 点检表：组织节点 × 判定计划
  → 专员明细：谁达标、谁不达标、谁没拿到数据
  → 命中内容：证据
  → 看板：同一投影上的固定几张卡
  → 导出：同口径的 Excel
```

**E 的职责是"把已经发生的判定翻译成可审计的数"，不重新判定、不采集、不授权。**

## 二、用户与场景

### 2.1 谁在用

| 角色 | 在 E 域做什么 | 依据 |
|---|---|---|
| `platform_admin` | 看全部品牌；维护内置指标与自定义指标 | `report.read` / `metric.catalog.*` |
| `hq_manager` | 看授权品牌；维护本品牌的自定义指标 | 同上，品牌范围 |
| `branch_manager` | 只看本分公司及下属门店的点检、明细与导出 | 只读，不可配置指标 |
| `store_staff` | 只看本人一行 | 只读，**不可导出**（`report.export` ❌） |

### 2.2 三条真实路径

1. **总部月底通报**：`hq_manager` 打开活动点检看板，看到三个判定计划分别为 71% / 55% / 60%、两个分公司低于 40%（不同板块的计划不合并成一个总完成率，E-D03）；按分公司排序后点进最低的分公司，下钻到专员明细，筛出「未达标」与「未获取成功」两批人，导出 Excel 发给分公司。
2. **分公司催办**：`branch_manager` 只看本分公司，看到某个门店的完成率明显偏低，点进门店看到具体是哪几位专员没发，直接线下催办。他不能改模板、不能改指标，也不能看别的分公司。
3. **业务质疑数字**：专员说"我明明发了"，总部从命中内容找不到他，再下钻到专员明细看到他的结果是「未获取成功」，原因是账号不可访问；页脚显示本轮同步成功率 94%。总部据此把问题交给运营去处理账号，而不是判他不达标。

### 2.3 规模

- 账号 6,000、专员 3,500、门店 3,000（总 PRD §2.3）；分公司约 43（旧系统实测，以 A 域主数据为准）。
- 一次活动点检表：分公司数 × 判定计划数 × **每个判定计划 4 列**（考核人数、完成人数、完成率、未获取成功）。
- 一次投影的稀疏行：组织节点（约 1,400）× 计划级指标数（约 30）；各层通过条数随专员明细存，不进投影指标。
- 命中内容：一次活动万级；包含图片的导出必须异步。
- 性能候选目标：43 个分公司 × 20 个指标 P95 < 2s，须在真实查询与容量设计中确认。

### 2.4 1.0 的边界

| 做 | 不做 |
|---|---|
| 指标字典：内置 + 判定计划派生 + 受限自定义 | 指标 DSL、跨对象聚合、无限嵌套公式 |
| 投影与原子切换、整活动重算 | 增量重算、多投影并行对比 |
| 组织点检 + 专员明细 + 命中内容 | 一行一条的全量内容明细 |
| 一张固定看板 | 自由看板、排行榜、热力图、地图 |
| 异步导出 + 下载中心 | 定时推送、订阅、邮件 / 短信报表 |

## 三、概念

### 3.1 指标（Metric）

一个指标 = 唯一编码 + 业务名称 + 口径（分子 / 分母 / 聚合）+ 支持的粒度 + 单位 + 责任人 + 版本。

编码是稳定的英文标识，不用中文别名拼；显示名可以改，编码不变。改口径产生新版本，不覆盖旧版本。

### 3.2 三类指标来源

| 类型 | 谁产生 | 1.0 |
|---|---|---|
| 内置基础指标 | 系统预置 | ✅ 只有四个 |
| 判定计划派生指标 | 判定计划自动派生 | ✅ |
| 受限自定义指标 | 超管 / 总部基于前两类做一次四则运算 | ✅ |

### 3.3 投影（Projection）

一次判定执行 → 一组冻结输入 → 一份可查询的指标事实。

- 投影是 **E 的唯一数据源**：点检表、专员明细、命中内容、看板、导出都读同一份投影，不各算各的；
- 投影不可变：重算产生新投影，旧投影保留可查；**唯一例外是活动计划删除时的级联删除**（见 `prd-platform.md` §6.11）；
- 一个投影只使用一个判定执行，不混用两次执行的结果。
- **投影随判定计划删除**（2026-10-30 决策，见 `prd-platform.md` §6.11）：活动计划删除时，相关投影一并删除，先进回收站保留 30 天，期满物理删除；回收期内不进任何界面、不参与新查询。

**术语**：本文的「判定计划」即「监控判定计划」——A 活动计划下的 1..n 份，监控段归 C、判定段归 D；计划看板与投影都按它出数。

### 3.4 三个视图

| 视图 | 一行是什么 | 回答什么问题 |
|---|---|---|
| 组织点检表 | 一个组织节点 | 这个组织在某判定计划上完成率多少 |
| 专员明细 | 一名 `MediaStaff` | 谁达标、谁不达标、谁未获取成功 |
| 命中内容 | 一条命中内容 | 凭什么判定它达标（证据） |

三者共用同一投影 token，下钻不换版本。

**板块是表的边界，不是行**（2026-11-02 决策）：家装与水机的检测项、话题集合、标准图与阈值不同，达标与不达标不可比、不可加。因此：

- 组织点检表**按板块分表**，每张表用的是本板块判定计划的分母；
- 活动层看板只汇总**可加的量**（账号数、待复核数、已复核数），**不提供跨板块的合并完成率**；
- 某分公司在某板块没有参与账号时，该板块显示「未参与」，不显示 0。

### 3.5 完成率与「未获取成功」

以下口径由 D 域 v1.1（2026-11-04，D-71）决定，E 只照做，不另行解释。

**计划总完成率（点检表默认列）**

- **分母** = 判定计划参与专员数，**固定不变**；按板块拆分的计划，各自只算本板块的参与专员，**不跨板块合并分母**；
- **分子** = 计划总结果为「成功」的专员数；
- 「未获取成功」**计入分母、不计入分子**，并单独列出数量与原因；
- 「不达标」计入分母、不计入分子；
- 完成率 = 成功人数 ÷ 考核人数；
- 三者关系必须能对上：**参与 = 成功 + 不达标 + 未获取成功**。

**各层通过条数（只在专员明细与导出出现）**（2026-11-04，替代原「分项完成率」）

- D 为每个专员保存 C1 / C2 / C3（通过第 1 / 2 / 3 层的内容条数）与内容 / 评论 / 账号三项结果；
- 它们是计数，没有分母，不算比率，不进点检表与看板；
- 用途是回答「这个人卡在哪一层」。

不做的事：不把「未获取成功」当 0；不从分母里静默扣除；不因为某轮数据没拿到而让分母忽大忽小。

### 3.6 比率上卷

任何粒度上卷都聚合组件，不平均下级百分比：

```text
分公司分子 + 分公司分子 → 大区分子
分公司分母 + 分公司分母 → 大区分母
大区完成率 = 大区分子 / 大区分母
```

- 分母为 0 返回 `no_data`，显示 `—`，不是 `0%`；
- 计划总率按参与人数上卷；
- `distinct`（去重计数）、`selector`（如最佳内容）、`semi-additive`（如粉丝边界）各按自己的上卷规则，不伪装成 SUM；
- 自定义指标若含除法，必须拆成分子 / 分母分别上卷。

### 3.7 观测基准

1.0 只有 `last_observed`：

- 取**截止时点之前逻辑上最新的已终态快照**，把实际快照 ID 与观察时间冻结进投影；
- 投影发布后不随 `current_snapshot_id` 漂移；
- 页面与导出必须显示「最后观测：YYYY-MM-DD」；
- 粉丝类边界指标保存开始 / 结束两个主页快照 ID 与边界偏差；差值可为负，**不得声称"活动精确新增"**。

`n_day` 与它的 N、方向、容差在 2.0，见 E-D08。

### 3.8 值的四态

| 状态 | 含义 | 显示 |
|---|---|---|
| `value` | 有有效值（含真实 0） | 数字 |
| `no_data` | 没有可用快照，或分母为 0 | `—` |
| `partial` | 部分覆盖 | 数字 + 覆盖标记 |
| `invalid` | 数据非法或违反不变量 | 拒绝发布并告警 |

禁止 `COALESCE(..., 0)`；真实 0、缺失、显式 null、非法值四态互不转换（`CONTEXT.md` 不变量 14）。

## 四、E1 指标字典

### 4.1 判定计划派生指标

每个判定计划派生以下**计划级**指标，绑定判定计划的稳定 ID：

| 指标 | 名称 | 计算 | 1.0 |
|---|---|---|---|
| `participant_count` | 考核人数 | D 的参与名单 | ✅ 固定列 |
| `achieved` | 完成人数 | COUNT(计划总结果 = 成功) | ✅ 固定列 |
| `rate` | 完成率 | achieved ÷ participant_count | ✅ 固定列 |
| `unobtained` | 未获取成功人数 | COUNT(计划总结果 = 未获取成功) | ✅ 固定列 |

- 「不达标人数」不单独建指标：它 = 参与 − 成功 − 未获取成功，单独建会产生三个数对不上的风险；
- **`hits`（命中内容数）不进入点检表默认列**；命中内容视图仍保留（E-D15 / E-D22）；
- **不设分项指标**（2026-11-04，D-71）；各层通过条数作为专员明细的列，不进指标字典；
- 改判定计划别名只改显示名，编码不变，报表列绑定不断；
- 判定计划归档后，历史投影仍可解释，新配置不能选它，不按同名替换。

### 4.2 内置基础指标

1.0 只有四个，作为点检表的固定列：

| 编码 | 名称 | 口径 | 说明 |
|---|---|---|---|
| `account_count` | 账号数 | COUNT(DISTINCT 平台账号) | 限定在判定计划参与名单内 |
| `follower_total` | 粉丝总数 | SUM(账号最后观测粉丝数) | `last_observed` |
| `published_content_count` | 发布内容数 | COUNT(内容快照 in 时间窗) | 按账号各存一条（D-23） |
| `interactions_total` | 互动总数 | SUM(赞 + 评 + 转 + 收) | **1.0 不上线**：跨平台口径未定，保持 `disabled`（§十一 11.1） |

考核人数（`participant_count`）见 §4.1，由 D 的参与名单直接给出，**E 不从"发过内容的人"反推**。

### 4.3 受限自定义指标

允许：两个操作数 + 一个四则运算符。

- **操作数**：已发布的内置 / 派生 / 自定义指标，或常数；
- **运算**：`+ - × ÷`，**不嵌套**（一次只能一个运算）；
- **除法**自动拆成分子 / 分母，上卷时按组件聚合；
- **除零**返回 `no_data`，不是 0；
- **依赖无环**：保存时校验，成环拒绝；
- **影响面**：保存前展示被几份配置引用、覆盖哪些历史活动，要求确认；
- **维护者**：只有 `metric.catalog.manage`（超管 + 总部），按适用品牌。

例：`人均发布内容数 = published_content_count ÷ participant_count`。

### 4.4 强制校验

1. **分子 ⊆ 分母**：比率类指标的分子人群必须小于等于分母人群；不满足拒绝保存，并指出冲突项。
2. **观测基准必须显式**：每个互动类指标必须声明 `last_observed` 及其容差；未声明不能发布。
3. **计划级完整**：`achieved` ⊆ `participant_count`；参与 = 成功 + 不达标 + 未获取成功。

### 4.5 版本与影响面

- 改口径 → 新版本；历史投影固定使用旧版本，不静默重写。
- 改别名、说明、单位、显示格式 → 只改元数据，不产生新版本。
- 归档指标：历史可读；新配置不能选，提示或拒绝。

## 五、E2 预聚合与投影

### 5.1 冻结什么

| 项 | 来源 |
|---|---|
| 判定计划的执行 ID（outcome set） | D |
| 参与名单快照（`MediaStaff` 稳定 ID 集合） | D |
| 每个专员的内容 / 评论 / 账号三项结果与 C1 / C2 / C3 通过条数 | D |
| 账号归属快照（Staff / Store / Dealer / Brand / Sector / Branch / Region） | D 或 A，按执行时点 |
| 内容 / 主页快照 ID | A |
| 指标版本集合 | E1 |
| 观测策略版本 | E1 |
| 截止时间与时区（北京时间） | E |
| 构建实现版本 | E |

**归属按判定执行时的快照上卷**：账号改绑后，新执行的判定按新归属；已保存的投影不改写。不按内容发布时间归属，也不按当前最新归属。这与 D 域 2026-10-29 的决定一致。

### 5.2 粒度

投影的稀疏行 = 活动计划 × 监控判定计划 × 组织层级 × 组织节点 × 指标编码。


组织层级按 `CONTEXT.md`：`Region → Branch → Sector → Store → MediaStaff`。1.0 中 Sector（板块）是分表边界，不作为点检表的行层级（E-D12）。

`Dealer` 是**交叉维度**，不是组织父节点，不参与 `dealer → branch` 的错误上卷。

### 5.3 构建与切换

```text
判定执行完成 → planned → building → validating → ready → active
                                               ↘ rejected / failed / cancelled
```

- 判定执行完成后**自动构建并自动激活**（E-D11）：业务刷新即可看到新数，不设人工发布步骤；
- 幂等键 = 判定执行 ID + 指标版本集合 + 观测策略版本；重复事件返回同一结果，不产生两份事实；
- 激活原子完成：新投影生效，旧投影标 `superseded`；
- 构建或校验失败：旧投影继续服务并标 `stale`；无旧版时返回 `not_ready`，**不返回全 0**。

### 5.4 激活前校验

- `achieved` ⊆ `participant`；
- 分子 ≤ 分母；
- 参与 = 成功 + 不达标 + 未获取成功；
- 指标依赖完整且无环；
- 四态与粒度兼容；
- 归属快照完整（缺组织链的对象不悄悄丢，记质量问题并计数）；
- 同一投影不混用不同截止时间。

### 5.5 重算

- 只做**整活动全量重算**，不做增量；
- 触发：判定重跑、指标版本变更、手工重算；
- 重算产生新投影，不覆盖历史；
- 重算期间旧投影继续服务，页面显示"正在重算，当前显示上一版"。

### 5.6 失败与一致性

| 情形 | 行为 |
|---|---|
| 新投影构建失败 | 旧投影继续服务并标 `stale` |
| 参与名单为空 | `no_data`，不返回 0% |
| 快照缺失或非终态 | `no_data` / `partial` + 质量问题，不回退 `current` |
| 归属不完整 | 该对象不进上卷，页脚列出未归属数 |
| 重复事件 / Worker 重试 | 幂等，只产生一个投影 |

## 六、E4 报表

### 6.1 组织点检表

**行**：默认「大区 → 分公司」两级（E-D12）；可展开门店、专员。板块不是行，按板块分表（§3.4）。

**列**：

```text
组织列（大区 / 分公司 [/ 板块 / 门店 / 专员]）
+ 基础指标固定列（账号数、粉丝总数、发布内容数、互动总数）
+ 每个判定计划一组列（考核人数、完成人数、完成率、未获取成功人数）
```

- 判定计划别名作为跨子列的主表头；同一活动下多个判定计划并列为多组列（E-D01）；
- 空行来自冻结的参与名单与组织快照，**不从当前目录临时补**；
- 默认按组织序；可按任一指标排序；
- 单元格可下钻到专员明细，筛选条件带入；
- 完成率的分母是考核人数，不是"发过内容的人数"；
- **只出计划总结果**：点检表不出各层条数；下钻到专员明细查看「卡在哪一层」（E-D16 修订）；
- **命中内容数不在计划组列里**；命中内容在第三张视图中查看（E-D15）。

**页脚**（每张表都有）：

> 数据截止时间 · 判定执行时间 · **各判定计划版本** · 指标版本 · 观测策略 · **各判定计划考核人数与未获取成功数** · 同步成功率 · `stale` 标记

### 6.2 专员明细

**行** = 一名 `MediaStaff`（在参与名单内）。

- 多账号合并为一行，**不重复进入分母**；单独显示账号数。

**列**：组织链、专员姓名、平台、账号数、每个判定计划的总结果（成功 / 不达标 / 未获取成功）+ 未获取成功原因、**内容 / 评论 / 账号三项结果**（成功 / 不达标 / 未获取成功）、**C1 / C2 / C3 各层通过内容条数**、基础指标、最后观测时间。

- 筛选：判定计划、结果、组织、平台；
- 下钻：专员 → 命中内容。

### 6.3 命中内容

**行** = 一条**通过全部内容层**的内容（C3，E-D18 修订）。

- 按账号各存一条：同一作品出现在多个账号时各一行，重复计数是已知且可接受的代价（D-23），页面必须写明。

**列**：组织链、专员、平台、账号昵称、内容标题、发布时间、各层结果、证据摘要 / 入口、互动数、观测时点。

> 计划总结果是**专员级**的，不套到单条内容上；命中内容只展示内容级的各层结果。

- **不做**「一行一条、含未命中」的全量内容明细（E-D02）；分母核查由专员明细与页脚回答。

### 6.4 同一投影

三张视图的每次请求都带 `projectionId + outcomeSetId`；下钻沿用同一 token，避免用户点击时恰逢重算而看到另一版明细。

### 6.5 模板边界（1.0）

- 1.0 只有**一套系统内置模板**，三张视图由它驱动，判定计划自动展开；**各层通过条数只在专员明细与导出中展开**，业务零配置（E-D10）；
- 业务**不能**新建模板、改列、改表头层级；
- 可选列开关属于个人显示偏好，不产生模板、不影响他人；
- 业务自建模板、模板复制、考核项映射在 2.0。

### 6.6 数据质量

- 数据质量不是独立指标列，是**视图属性**：页脚固定显示，异常组织行标黄提示；
- 快手不采评论（D-51），依赖评论的判定项在 E 中显示为「未获取成功」，原因注明"平台不支持"，**不计入不达标**；
- 小红书评论部分覆盖（D-50）只影响相关对象 `partial` 标记，不修改判定结论；
- 数据质量问题只记录，不通过删除业务数据来"修复"。

- 文件分批写入私有临时对象，校验成功后原子发布；失败不暴露半成品；
- **交付前再查一次范围**：当前范围已收缩且产物含超范围数据 → 拒绝、删除或按新范围重建。

### 8.3 Excel 保真

三层表头 + 合并单元格；冻结行列；隔行底色；条件着色（命中 / 未获取 / 异常）；嵌入封面图（限并发、单文件图片数上限，超限降级为链接并在完成状态返回 warning）；主页与内容超链接；文件名模板；页脚口径说明。

### 8.4 下载中心

- 本人任务列表：对象、状态、行数、大小、创建时间、过期时间；
- 可重新下载、可取消排队中的任务；
- 下载为短期签名地址；保留期默认 7 天、**配置化**（不写死进表默认）（E-D13）；
- 撤权或停用后，未过期文件不可交付。

### 8.5 资源上限

行数、图片数、单图大小、文件大小、运行时长、并发都必须有硬上限；具体数值在 `e-metrics` spec 实测后定（§十一 11.4）。

- 指标与模板的「适用品牌」是**配置范围，不是授权**；
- 最终数据 = 配置适用 ∩ 当前 DataScope ∩ 用户筛选；
- 分享报表或看板只分享配置，不分享数据，不扩大范围。

## 十二、验收标准

每条都必须能被业务人员判断真假；`[自动]` 指可由测试脚本验证，`[手工]` 指需要人在界面上操作确认。

### E1 指标字典

- [ ] `[自动]` 新建一个判定计划后，点检表可选列里立刻出现该计划的完成人数、完成率、未获取成功人数；
- [ ] `[自动]` 改判定计划别名，表头与看板标题同步变化，编码与数据不变；
- [ ] `[自动]` 保存一个分子大于分母的比率指标被拒绝，并指出冲突项；
- [ ] `[自动]` 互动类指标未声明观测基准时不能发布；
- [ ] `[自动]` 自定义指标 `A ÷ B` 在分公司层与上卷到大区层都等于组件相除的结果；
- [ ] `[自动]` 自定义指标引用自身形成环时被拒绝；
- [ ] `[手工]` 超管能创建「人均互动数」并在点检表里作为可选列看到。

### E2 投影

- [ ] `[自动]` 同一判定执行重复触发构建，只产生一个投影；
- [ ] `[自动]` 构建失败时上一版投影继续可查，页面显示 `stale`；无上一版时显示"尚未生成"，不显示全 0；
- [ ] `[自动]` 参与 = 成功 + 不达标 + 未获取成功，页脚三个数能对上；
- [ ] `[自动]` 成功集合是参与集合子集；构造一个越界数据时投影拒绝发布；
- [ ] `[自动]` 账号改绑后，旧投影的归属与数值不变；新执行的投影按新归属；
- [ ] `[自动]` 重算产生新投影，旧投影仍可查。

### 组织点检表

- [ ] `[自动]` 点检表能回答「某分公司某判定计划的完成率」；
- [ ] `[自动]` 大区完成率 = 大区分子 ÷ 大区分母，不等于各分公司完成率的算术平均；
- [ ] `[自动]` 分母为 0 时显示 `—`，不显示 0%；
- [ ] `[自动]` 「未获取成功」单独成列，不并入不达标；
- [ ] `[自动]` 空行来自冻结名单：名单里的门店即使没有数据也出现，当前主数据里新增的门店不凭空出现；
- [ ] `[自动]` 同一组织节点在同一投影下，点检表、看板、导出的数值完全一致；
- [ ] `[手工]` 页脚显示数据截止、判定执行时间、各判定计划版本、各判定计划考核人数、未获取成功数与同步成功率。

### 计划组与各层条数（2026-11-04 修订）

- [ ] `[自动]` 点检表计划组固定四列：考核人数、完成人数、完成率、未获取成功；不出现命中内容列
- [ ] `[自动]` 点检表与看板不出现分项率或各层条数
- [ ] `[自动]` 只有一个完成率，分母 = 参与专员数；页脚写明分母
- [ ] `[自动]` 没有参与账号的组织显示「未参与」
- [ ] `[自动]` 专员明细有内容 / 评论 / 账号三项结果与 C1 / C2 / C3 条数；被判不达标的专员能看出卡在哪一层
- [ ] `[自动]` D 的「判定结果」Excel 明细含每条内容的各层结果，汇总含计划总结果与各层条数
- [ ] `[自动]` 命中内容视图的行 = 通过全部内容层的内容

### 专员明细与命中内容

- [ ] `[自动]` 一名专员有多个账号时，专员明细只有一行，不重复进入分母；
- [ ] `[自动]` 从点检表某格下钻，带出该组织下的专员明细，且仍是同一投影版本；
- [ ] `[自动]` 专员明细可筛出「未达标」与「未获取成功」两类名单；
- [ ] `[自动]` 命中内容一条一行，同一作品出现在两个账号时显示两行并有说明；
- [ ] `[手工]` 每条命中内容能看到命中的判定计划与证据入口。

### 看板

- [ ] `[自动]` 同一看板配置，总部与分公司打开看到不同范围，但同一可见单元数值一致；
- [ ] `[自动]` 切换活动计划后，所有卡片切换到对应的投影；
- [ ] `[自动]` 看板不出现不可见范围的组织；
- [ ] `[手工]` 六张卡片都能正常加载，空数据有明确空状态。

### 导出

- [ ] `[自动]` 万行级别的导出不阻塞请求，任务可查进度；
- [ ] `[自动]` 导出提交后撤权，产物不交付或按新范围重建；
- [ ] `[自动]` 文件名与页脚符合模板，含数据截止与版本；
- [ ] `[自动]` 图片数超限时降级为链接并在完成状态返回 warning；
- [ ] `[手工]` 导出的点检表含表头合并、冻结、条件着色与页脚。

### 边界

- [ ] `[自动]` `store_staff` 只能看到本人的一行，改参数无法越权；
- [ ] `[自动]` 分享看板或报表只复制配置，不扩大数据范围；
- [ ] `[自动]` E 不重新计算规则结论：外部写入一个与 D 结果不一致的手工值会被拒绝或标记。
