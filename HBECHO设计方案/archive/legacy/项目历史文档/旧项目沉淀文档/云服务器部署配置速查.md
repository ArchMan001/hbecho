## 5. 域名与 HTTPS

- 主域：`liuxuekui.click`
- 已用子域：`ai.liuxuekui.click`（本项目）、`hx.liuxuekui.click`、`quant.liuxuekui.click`
- 证书：宝塔签发 Let's Encrypt，自动续期
- 站点配置：`/www/server/panel/vhost/nginx/<域名>.conf`
- 证书路径：`/www/server/panel/vhost/cert/<域名>/fullchain.pem` 与 `privkey.pem`

新项目流程：宝塔面板 → 网站 → 添加站点（填子域）→ SSL → Let's Encrypt 申请 → 反向代理指向 `127.0.0.1:<端口>`。同时在域名 DNS 加一条 A 记录指向 `47.83.139.171`。

### 反代配置模板（前后端分端口）

```nginx
server {
    listen 80;
    listen 443 ssl;
    server_name <子域>.liuxuekui.click;
    ssl_certificate     /www/server/panel/vhost/cert/<子域>.liuxuekui.click/fullchain.pem;
    ssl_certificate_key /www/server/panel/vhost/cert/<子域>.liuxuekui.click/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    location /api/ {
        proxy_pass http://127.0.0.1:<后端端口>/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    location / {
        proxy_pass http://127.0.0.1:<前端端口>/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

单服务的项目只保留 `location /` 一段即可（本项目 `ai.liuxuekui.click` 就是全部转 `127.0.0.1:3004`）。

## 6. 部署脚本模板

新项目复制到 `scripts/deploy.sh`，只需改开头三行：

```bash
#!/usr/bin/env bash
# 部署脚本：同步代码到云服务器并重启容器
set -euo pipefail

SERVER="root@47.83.139.171"
REMOTE_DIR="/opt/<新项目名>"
LOCAL_DIR="$(cd "$(dirname "$0")/.." && pwd)"

echo "==> 同步文件到 ${SERVER}:${REMOTE_DIR}"
rsync -avz --delete \
  --exclude='.git' \
  --exclude='node_modules' \
  --exclude='.env' \
  --exclude='images/' \
  "${LOCAL_DIR}/" "${SERVER}:${REMOTE_DIR}/"

echo "==> 远程：确保 .env 存在"
ssh "${SERVER}" "[ -f ${REMOTE_DIR}/.env ] || (echo '❌ 服务器缺少 .env，请先上传' && exit 1)"

echo "==> 远程：构建并重启容器"
ssh "${SERVER}" "cd ${REMOTE_DIR} && docker compose up -d --build"

echo "==> 远程：清理悬空镜像"
ssh "${SERVER}" "docker image prune -f"

echo "==> 部署完成 ✓"
```

配套约定：

- `.env` 永不同步，服务器上单独维护一份。
- compose 端口一律写成 `"127.0.0.1:<宿主端口>:<容器端口>"`。
- 每个项目使用独立的 docker network，避免容器名冲突。
- 容器命名带项目前缀（如 `douyin-web`、`quant-api`），全服务器唯一。

## 7. 首次部署（无部署脚本时的手工流程）

```bash
# 1. 打包上传（排除敏感文件与大体积数据）
tar --exclude='.git' --exclude='node_modules' --exclude='.env' \
    --exclude='images' --exclude='*.xlsx' --exclude='*.csv' \
    --exclude='*.png' --exclude='*.jpg' --exclude='.DS_Store' \
    -czf /tmp/<项目名>.tar.gz .

scp /tmp/<项目名>.tar.gz root@47.83.139.171:/tmp/
ssh root@47.83.139.171 "mkdir -p /opt/<项目名> && cd /opt/<项目名> && tar -xzf /tmp/<项目名>.tar.gz"

# 2. 上传 .env
scp .env root@47.83.139.171:/opt/<项目名>/.env

# 3. 启动
ssh root@47.83.139.171 "cd /opt/<项目名> && docker compose up -d --build"
```

## 10. 安全注意事项

- 业务端口不要绑 `0.0.0.0`，一律 `127.0.0.1` + Nginx 反代。
- 安全组只放行 22 / 80 / 443；8888（宝塔）建议限定来源 IP。
- 密码、API Key、OSS Key 全部走 `.env`，绝不硬编码、绝不写进 git 或 IDE 配置文件。
- 待处理项：`.claude/settings.local.json` 的命令白名单中残留 MySQL 明文密码，需清理，并确认未被提交到远端仓库。
- `root` 直登方便但风险高，长期建议改为普通用户 + `sudo`，并关闭密码登录（`PasswordAuthentication no`）。
