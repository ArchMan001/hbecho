## 走查任务

用一句话：**总部运营给「618 家电焕新季」建一个判定计划，圈出参与内容，传封面标准图试跑，确认执行，然后去看点检表，下钻到未达标专员。**

建议按这个顺序走：

1. 判定计划列表 → 新建「618 焕新视频考核」→ 进入第 1 页；
2. 第 1 页：确认时间窗与形态（必选）→ 按需「添加能力」选文本识别 / 话题识别 / 视频时长 → 确认圈定 → 看条数与未获取原因；
3. 第 2 页：按需添加封面模板 / 元素 / 头像 / 背景 → 上传标准图（原型用「使用演示图」按钮）→ 试跑 → 看 0–10 分布与 11 档样例 → 调阈值；
4. 第 3 页：按需添加评论要求（ASR 在当前环境不可添加）→ 填关键词与达标方式 → 确认执行（弹窗写「发布 v1 并执行」）→ 执行记录；
5. 执行记录：先看到「等待采集」，再自动完成 → 看成功 / 不达标 / 未获取成功 → 打开专员证据；
6. 点「查看点检表」「下载判定结果」→ 两个 E 域的占位页（本原型不实现 E 的页面）；
7. 回到已发布的「618 主推视频考核」→ 新建草稿（选从 v3 复制、落到第 2 页）→ 看回退 / 新建草稿的确认弹窗。

原型右上角可以切换角色；左侧栏底部有「演示状态」，用于看加载、空、错误和无权限。

## 状态覆盖

- 列表：正常、加载、空、错误、无权限、只读；
- 向导：未圈定（不能试跑）、已圈定（未试跑）、已比对、能力不可执行（阻塞项）、回退预览；
- 执行：排队、执行中、等待采集（`waiting_on=demand`）、等待识别（`waiting_on=signals`）、完成、失败、取消、过期（结果行按保留期清理）；
- 结果：成功 / 不达标 / 未获取成功；`stale` 标记；同步不完整提示；零内容专员。

## 能力选择（第 1、2、3 页，2026-11-12 刘学奎要求）

- **计划级条件必选**：时间窗、内容形态始终生效，不放在能力列表里；
- **新建计划不预置可选能力**：只带时间窗与内容形态；演示数据里的旧计划保留已配能力，便于走查；
- **第 1 层按需添加**：点「添加能力」列出 **文本识别 / 话题识别 / 视频时长**，选择后才出现对应卡片，可删除；文本与话题允许多个，视频时长只有一个；
- **第 2 层按需添加**（v1 旧写法，已被精密版取代）：精密版列出 **整张图片对比 / 图片元素对比**（图片文字对比 2.0），每个能力先选对比元素（头像 / 封面 / 主页背景）；元素图的 `elementKey` 由上传字节 SHA-256 生成，用户不填写；
- **第 3 层按需添加**：列出 **音频 ASR / 评论要求**；ASR 能力未启用时菜单项禁用；
- 每张能力卡的结构统一：左侧图标 + **可编辑的能力名称（别名，可留空）** + 能力类型标签；右侧删除按钮；卡内字段两列或三列对齐，关键词 / 话题另起一行；
- **确定与回退按钮在右上角和页面底部各有一组**；第 1 页没有回退（第一层没有可回退的步骤），第 2、3 页有；
- **已定（2026-11-13，D-D20）**：能力别名进入判定段配置、随版本保存，不参与 `config_sha256`；别名显示在配置页、证据与导出明细，E 的点检表按判定计划分组、不按能力分列（精密版卡片提示已于 2026-11-16 改为「显示在配置页、证据与导出明细中」；v1 对照稿未改）；目前没有做「每个能力各自要求发布几条」，因为 D 的模型是内容要求一个专员级达标方式，不是按能力分别计数。

## A · 精密工作台（2026-11-13）

刘学奎选定 A 方向后，按同一套组件语言把三页向导重做了一版可点击原型：

- 打开 <http://localhost:4100/d-rule-engine/precision/>；
- 目录 `precision/`，是 v1 的完整拷贝 + 精密主题样式；v1 仍保留在 `../` 便于对照；
- 第 1 页：时间窗改为「起 / 止」一体化日期范围组件；计划级条件 + 行式能力条（序号 / 能力名 / 能力别名 / 删除）；文本能力一行三列：文本位置、组合方式、数量要求；话题能力一行两列：组合方式、数量要求，话题在下一行。**数量 N 是整层共享值**；原型演示仍显示 6 / 4 两个值，正式实现按 spec 同步为同一个 N，同层文本 / 话题条件 AND 后按点赞取前 N 条进入下一层；
- 第 2 页：原型展示三类能力——整张图片对比 / 图片元素对比 / 图片文字对比；**1.0 只启用前两类，图片文字对比（OCR）是 2.0，正式实现要置灰或不出现在添加菜单**；每个能力先选「对比元素」（头像 / 封面 / 主页背景），再上传标准图 / 元素图或填写文字；阈值支持「数字步进 + 可拖动刻度尺 + 直接输入」；**原来的「内容达标方式（计划级）」已从第 2、3 页移除**，数量要求并入第 1 层能力；
- 第 3 页：ASR / 评论能力条，评论的组合方式、达标方式、N 与关键词分行对齐；
- 试跑结果：每个能力独立的 0–10 分布；样例固定 5 个槽位，不足 5 张时从第一个槽位起显示，不按数量平均铺开；
- 列表、详情、执行记录、结果占位页同步使用精密主题；执行记录列表与原因标签是本次补齐的（v1 缺这两个函数）。执行详情不加视频明细入口；全量视频明细视图归 E，D 不建表。
- 截图：`precision/shots/p1-circle.png`、`p1-caps.png`、`p2-compare.png`、`p2-trial.png`、`p3-execute.png`（1440×900）。
- 状态：**已确认（2026-11-13，刘学奎）**；页面任务与 `src/app/` 代码待排期。全量视频明细视图归 E 域，D 不实现明细表，本版不加入口。

## 三版风格对比（2026-11-13）

同一页「第 2 页 · 比对」的能力配置，做了三种视觉方向，用于挑选按钮、选择器、上传框与阈值框的关系：

- 打开 <http://localhost:4100/d-rule-engine/explore/style-explorer.html>，可并排、单张、按桌面 / 手机视口查看；
- 候选文件在 `explore/`：`a-precision.html`、`b-soft.html`、`c-ledger.html`，方向信息在 `manifest.json`；
- **A · 精密工作台**：紧凑行式能力条，上传在左、数字步进 + 刻度尺在右；细线分隔、弱阴影、高密度；
- **B · 柔和层叠**：大圆角卡片，上传预览与阈值滑杆合在一张素材卡内；暖色底、柔和阴影；
- **C · 编辑台式**：表格式能力清单，编号 / 素材 / 标尺阈值 / 状态逐列对齐；宋体标题、纸张质感、红色信号；
- 三版都是**静态风格候选**，只做代表页，不接交互；选定后再把同一套控件语言铺到第 1、2、3 页。

## 与 design §15 的关系

本原型按 §15 的页面清单、流程、状态矩阵与字段可见性实现，并把§14 的待确认项体现在画面上：

- 确认执行弹窗写「发布 vN 并执行」，与 #2 一致；
- 新建草稿弹窗可以「从哪个已发布版本复制」，与 #27 一致；
- 回退只删草稿的圈定 / 试跑结果，已发布版本的执行结果保留，与 #3 一致；
- `waiting_on` 区分「等待采集」和「等待识别」，与 §7.2 的修正一致；
- 含 ASR 但能力未启用时，页面显示阻塞项并禁用确认，与 #8 一致。
