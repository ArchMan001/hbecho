## 和 v1 的差异

| 方面 | v1 | v2 |
|---|---|---|
| 页面开头 | 页面标题下紧接一块带渐变底、英文眉标（`ACTIVITY PORTFOLIO`）的大概览条 | 去底色、去英文眉标；改为上下两条细线的**概要带**，数字右对齐成组 |
| 侧栏卡片标题 | 英文眉标（`PLAN HEALTH` / `OWNERS` / `LIMITS`） | 中文小标签 + 品牌色短竖线（计划概览 / 负责人 / 限额） |
| 字号关系 | 正文 13 / 说明 11.5 / 标签 10.5，三级只差 1px | 正文与辅助收成 5 档：26 页面标题 / 17 概要带 / 15.5 区块标题 / 13.5 正文 / 11.5 辅助；统计数字另用 26，登录页标题另用 58 |
| 数字 | 统计、日期、编号统一用等宽字体 | 计数与日期用无衬线 + 等宽数字（`tabular-nums`），只有 ID、稳定码、时间轴时间用等宽字体 |
| 品牌色比例 | 选中芯片、步骤点、开关、进度条都用品牌渐变 | 渐变只留给主按钮与侧栏选中项；选中芯片、开关、步骤点改用品牌纯色/浅底 |
| 卡片 | 卡片套卡片，11 种圆角、5 套阴影 | 圆角收成 12（卡片）/ 10（控件）/ 8（芯片）；卡片只用 1px 边线，阴影只留给浮层 |
| 统计块 | 卡片里再放带边框的小卡片 | 去掉边框，改用 2px 左侧竖线分组 |
| 筛选区 | 高 30 的芯片 + 大留白卡片 | 高 28 的描边芯片，卡片内距收紧 |
| 表格 | 表头全大写、10.5px；行内 15px/16px | 表头不再大写、11px；行内 13px/16px，首列字重 550 |
| 角色标识 | 平台超管蓝、总部人员绿、分公司人员琥珀、门店专员灰，与状态徽标同形同色 | 角色改中性描边标签，绿 / 琥珀 / 灰只表示状态 |
| 返回链接 | 11.5px 灰色文字 | 34px 白底描边按钮，箭头 16px、文字 12.5px，hover 箭头左移 |
| 点击热区 | 芯片 30、行内按钮 30 | 视觉高度不变，用伪元素把可点区扩到 ≥36（桌面） |
| 登录页 | 68px 标题 + 三块毛玻璃事实卡 + 28px 圆角 | 58px 全白标题（不再用透明度做层次）；三块事实改成竖线分隔的编辑式列表；白卡 20px 圆角 |

## 怎么打开

在仓库根目录运行：

```bash
python3 -m http.server 4174 --directory ui-lab/hbecho-ui-v2
```

然后打开 <http://localhost:4174/>。与 v1（`4173`）同时开也可以，方便左右对照。

## 第二轮：内容与结构问题（2026-11-10）

刘学奎确认后，上一轮列出的 8 条内容 / 结构问题已处理：

1. **审计筛选**：左侧三栏改成表格上方一行（事件 / 时间两个下拉 + 已选说明），两个筛选现在真的会过滤数据；
2. **内部术语与 ID**：`reason_code` 表头改为「原因」，单元格人话在上、稳定码在下；审计操作者显示姓名（服务显示「访问控制服务 / 系统任务」），去掉 `user:1`；`p1` / `a1` 从列表和详情移除；`F5 路径 2`、A / D 域编号、`activity_plan.join`、`resolve_account`、`sync worker`、`GrantBoundary`、`MediaStaff`、`phone_exists`、权限码全部改成业务语言；
3. **计划详情**：删除右栏「快捷操作」卡，右栏只留计划概览 / 负责人 / 下游判定三张；
4. **批次详情**：8 个统计减为 7 个（「解析中」只在进度卡出现），去掉重复的「行结果」单位，改在统计上方写一次「行结果 · 共 200 行」；原因列改人话 + 稳定码；
5. **手机端筛选**：收进「筛选」按钮，展开才显示；「清空」不再单独折行；
6. **账号详情**：确认疑似空账号 / 手工补抓 / 移出名单移到详情顶部，900px 高度下可见；
7. **审计文案**：「手机号明文」改为「手机号按权限可见」，与脱敏演示数据一致；
8. **占位状态**：「XX 被关闭」改为「品牌被关闭」。
