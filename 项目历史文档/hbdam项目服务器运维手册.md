## 2. 如何连接

### 2.1 日常连接（已配好）

```bash
ssh hbdam
```

配置在 `~/.ssh/config`，内容包含三条端口转发：

| 本地端口 | 转发到 | 用途 |
|---|---|---|
| 8080 | 服务器 127.0.0.1:80 | **备案期间访问 Web**，浏览器开 `http://127.0.0.1:8080` |
| 13306 | 服务器 127.0.0.1:3306 | MySQL 客户端连接 |
| 15432 | 服务器 127.0.0.1:5432 | PostgreSQL 客户端连接 |

数据库端口永远不在安全组开放，客户端一律连 `127.0.0.1:13306` / `127.0.0.1:15432`。

### 2.2 凭证

| 凭证 | 位置 | 说明 |
|---|---|---|
| SSH 私钥 | `~/.ssh/hbdam_ed25519` | ed25519。**不要提交 git、不要外传** |
| SSH 公钥 | `~/.ssh/hbdam_ed25519.pub` | 已装到服务器 `/root/.ssh/authorized_keys` |
| root 密码 | `~/.ssh/hbdam_root_password.txt` | 28 位随机串。**仅供控制台 VNC 兜底**，SSH 已禁用密码认证。建议存入密码管理器后删除该文件 |

### 2.3 兜底通道（SSH 连不上时）

按优先级：

1. **会话管理（Session Manager）** —— 免密、免公网、无需开放入方向端口。需先开启，见 §4.2
2. **Workbench 网页连接** —— 控制台 → 实例 → 远程连接 → Workbench 远程连接。走阿里云内部链路，不依赖安全组 22 端口
3. **VNC** —— 系统起不来时唯一可用的通道（比如 fstab 写错导致启动失败）。用 §2.2 的 root 密码登录

> fstab 里给数据盘加了 `nofail`，正是为了避免"盘挂不上导致系统起不来、只能靠 VNC 救"的情况。

## 3. 已完成的配置

以下均已在 2026-08-18 完成并验证。

### 3.1 SSH 安全加固

服务器 `/etc/ssh/sshd_config.d/90-hbdam-hardening.conf`：

```
PasswordAuthentication no
PermitRootLogin prohibit-password
KbdInteractiveAuthentication no
ChallengeResponseAuthentication no
MaxAuthTries 4
ClientAliveInterval 300
ClientAliveCountMax 2
```

**处置记录**：实例初始 root 密码为弱密码（`品牌名+123.` 模式，属暴力破解字典高频项），且曾出现在聊天记录中。已换为 28 位随机串并关闭 SSH 密码认证，实测旧密码返回 `Permission denied (publickey)`。检查 7 天内 SSH 认证失败记录为 0 次 —— 风险窗口在被利用前关闭。

> **改 SSH 配置的铁律**：改完先 `sshd -t` 验证语法，再 `systemctl reload sshd`，**并且保持当前会话不断开**，另开一个终端验证能登进来之后才能关掉旧的连接方式。顺序错了就得走 VNC 救。

### 3.2 数据盘

```bash
parted -s /dev/nvme1n1 mklabel gpt
parted -s -a optimal /dev/nvme1n1 mkpart primary ext4 0% 100%
mkfs.ext4 -F -L hbdam-data /dev/nvme1n1p1
# fstab 用 UUID，不用设备名
UUID=1b64530e-7c32-44ff-b230-1539866b00aa /data ext4 defaults,noatime,nofail 0 2
```

三个选择的原因：

- **UUID 而非设备名**：NVMe 设备名可能在重启后漂移，写死 `/dev/nvme1n1p1` 有风险
- **`nofail`**：盘挂不上时系统仍能启动，保住 SSH 这条救援通道
- **`noatime`**：不记录文件访问时间，减少大量小文件读取（抽取管道）时的无谓写入

实测数据盘顺序写 **469 MB/s**。

### 3.3 系统参数

`/etc/security/limits.d/90-hbdam.conf`：nofile / nproc 均 65535
`/etc/systemd/system.conf.d/90-hbdam-limits.conf`：`DefaultLimitNOFILE=65535:65535`

> 两个文件都要写：`limits.conf` 只作用于登录会话，systemd 启动的服务（MySQL、PG、Docker）读的是 `system.conf`。只改前者会发现数据库的 fd 上限没变。

`/etc/sysctl.d/90-hbdam.conf`：

```
net.core.somaxconn = 4096          # 200 峰值在线 + 突发
net.ipv4.tcp_max_syn_backlog = 4096
net.ipv4.ip_local_port_range = 10240 65000
net.ipv4.tcp_tw_reuse = 1
vm.swappiness = 1                  # 32G 跑数据库，尽量不换页
vm.overcommit_memory = 1
fs.file-max = 1000000
fs.inotify.max_user_watches = 524288
```

时区本来就是 `Asia/Shanghai`，未改动。时间同步由 `chronyd` 负责，源为阿里云内网 NTP（`100.100.61.88`）。

### 3.4 Docker

| 组件 | 版本 | 来源 |
|---|---|---|
| Docker 引擎 | 28.3.3 | Alinux 官方源 `moby` 包 |
| Compose | 2.26.1 | Alinux 官方源 `docker-compose-plugin` |

> Alibaba Cloud Linux 4 上阿里云推荐装 `moby`（命令、服务名 `dockerd`、API 与标准 Docker 一致）。**但 `moby` 不含 compose 插件**，需另装 `docker-compose-plugin`。源里有 2.26.1，比手动下载二进制好维护。

`/etc/docker/daemon.json`：

```json
{
  "data-root": "/data/docker",
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "3" },
  "live-restore": true,
  "default-ulimits": {
    "nofile": { "Name": "nofile", "Hard": 65535, "Soft": 65535 }
  },
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.net",
    "https://docker.1ms.run"
  ]
}
```

四项的原因：

- **`data-root` 指向数据盘**：镜像和容器层会持续长大，不能占系统盘
- **`log-opts` 轮转**：不配这一项，容器日志能把磁盘写满。这是自建 Compose 部署最常见的事故
- **`live-restore`**：Docker 守护进程重启时容器不停
- **`registry-mirrors`**：Docker Hub 在国内 ECS 上不可达（实测 `registry-1.docker.io` 超时），必须配加速源

> 阿里云 ACR 的 `registry.cn-beijing.aliyuncs.com/library/*` 命名空间已不再公开（返回 `pull access denied`），不能当官方镜像源用。

### 4.1 `[ ]` 收紧安全组 22 端口

**为什么急**：22 端口当前对 `0.0.0.0/0` 开放。虽然已关闭密码认证（只能密钥登录），但公网暴露的 SSH 会持续被扫描，日志噪音大，且一旦将来出现 OpenSSH 漏洞就是直接暴露面。

**先读这一段再动手**：你的出口 IP 是 `223.78.94.132`（山东移动，青岛）。移动宽带的 IP **大概率是动态的**，重启光猫就会变。所以**不能**简单锁死到这个 IP，否则 IP 一变就进不去了。

正确顺序是：**先做 §4.2 开启会话管理（兜底通道），确认能用，再回来做本节。** 这样即使 IP 变了也有路进去。

#### 操作步骤

1. 打开 ECS 控制台 <https://ecs.console.aliyun.com>
2. 左上角**地域切换器**选「华北2（北京）」。选错地域会看不到实例，这是最常见的第一个卡点
3. 左侧菜单 → 「实例与镜像」→「实例」，找到 `hbdam`
4. 点实例名称 `hbdam` 进入详情页
5. 点上方「**安全组**」页签（有些界面版本叫「网络与安全组」）
6. 列表里会有一个安全组，点它右侧的「**配置规则**」（或点安全组 ID 进去后选「访问规则」）
7. 确认在「**入方向**」页签

现在你会看到一条 22 端口、授权对象 `0.0.0.0/0` 的规则。**先加新的，别急着删旧的。**

8. 点「**手动添加**」，填：

| 字段 | 填什么 |
|---|---|
| 授权策略 | 允许 |
| 优先级 | `1` |
| 协议类型 | SSH(22)（或「自定义 TCP」+ 端口范围 `22/22`） |
| 授权对象 | `223.78.94.132/32` |
| 描述 | `SSH-liuxuekui-mobile-20260818` |

> `/32` 表示只这一个 IP。描述里写清是谁、什么时候加的，将来清理规则时才知道能不能删。

9. 点「保存」。**安全组规则立即生效，不需要重启实例。**

10. **验证**（关键，别跳过）。在本机新开一个终端：

```bash
ssh -o BatchMode=yes hbdam 'echo 连接正常'
```

必须看到「连接正常」才能继续下一步。

11. 验证通过后，回到规则列表，找到那条 22 端口 + `0.0.0.0/0` 的规则，点「删除」。

> **为什么必须删**：阿里云安全组的规则是**并集**生效。只要 `0.0.0.0/0` 那条还在，新加的窄规则就毫无作用 —— 全网依然能访问。这是很多人以为自己收紧了但其实没有的原因。

12. 再验证一次 `ssh hbdam`，确认仍然通。

#### 如果以后 IP 变了连不上

先用 §4.2 的会话管理进机器（不受安全组影响），然后回到本节步骤 8，用新 IP 加一条规则、删掉旧的。或者临时把授权对象改宽为 `223.78.0.0/16`（移动网段，比全网小得多），牺牲一点精确性换稳定性。

> **域名 whois 与备案主体不一致是最高频的驳回原因。** 如果 `hbmarketer.com` 注册在个人名下但要以公司主体备案，得先做域名过户。这个动作有几天延迟，越早查越好。

#### 第三步：提交

1. 备案控制台 → 「开始备案」，按引导填：主体信息 → 网站信息 → 上传材料 → 真实性核验
2. 网站信息里域名填 `hbmarketer.com`（主域名），网站名称不要带「中国」「国家」「国际」等字样，也别用纯个人昵称
3. 提交后流程：阿里云初审（1–2 工作日）→ 短信核验（**收到后 24 小时内必须点链接确认，否则作废重来**）→ 管局审核（1–20 工作日，多数 1–2 周）

#### 备案期间的红线

**不要把 `www.hbmarketer.com` 解析到 `123.57.248.189`。** 未备案域名解析到内地服务器提供服务，会被阿里云拦截，并且影响备案审核。

开发照常进行，访问走 §2.1 的 SSH 隧道（`http://127.0.0.1:8080`）。这条路径已实测可用，且公网 80 端口不可达，不会被巡检命中。

#### 备案通过后

1. 在 `www.hbmarketer.com` 的 DNS 里加 A 记录指向 `123.57.248.189`
2. 安全组开放 80 / 443
3. 网站底部加备案号，并链接到 <https://beian.miit.gov.cn>（**管局会复查这一项，不挂会被撤销备案**）
4. 然后才能做 §4.4 的 CDN

### 4.4 `[ ]` 创建 OSS Bucket

**现在就能做，不用等备案。** OSS 走默认域名不需要备案，直传、内网打包、签名下载全部可用。9.1TB 迁移也可以立刻开始。

#### 创建

1. 打开 OSS 控制台 <https://oss.console.aliyun.com>
2. 点「**创建 Bucket**」
3. 逐项填：

| 字段 | 填什么 | 为什么 |
|---|---|---|
| Bucket 名称 | 建议 `hbdam-assets`（全局唯一，只能小写字母数字和短横线） | |
| **地域** | **华北2（北京）** | ⚠️ **最关键的一项**。与 ECS 同地域，内网流量才免费。选错要重建，且已上传的数据得跨区复制 |
| 存储类型 | 标准存储 | PRD 5.5：全量先进标准，再由生命周期自动降档 |
| 同城冗余 | **关闭**（即 LRS 本地冗余） | 素材在百度网盘和本地都有副本，ZRS 是纯浪费钱 |
| 读写权限 | **私有** | 全部访问走签名 URL / CDN 鉴权 |
| 版本控制 | 不开启 | 版本靠 OSS key 里的 `v{version}`（域G 3.1），不用 OSS 版本控制 |
| 服务端加密 | 无（或 OSS 完全托管） | 按需 |
| 实时日志查询 | 可开 | 便于排查访问问题 |

> **「地域：中国内地通用」是资源包的适用范围，不是 Bucket 的位置。** 已购的 OSS 资源包写着「中国内地通用」，那只是抵扣券能用在哪些地域。Bucket 建在哪，是创建时单独选的。Bucket 误建在杭州，资源包照样抵扣存储费，但 ECS 读写它就变成跨地域公网流量，全额计费且无任何提示。

4. 点「确定」

#### 配置 CORS（浏览器直传的前提）

不配这一项，前端直传会被浏览器拦掉，报 CORS 错误。

1. 进入刚创建的 Bucket → 左侧「数据安全」→「**跨域设置**」（或「权限管理」→「跨域设置」）
2. 点「创建规则」：

| 字段 | 填什么 |
|---|---|
| 来源 | `http://127.0.0.1:8080`（换行）`http://localhost:8080` |
| 允许 Methods | `GET` `POST` `PUT` `HEAD` |
| 允许 Headers | `*` |
| 暴露 Headers | `ETag`（换行）`x-oss-request-id` |
| 缓存时间 | `600` |

> 备案通过、正式域名启用后，回来把 `https://www.hbmarketer.com` 加进「来源」。
> 「暴露 Headers」里的 `ETag` 是分片上传必须的 —— 前端要读 ETag 来确认每个分片，不暴露的话大文件上传会失败。

#### 配置生命周期规则

1. Bucket → 左侧「数据管理」→「**生命周期**」
2. 创建**第一条**规则（清理打包产物）：

| 字段 | 填什么 |
|---|---|
| 状态 | 启用 |
| 应用范围 | 指定前缀 |
| 前缀 | `packages/` |
| 文件生命周期 | 距最后修改时间 `7` 天后 → 删除 |

理由：zip 包是可以从原文件重建的派生物，留着纯占存储费。域G 已定 7 天。

3. 创建**第二条**规则（清理碎片）：

| 字段 | 填什么 |
|---|---|
| 状态 | 启用 |
| 应用范围 | 整个 Bucket |
| 碎片（未完成的分片上传） | `7` 天后删除 |

> **第二条是刚需，不是可选项。** 9.1TB 迁移必然多次中断，每次中断都留下未完成的分片。这些碎片**在控制台文件列表里看不到，但照常计费**。不配这条，账单会莫名增长且找不到原因。

4. 降档规则（L2 → 低频等）暂不配。域G 3.2 说明具体天数需按实际访问数据调整，等有访问日志再定。

#### 验证内网连通

创建完在服务器上验证（把 `<BUCKET>` 换成实际名字）：

```bash
ssh hbdam 'curl -s -o /dev/null -w "内网 HTTP %{http_code}\n" \
  https://<BUCKET>.oss-cn-beijing-internal.aliyuncs.com/'
```

返回 `403` 是**正常的** —— 说明 bucket 存在且拒绝未签名的匿名访问，正是私有权限应有的表现。返回 `404` 说明 bucket 名字错了。

### 4.5 `[ ]` 绑定实例 RAM 角色（免 AccessKey）

**为什么要做**：如果把 AccessKey 写进服务器的配置文件或环境变量，那把长期密钥就落在磁盘上了 —— 一旦机器被入侵或配置文件误提交进 git，攻击者拿到的是可以长期使用的凭证。实例 RAM 角色的做法是：代码向本机的元数据地址要一个**临时凭证**（自动轮转、有有效期），机器上不存任何长期密钥。

#### 第一步：创建权限策略

1. 打开 RAM 控制台 <https://ram.console.aliyun.com>
2. 左侧「权限管理」→「**权限策略**」→「创建权限策略」
3. 切到「**脚本编辑**」页签，把内容替换成（把 `<BUCKET>` 换成实际 bucket 名）：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:GetObject",
        "oss:PutObject",
        "oss:DeleteObject",
        "oss:ListObjects",
        "oss:GetObjectMeta",
        "oss:AbortMultipartUpload",
        "oss:ListParts"
      ],
      "Resource": [
        "acs:oss:*:*:<BUCKET>",
        "acs:oss:*:*:<BUCKET>/*"
      ]
    }
  ]
}
```

4. 名称填 `hbdam-oss-rw`，保存

> **不要用 `AliyunOSSFullAccess`。** 那个策略给的是账号下**所有** bucket 的全部权限，包括删除整个 bucket。上面这份只给单个 bucket 的读写，且不含删 bucket 的权限。

#### 第二步：创建角色

1. RAM 控制台左侧「身份管理」→「**角色**」→「创建角色」
2. 可信实体类型选「**阿里云服务**」
3. 角色类型「普通服务角色」，受信服务选「**云服务器 ECS**」
4. 角色名填 `hbdam-ecs-role`，创建
5. 创建完点「**添加权限**」，在「自定义策略」里选刚建的 `hbdam-oss-rw`，确定

#### 第三步：绑定到实例

1. 回到 ECS 控制台 → 实例列表 → 勾选 `hbdam`
2. 右上「更多」→「实例设置」→「**授予/收回 RAM 角色**」
3. 选 `hbdam-ecs-role`，确定。**立即生效，不用重启**

#### 第四步：验证

```bash
ssh hbdam 'curl -s http://100.100.100.200/latest/meta-data/ram/security-credentials/hbdam-ecs-role'
```

应返回一段 JSON，含 `AccessKeyId`、`AccessKeySecret`、`SecurityToken`、`Expiration`。看到 `Expiration` 就对了 —— 那是有效期，说明是临时凭证。

拿不到就查：角色名拼写、是否真的绑上了、`100.100.100.200` 是阿里云元数据服务的固定地址（内网，不需要配路由）。

#### 代码怎么用

阿里云各语言 SDK 都支持「实例 RAM 角色」凭证提供者，配置角色名即可，SDK 自己负责取凭证和过期刷新。**代码里不出现任何 AccessKey。**

浏览器直传是另一条路：由后端调 STS `AssumeRole` 签发更短有效期的临时凭证给前端（域G 3.5 定的 `sign.upload_expires` = 3600 秒）。前端永远拿不到长期密钥。

### 4.6 `[ ]` 配置自动快照

**作用**：整盘的时间点备份，是搞坏系统后最省事的回滚手段。

1. ECS 控制台左侧「存储与快照」→「**快照**」→「快照策略」（或叫「自动快照策略」）
2. 「创建策略」：

| 字段 | 填什么 |
|---|---|
| 策略名称 | `hbdam-daily` |
| 创建时间 | `03:00`（低峰期） |
| 重复日期 | 每天 |
| 保留时间 | `7` 天 |
| 跨地域复制 | 不开（额外收费，本项目不需要） |

3. 创建后点「**设置磁盘**」（或在磁盘列表里选盘 → 设置自动快照策略），把**系统盘和数据盘都勾上**

> 只给系统盘配是常见遗漏。数据库数据在数据盘，那才是最需要备份的。

**快照不能替代数据库逻辑备份**：快照是块级的，恢复粒度是整盘。误删一张表时你不会想把整盘回滚到昨天。所以还要另配 `mysqldump` / `pg_dump` 每日导出到 `/data/backup`，再同步一份到 OSS。这条等数据库部署时一起做。

### 4.7 `[ ]` 配置监控告警

1. 打开云监控控制台 <https://cloudmonitor.console.aliyun.com>
2. 左侧「报警服务」→「**报警规则**」→「创建报警规则」
3. 产品选「云服务器 ECS」，资源范围选实例 `hbdam`
4. 按下表建三条规则（可以在同一个规则里加多个条件）：

| # | 指标 | 阈值 | 为什么是这个数 |
|---|---|---|---|
| 1 | **磁盘使用率**（`/data`） | 连续 2 次 > 80% | ⚠️ **最关键的一条**。数据盘只有 100G，是本机最紧的资源 |
| 2 | CPU 使用率 | 连续 3 次 > 80% | 打包是 CPU 密集（PRD 2.4：唯一压力点）。这条报警直接告诉你打包 worker 数配多了 |
| 3 | 公网流出带宽 | 连续 2 次 > 25 Mbps | 接近 30 Mbps 上限说明有流量在穿 ECS，而架构设计是要绕开它的 |

5. 通知方式：勾选短信 + 邮件，联系人组选你自己（第一次用需要先在「报警联系人」里创建联系人和联系人组）

> 磁盘使用率监控需要 ECS 装监控插件（云监控 Agent）。实例详情页 CPU/内存旁边如果显示「安装插件」，点一下装上。不装的话只有 CPU 和网络指标，看不到磁盘和内存。

## 5. 常用运维命令

```bash
# 连接
ssh hbdam

# 磁盘水位（数据盘 100G，重点看这个）
ssh hbdam 'df -hT /data /'

# 数据盘各目录占用排序

ssh hbdam 'journalctl -u sshd --since "-24h" --no-pager | grep -ciE "failed password|invalid user"'

ssh hbdam 'uptime; free -h'

```

## 6. 新项目复用：从 0 开始的顺序

这一节是给「另一个从 0 开始的项目」用的。顺序经过本次实践验证，**按序做能避开几个会互相锁死的坑**。

### 阶段一：买之前先定的三件事

| # | 决定什么 | 为什么必须在买之前 |
|---|---|---|
| 1 | **地域** | ECS、OSS 必须同地域。买错要重建，已传数据得跨区复制。国内用户面向的项目就选内地地域 |
| 2 | **域名后缀能否备案** | 工信部只批复了部分顶级域。`.com` / `.cn` 稳妥；冷门后缀（如 `.click`）可能根本无法备案，会导致整个 CDN 和域名访问方案作废。验证方法：在备案系统填域名走到「网站信息」步骤，不支持会直接报错 |
| 3 | **系统盘 / 数据盘分开** | 数据盘单独挂载，数据与系统解耦。重装系统时数据盘不受影响 |

**买的时候：登录凭证直接选「密钥对」，不要选密码。** 本次实践中用的是密码，且是弱密码，等于开局就给自己制造了一个必须紧急处理的安全问题。选密钥对可以完全跳过后面的换密码、装公钥、关密码认证这三步。

### 阶段二：机器到手后的顺序（关键）

```
1. 打通兜底通道         ← 开启会话管理。必须最先做
2. 装公钥、验证密钥登录
3. 关闭 SSH 密码认证     ← 验证成功后才能做
4. 收紧安全组 22         ← 有兜底通道才敢做
5. 挂数据盘（UUID + nofail）
6. 系统参数（limits 两处 + sysctl）
7. 装 Docker（改 data-root、日志轮转、镜像加速）
8. 配快照 + 监控告警
9. 建 OSS（同地域 + 私有 + LRS + CORS + 生命周期）
10. 绑实例 RAM 角色
11. 提交 ICP 备案（可与 5–10 并行）
```

**为什么第 1 步必须最先**：第 3、4 步都是「可能把自己锁在门外」的操作。没有兜底通道就做这两步，一旦出错（sshd 配置写错、IP 变动、安全组填错），唯一的救援方式是控制台 VNC + root 密码 —— 而如果密码也刚好被改坏，就只能重装系统了。

### 阶段三：三条容易踩的坑

| 坑 | 后果 | 怎么避 |
|---|---|---|
| OSS endpoint 漏写 `-internal` | **无报错、无变慢、只在账单上体现**。同地域下公网 endpoint 物理上也走内部骨干，测不出差异 | endpoint 集中在一处配置，code review 必查 |
| 容器日志不配轮转 | 磁盘被日志写满，服务全挂 | `daemon.json` 里配 `log-opts` |
| OSS 不配碎片清理 | 中断的分片上传在控制台**看不见但计费**，账单莫名增长 | 生命周期规则加「碎片 7 天删除」 |

### 阶段四：并行推进的事

备案要 1–3 周，但它**只阻塞两件事**：域名对外访问、CDN 加速域名。以下全部不受阻塞，应并行：

- OSS 建桶与数据迁移（走默认域名，无需备案）
- 全部后端开发（访问走 SSH 隧道 `http://127.0.0.1:8080`）
- 数据库部署、内容抽取管道

**代码侧要提前留的两个接缝**：① 所有 endpoint 走环境变量，`CDN_DOMAIN` 留空时自动回落 OSS 公网签名；② 下载 URL 的生成收敛到一个函数。这样备案通过后接 CDN 只改配置，不动调用点。
