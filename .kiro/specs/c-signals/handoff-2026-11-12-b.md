## 4. 任务 11、12、13 要做什么（补充 tasks.md 原文）

### 任务 11 · 保留期与清理

- **写入时的 `expires_at` 已经做了**：成功结果 +1 年、失败结果 +3 个月（`scoring/result-row.ts`）、历史行 +1 年（`features/ingest.ts`）、任务 +1 年（`tasks/queue.ts`）。**还没做**的是：
  1. `retainUntil(resultIds, until)`：`UPDATE signal_results SET expires_at = GREATEST(expires_at, :until)`，只接受结果行 ID，传较早时间不缩短（design §7.11）。要在 `assemble.ts` 暴露，并按 SG-14 补授权（调用方是 D 的服务身份，Capability 建议用 `rule.run.execute`，与 `requestScores` 一致；先查 requirements SG-14 再定，定了写进完成记录）。
  2. 清理器：分块（每块 1000）`DELETE … WHERE expires_at < :now ORDER BY expires_at LIMIT 1000`，循环到无行；对象是 `signal_results`、`signal_history`、`signal_tasks`（**只删终态任务**：`succeeded` / `dead`，不删仍在跑的）。特征行**不清**。幂等、可中途退出重跑。
  3. 清理不入队、不重算；清理后读取得 `missing(not_computed)`，任务表无新行；被清理结果行对应的 `succeeded` 任务 `result_id` 会被 `ON DELETE SET NULL` 置空，`requestScores` 随后把它置回 `pending`（任务 8 已覆盖这条路径）。
- 验证项见 tasks.md 任务 11：`FakeClock` 推进 13 个月 / 4 个月、`retainUntil` 延后与不缩短、清理后读取 `missing`、特征行不被删、分块中途退出可重跑、`retainUntil` 的契约测试（fake D 的调用序列）。
- 每日调度点放在任务 12 的 `signals run` 里；任务 11 只交付函数与 `signals retention --once` 所需的入口。

## 6. 约定与易踩的坑（本轮踩过的）

**代码与设计约定**

- **只有 `facts.ts` 可以引用 A 域的表**（具名 import、`import *`、裸 SQL 的 `FROM/JOIN` 都会被护栏抓到）。需要新的 A 域读取，加成 `facts` 的函数，不要放宽护栏。对 A 域**代码模块**（`projection`、`media-archive` 等）的 import 不设限。
- **`scoring/matcher-client.ts` 是 signals 里唯一允许 `fetch` 的文件**；signals 里不得出现模型 SDK 或模型域名；也不得 import `provider-adapter`、`orchestrator`、`raw-capture` 的网关部分（类型 import 和 `raw-capture/ports`、`raw-capture/oss-store` 除外）。
- **网络 IO 期间不持有数据库事务**。任务 runner 的模式是：领取（短事务）→ 事务外调用 → `fenced()` 短事务写结果。
- 成本与并发类数值**不写代码默认值**；所有 BIGINT 在 JSON / CLI 输出为十进制字符串；业务代码里不出现角色名；外部 ID 当文本。
- `composeState` 是纯函数，状态判断集中在 `compose.ts`；读取口不得建任务、不得调用网关或能力服务（`activeModel` 是配置查询，允许）。
- 改能力版本的方法（测试里模拟“升级”）：临时改 `CAPABILITY_VERSIONS` 表（必要时往 `NORMALIZERS` 注册新实现），`try/finally` 恢复。参考 `recompute.db.test.ts`。

**测试**

- **signals 下的 `*.db.test.ts` 不得出现 `Promise.all`**（护栏 ③）——连只读的并发也不行，用顺序 `for` 循环。本轮就被它拦过一次。
- db 测试每个用例前自动 `resetData`；**同一个用例里要多次重建“世界”时，中间手动 `resetData(t.pool)`**（`createWorld` 会建计划 1，重复创建会 `segment_exists`）。
- `FakeClock` 在模块级共享时状态会跨用例累积，断言时间用相对值。
- 一次写入同时违反多条 CHECK，MySQL 只报告其中一条；MySQL 的 CHECK 遇到 NULL 会放行。
- 做完一个任务的关键断言后，**做变异检查**（把实现改坏，确认对应用例失败，再恢复）。本轮每个任务都做了，别省。
- 默认测试离线：`FakeObjectStore`、`FakeClock`、`FakeMatcher`、`FakeAiGateway`；`network-deny` 在挂具里。
- 测试挂具速查：`tests/harness/signals-world.ts` 的 `createWorld(t, {gateway?, matcher?, cfg?, chunkSize?})`、`makeSubject`（封面主体）、`makeAudioSubject`、`drain`；`tests/harness/signals.ts` 的 `seedContent`、`addSnapshot`、`setCurrent`、`insertComment`、`insertFeature`、`insertSegment`、`insertMediaReference`、`insertAvailableAsset`、`QueryCounter`（断言“零查询 / 查询次数为常数”）。
