## 走查要点
1. **入口**：判定计划页只新增「全量明细」按钮（D 已实现页面里加）；没有已完成执行的计划也能点进去，看到空态且不能导出。
2. **视频明细**：21 个固定列（表头逐字按你给的）+ 青色表头的能力列；点「跳到能力列」直达。封面可点击放大。
3. **能力列规则**：`品牌词`（别名）、`文本关键词`（无别名的默认名）、`话题 #1` / `话题 #2`（重名加序号）、`整图对比` 类默认名；图片类单元格显示**分数**；没被选中或被更早层挡住的显示「前置条件未满足，不进行计算」；获取失败显示原因码。
4. **账号维度**：19 个固定列 + 每个条件一列（含头像、主页背景）+ 判定结果；能力列只有四个值。看「各能力列都通过、判定结果仍不通过」：切到执行 v1（N=1）的账号维度，找专员「马超」。
5. **历史执行**：右上「执行」下拉。v2：旧执行，账号能力列为空 + 提示；v1：内容明细已过保留期，视频明细不可用、账号维度可用。
6. **导出**：点「导出 Excel」看将导出的 sheet、表头、行数与文件名；左下「原型控制」里「模拟导出超限」可看 `export_row_limit` 的样子。导出不含图片。
7. **角色**：左下「原型控制」切换。分公司人员只见北京分公司；**门店专员只见本人、没有导出按钮**；门店专员的导航里临时放了一个「全量明细」入口（D 的页面门店看不到，设计上这个入口待定，见 requirements U6）。
8. **状态**：「原型控制」里切换加载 / 空 / 无权限 / 错误 / 处理中。
## 深链接（原型专用）
`#/reports/jp1?tab=accounts&role=branch_manager&state=empty`；`#/reports/jp1/e2`（旧执行）、`#/reports/jp1/e1`（已清理）、`#/reports/jp2`（无执行）；`?modal=export` 直接打开导出弹窗。
## 数据说明
全部虚构（组织、专员、标题、数字）。结果不是写死的：用一个小的确定性生成器，按 requirements EL-4 / EL-6 的规则现算三层结果与账号能力四态，所以原型里的现象就是规则本身的后果；换一次执行（不同的数量 N、不同的条件集合）结果会随之变化。
