## 一、这个域管什么

### 1.1 四个问题

```
什么算命中     → 用哪些条件组合来判断一条内容或一个账号
先判哪些       → 把几千条缩到值得细看的一小部分
怎么判         → 便宜的先用，贵的只用在收敛后的小范围
算得对不对     → 证据、试运行、版本、重算
```

### 1.2 不管什么

| 事情 | 归谁 |
|---|---|
| 内容、账号、评论、媒资怎么采 | A 数据底座 |
| 从内容里抽信号、做比对与理解 | C 识别能力 |
| 指标口径、聚合、报表与导出文件 | E 指标与看板 |
| 谁能配规则、谁能发布 | B 访问控制 |
| 活动怎么建、任务怎么下发 | F 业务应用 |
| 模型调用成本上限 | I 运维与成本 |

### 1.3 一条主线

```
业务建活动 → 配公共条件（时间、平台、形态、板块、范围）
→ 第 1 层：用免费条件圈出候选
→ 第 2 层：上传标准图，对候选做素材比对
→ 第 3 层：对剩下的小集合做内容理解与综合判断
→ 试运行看证据与费用 → 发布 → 产出判定
```

**D 的职责是"把业务标准变成可执行、可解释、可重算的判定"，不创造事实、不实现识别。**

### 1.4 判定结果只有三种

2026-10-28 决策（刘学奎）：素材没拿到时**不等待、也不判不达标**，直接记为「未获取成功」。业务看到的结果只有三种：

| 结果 | 含义 | 计入完成率 |
|---|---|---|
| **成功** | 判定完成且符合标准 | ✅ 计入 |
| **不达标** | 判定完成但不符合标准 | ✅ 计入（作为未完成） |
| **未获取成功** | 依赖的数据或素材没拿到，无法判定 | ❌ 不计入不达标，单独统计 |

**「未获取成功」不是失败，也不是不达标。** 它表示"这条我们不知道"，必须能在报表里单独看到数量与原因（图片没下载到、评论拿不到、账号不可访问等）。

**完成率的分母口径**（2026-11-03 修订）：分两层——分项完成率的分母是**到达该层的专员数**，计划总完成率的分母是**参与专员数**（见 §2.0.2）。未获取成功的对象/专员计入所在分母、不计入分子，报表同时单独列出其数量。

**判定单位是专员**：一个专员的多个内容 / 评论先按考核项的内容级条件与专员级达标方式聚合，再合成计划总结果；内容级明细仍保留用于下钻。

技术实现上仍保留更细的内部状态（等待依赖、技术失败、结构不适用、stale），但**业务展示与统计只按成功 / 不达标 / 未获取成功三种归并**：

- 等待依赖、技术失败、结构不适用 → **未获取成功**；
- 明确判定为不符合，或专员没有任何参与范围内的内容 → **不达标**；
- C 的 stale 旧值被使用时，结果仍按成功 / 不达标，另带 `stale` 标记，不并入未获取成功。

> 这条同时约束了 §2.3 的素材缺失处理：不设"等待到活动结束"或"超期判不达标"的策略，拿到就判，拿不到就记「未获取成功」。

## 二、三层向导

### 2.0 监控判定计划

**这是 D 域的核心业务对象**（2026-10-30 定名，承接 2026-10-28 的「活动规则判定计划」；下文简称判定计划）：业务人员为一个活动计划建立一个或多个「监控判定计划」，每个计划是一条从监控到出结果的完整链路。

名字里的两段分属两个域，共用一个计划 ID 与版本号：

| 段 | 内容 | 归属 |
|---|---|---|
| **监控段** | 信号集合、标准图 / 元素图 | C 识别能力 |
| **判定段** | 三层条件、阈值、层间组合、达标定义 | D 规则与考核 |
| 生命周期与执行 | 状态、版本、名单快照、执行与证据 | D 规则与考核 |

C 与 D 各持一张 1:1 的记录，通过计划 ID 关联；删除级联一致。**C 不写判定段，D 不写监控段。**

```
活动计划（A 域：总部创建、分公司提报名单）
        ↓ 引用
监控判定计划（1..n）
  ├─ 第 1 页 · 圈定
  ├─ 第 2 页 · 比对
  └─ 第 3 页 · 理解与执行
```

**参与范围的前置条件**：D 不自己维护参与范围，**引用 A 域「活动计划」的监控清单**（见 A 域 PRD 第十一章）。活动计划由总部或超管按品牌创建，参与分公司导入门店监控信息后形成名单；监控判定计划只引用其 ID，不复制名单。

**计划版本与选择规则**（2026-11-03 修订）：活动计划本身**不版本化**，只有状态；每个活动计划下可建 **1..n 个监控判定计划**，**版本挂在该计划上**（监控段与判定段共用一个版本号；**只有配置变更并发布才产生新版本**；能力升级与重算不升版，见 C-D03 / C-D04 / D-D08；旧版本结果保留可查）。选择活动计划建监控判定计划时，**只能选本人创建的**（超级管理员可选全部）；分公司即使加入了活动计划，也不能建。

**按需采集由监控判定计划触发**（2026-10-30 决策，见 `prd-platform.md` §6.11）：第 2/3 层需要的视频详情、视频源与评论由本计划向 A 提出需求；A 先判断本轮是否已有该视频的详情或该内容的评论，有则复用、不重复抓取。计划只提需求，采集执行与幂等由 A 负责。

**活动计划的状态如何影响判定数据**（2026-10-29 决策）：

| 活动计划状态 | 判定计划与结果 |
|---|---|
| 采集中 | 正常，可新建、可触发 |
| 暂停 / 归档 | **保留**，可随时转回采集中；归档期间**只能触发已有判定计划，不能新建** |
| 删除 | **一并删除，先进回收站保留 30 天**，期满物理删除；删除弹窗必须写明「下面有 N 个判定计划、共 M 条结果将被删除」 |

**删除前必须检查在途执行**（2026-10-29 决策）：有判定正在执行时不允许删除，提示「有 N 个判定正在执行，请等待完成或先取消」。否则会出现执行到一半、活动计划已消失、结果无法落库。

底层采集数据在任何情况下都不受影响，仍由 A 长期保留。

### 2.0.1 三页阻塞式流程

**第 1 页 · 圈定**

1. 引用所属活动计划的监控清单；
2. 配置条件：时间窗、内容形态、标题/正文关键词、话题标签、视频时长；
3. 点击确认 → **同步运算**，返回圈定条数；
4. 弹窗提供 CSV / Excel 下载，业务可查看圈定结果；文件统一由 E6 导出中心生成（D-D09）；
5. 再次确认 → 进入第 2 页。

**第 2 页 · 比对**

1. 选择做法（图片相同 / 图片含元素；图片含文字 2.0），再选择对象类型（头像 / 封面 / 主页背景）；
2. 每个图像对象上传一张标准图；元素图按元素条件各一张（D-D16）；
3. 点击确认 → **试跑**（对到达本层的专员内容执行比对），返回连续 0–10 分分布与 11 档样例；
4. 业务看样例调整阈值与专员级达标方式，可反复试跑；
5. 确认 → 进入第 3 页。

**第 3 页 · 理解与执行**

1. 1.0 只开放**音频理解（ASR + 大模型）**与**评论考核项**；图片理解、视频理解 2.0（D-D10 / D-D12）；
2. 在**表单**里填一段自然语言标准（如「口播要提到海信并与活动主题相关」）；C 用固定提示词 + 该标准 + 模型版本判定，不做多轮对话（D-D11）；
3. 每计划最多一个 ASR 考核项；确认 → **异步全量执行**；
4. 全部完成后消息提示，可下载结果（文件由 E 域导出中心生成，见下方「结果下载」）。

**第 2、3 层可以空着**（2026-10-29 决策）：很多考核只看关键词与时间，不需要看图或听声音。三页结构保留，但第 2、3 页允许空配置直接确认——空配置等于没有这一层，不破坏流程。

第 1 层必填，否则退化成全量判定。

**结果下载**（2026-10-29 决策）：一个 Excel，三个 sheet。

| Sheet | 内容 |
|---|---|
| 汇总 | 按专员 / 门店的达标与未达标数量、未获取成功数量 |
| 明细 | 每条内容一行，含判定结果、命中的条件与值、证据 |
| 未获取成功 | 单独列，含原因（素材未归档、评论拿不到、链接无效等） |

**文件由 E 域导出中心（E6）生成，D 不自己产出文件**（2026-10-29 决策，决策人刘学奎；对应 E 域 PRD 的 E-D04）：D 负责给出判定结果、参与名单、命中条件与证据；文件渲染、封面嵌图、私有存储、签名下载与导出的三次范围复查由 E6 统一执行。D 的页面保留「下载结果」入口，点击后调用 E6。

这样页面、看板与导出读同一份投影，不会出现两套口径、两套异步任务与两套权限复查。

> 这条推翻了本节此前「结果下载由判定模块自己产出」的写法。

**执行失败只重跑失败子集**（2026-10-29 决策）：判定按内容粒度落库，成功的保留，只重试失败的部分；重试次数与间隔由 I 域配额控制，不无限重试。

**活动计划跨年不限制**（2026-10-29 决策）：一个计划可以长期运行，按创建时间归属年份；期间名单变化由「执行时锁名单 + 保存快照」兜住，不同批次结果各自可比较。

**状态流转**：

```text
草稿 → 已圈定 → 已比对 → 执行中 → 已完成
```

- 步骤是**阻塞式**的：前一步未确认，不能进入下一步；
- **每次只回退一层**：第 3 页只能回退到第 2 页，第 2 页只能回退到第 1 页，不能跳层；
- **回退必须弹窗确认**，说明哪些结果会被删除；回退直接删除后续步骤已产生的结果，**不保留历史版本**（2026-10-30 决策）；
- 第 2 页回退到第 1 页：圈定结果重跑；
- 第 3 页回退到第 2 页：**已获取的视频与评论数据不重复抓取**——A 域先判断本轮是否已有该视频的详情或该内容的评论，有则直接调用，没有才发起采集（2026-10-28 决策）；
- 标准图或元素图变更后，旧结果不再复用；重算由业务在配置或执行时触发，不后台自动重跑历史；
- **C 的能力升级不改写已保存判定，也不自动重算历史计划**；新执行使用当前能力版本（C 域 §7.1）；
- **执行期间名单锁定**（2026-10-28 决策）：异步执行开始时固定参与名单，运行中不允许修改本计划的名单；**其他活动计划的名单变化不影响本次执行**；
- **移出的账号不参与执行**（2026-10-29 决策）：判定按执行时锁定的名单算；移出前的历史内容与评论保留，但不进入本次结果，也不触发重采；
- **按执行时的归属算**（2026-10-29 决策）：账号改绑后，**新执行**的判定按当前归属算到新门店；**已保存的历史判定结果不因改绑而改写**。同一批内容重算前后可能归属不同，这是预期行为，不是 bug；
- **执行记录必须保存所用名单快照**，否则移出前后两次结果无法比较；
- **判定不自动跑**（2026-10-29 决策）：没有定时任务，全部由业务人员主动触发；活动归档期间同样可以手动触发；
- 计划版本只由**配置变更并发布**产生；同一版本的执行、重算、试跑不升版；**重算**的旧版本结果保留可查，**回退**则直接删除（D-D08）；

### 2.0.2 考核项与完成率模型（2026-11-03）

**对象类型**：内容 / 评论 / 账号。内容与评论级考核项按专员聚合；账号级直接判定。

**一个考核项 = 内容级条件 + 专员级达标方式**：

- 内容级条件：哪些内容 / 评论 / 账号算"符合"（如话题含 `#618`、评论正文含某词、封面分数 ≥ 8）；
- 专员级达标方式：

| 达标方式 | 判定 | 适用对象 |
|---|---|---|
| 至少 N 条 | 符合条件条数 ≥ N | 内容 / 评论 |
| 全部通过 | 全部符合 | 内容 / 评论 |
| 任一条通过 | 至少 1 条符合 | 内容 / 评论 |
| 比例阈值 | 符合条数 ÷ 参与条数 ≥ X% | 内容 / 评论 |
| 账号级直接判定 | 账号的匹配分 ≥ 阈值 | 账号 |

**三层按专员推进**：同层所有考核项**全部通过**，才进入下一层；层间 AND。第 1 层（文本 / 事实）、第 2 层（模板 / 元素匹配）、第 3 层（1.0 只有音频 ASR + 大模型判定与评论项；图片 / 视频理解 2.0）。

**分母口径**：

- 分项完成率 = 通过该考核项的专员数 ÷ **到达该层的专员数**；
- 计划总完成率 = 通过计划的专员数 ÷ **参与专员数**；
- "到达该层" = 通过前面所有层全部考核项的专员。

**三值阈值**（部分内容未获取成功）：

- 至少 N 条：已知通过 ≥ N → 成功；已知通过 + 未获取 < N → 不达标；否则未获取成功；
- 全部通过：任一不达标 → 不达标；否则任一未获取 → 未获取成功；否则成功；
- 任一条通过：任一通过 → 成功；否则任一未获取 → 未获取成功；否则不达标；
- 比例阈值：把 N 换成比例，按同样三值逻辑判断；
- 账号级直接判定：分数 ≥ 阈值 → 成功；缺素材 → 未获取成功；否则不达标。

**边界**：

- 空层视为通过：某一层没有配置任何考核项，就当作没有这一层的额外要求；
- 未到达的层不参与计划总结果合成；
- 零内容专员对**任何内容级达标方式都判不达标**，"全部通过"也不例外（否则空集会被误判为通过）；
- 至少 N 条要求 N ≥ 1；比例阈值要求 X > 0。

**计划总结果**：各考核项三值 AND，**不达标优先**：

```text
任一考核项不达标     → 不达标
否则任一未获取成功   → 未获取成功
否则                 → 成功
```

**零内容**：专员没有任何参与范围内的内容 → 内容级考核项**不达标**，不是未获取成功（D-D14）。

**stale**：C 的旧值默认可用；D 的结果带 `stale` 标记，不改变成功/不达标/未获取成功三态（D-D13）。

**组合项**：同一文本条件内部多个值可选全含 / 任一；只用于文本（关键词、话题、ASR 转写文本）；**不做跨考核项组合**（D-D07）。

**分项结果与 E**：D 保存每个考核项的结果；E 是否在计划组下出分项列，由 E 决定。计划总结果保持 E 现有的四个指标。

### 2.1 为什么是三层

| 层 | 成本 | 候选规模 | 业务心智 |
|---|---|---|---|
| 第 1 层 基础筛选 | 0 档，免费 | 千级 | 先圈出相关的 |
| 第 2 层 素材比对 | 1 档，免费 | 百级 | 再看素材对不对 |
| 第 3 层 内容理解 | 2–3 档；1.0 只开放 ASR + 大模型（付费）与评论，图片 / 视频 2.0 | 十级 | 最后看内容说了什么 |

层间只支持 AND；同层多个考核项也 AND，全部通过才进入下一层。层内的 OR 只存在于同一文本条件内部多个值之间（全含 / 任一），不跨考核项组合。跨层 OR 不支持；需要"文案命中或画面命中"时，只能配成两个独立考核项，各自出完成率，不合成一个"或"的结论（D-D07）。

### 2.2 第 1 层 · 基础筛选

**目的**：用零成本条件把活动范围内的全部内容，缩到值得继续看的一批。

**允许的条件**（每行是一个考核项的内容级条件；同一层多个考核项 AND）：

| 条件 | 来源 |
|---|---|
| 参与范围 | **活动计划的监控清单**（A 域，本页只读展示） |
| 时间窗 | 计划级 |
| 内容形态（视频 / 图文 / 未知） | 计划级 |
| 标题 / 正文关键词（全含 / 任一） | 考核项 |
| 话题标签（全含 / 任一） | 考核项 |
| 视频时长区间 | 考核项 |

> 文本类条件内部多个值可选**全含 / 任一**（组合项）；这是同一考核项的条件组合，不是跨考核项组合（D-D07）。

**数据边界（原则）**：第 1 层只使用**一次同步中已经拿到的列表与主页字段**，不触发详情接口、不触发评论接口、不读图、不调任何外部服务。

- **播放量永远不在第 1 层**：播放数只在详情接口返回，取它会带来额外的接口调用与成本；
- 同理，评论正文也不在第 1 层；
- 这条边界让第 1 层可以反复试跑而不产生任何费用。

**2026-10-28 明确不做**（决策人刘学奎）：

| 不做 | 原因 |
|---|---|
| 否定条件（"不含某词 / 不含某话题"） | 业务当前不需要 |
| 只看本人发布 / 包含共创作品 | 业务当前不需要 |
| 播放量等任何依赖详情接口的条件 | 成本上升，见上 |
| 发布时段（星期几、几点到几点） | 没有这么严苛的需求 |
| 置顶内容处理 | 已由 A 域实现，不属于第 1 层 |
| 关键词输入方式、字段选择用业务语言、考核项范围收窄校验、话题归一化提示 | 属于界面细节，后续单独设计 UI |
| 实时命中预估 | 没有实现价值 |

### 2.3 第 2 层 · 素材比对

**目的**：判断素材本身是否符合活动要求。

**三个业务能力**（不区分主页背景 / 头像 / 封面 / 图文图片，使用时选择对哪个对象做比对）：

| 业务问法 | 输入 | 技术手段 | 成本档 | 1.0 |
|---|---|---|---|---|
| 这张图和标准图是不是同一张 | 标准图 | 特征匹配（pHash 预筛 + SIFT / ORB 精匹配） | 1 | ✅ |
| 图里有没有这张元素图 | 元素图 | 局部特征匹配（SIFT / ORB + 单应性校验） | 1 | ✅ |
| 图里有没有某些字 | 要求出现的文字 | OCR + 字符串匹配 | 2 | ❌ 2.0 |

> **不做类别识别**（2026-10-28 决策）：业务说"要有空调外机"时一定有一张具体的外机图，走元素图匹配即可，不需要视觉大模型。
>
> **三种做法统一输出连续 0.0–10.0 分**；11 个整数档只用于界面选阈值与展示样例，不改变存储与比较精度（C-D08）；只有前两种是本地算法免费，文字识别需要外部调用。

**标准图与阈值**：

- **每个监控判定计划、每个图像对象各一张标准图**（封面 / 背景 / 头像最多三张）；同一对象不做多标准图组；多个计划可以引用同一张图，C 按图片指纹共享结果（D-D16 / C-D01）；
- **模板匹配项每对象最多一个**；元素图匹配项按元素条件多张；图片含文字 2.0；
- 业务进入第 2 层时上传标准图（或元素图），后台对该计划**到达本层的专员内容**执行比对，不等到规则发布；
- **元素图同样要试比对**：上传后先拿圈定范围内的样本跑一遍，看能不能找到、找到多少，避免业务拿一张实际画面里不会出现的图去配规则；
- 分值**连续 0.0–10.0**；11 个整数档只用于界面选阈值与展示样例，存储与规则比较用连续值（C-D08）；
- 阈值属于判定段，随监控判定计划版本冻结；标准图 / 元素图属于监控段（C 管理），变更**产生新版本**；旧结果不复用，重算由业务显式触发（D-D08 / C-D04）。

**标准图与元素图的存储**（2026-10-28 决策，2026-11-03 修订）：

- 由 C 管理（监控段），存 OSS，按 `监控判定计划 ID + 版本 + 图像对象 + 图片 SHA-256` 定位；D 只引用，不写图（C-D02）；
- 旧版本不覆盖：换图产生新版本，旧结果仍可解释；
- 计划回退到某一版时，引用该版的标准图，不重新上传。

**素材缺失**（2026-10-28 决策）：本轮素材未归档、下载失败或只有 `carried_forward` 时，该对象**不参与比对**，判定结果记「未获取成功」（§1.4）。未获取成功的对象**仍计入完成率分母**，只是不计入分子。界面点出数量与原因（如"137 条中 12 条未获取成功"）。不设"等到活动结束"或"超期判不达标"的策略。

**按平台自动禁用**：小红书主页接口不返回头像与背景，选择小红书范围时这两个对象直接不可选，避免业务配出永远不命中的条件。

**2026-10-28 明确不做**：

| 不做 | 原因 |
|---|---|
| 同一图像对象的多标准图组 | 每个图像对象一张；按对象各一张，避免参数与缓存复杂化（D-D16） |
| 图文图片、视频首帧作为比对对象 | 当前不存在该场景 |

### 2.4 第 3 层 · 内容理解

**目的**：在已经收敛的小集合上，看懂画面与声音，并做综合判断。

**能力与 1.0 范围**：

| 类型 | 输入 | 处理 | 输出 | 1.0 |
|---|---|---|---|---|
| 音频理解 | 视频音轨 | ASR + 固定提示词 + 表单标准 → 大模型判定 | 转写文本 + 结构化判定（结论、理由、模型 / 提示词版本） | ✅ |
| 图片理解 | 封面、主页背景、图文图片 | 视觉大模型 + 系统提示词 | 标准化结构化描述 | ❌ 2.0 |
| 视频理解 | 视频（关键帧或整段） | 视觉大模型 + 系统提示词 | 标准化结构化描述 | ❌ 2.0 |

**工作方式（1.0）**：

1. 音轨先 ASR 得到转写文本；转写文本是全局信号，所有 ASR 项共享；
2. 业务在**表单**里填一段自然语言标准（如"口播要提到海信并与活动主题相关"）；C 用固定提示词 + 该标准 + 模型版本判定，产出结构化判定（结论、理由、模型版本、提示词版本）；**不做多轮对话**（D-D11）；
3. **每计划最多一个 ASR 考核项**；判定结果按「标准文本 + 提示词版本 + 模型版本」参数化，不与其他计划 / 标准混用（D-D10）；
4. 图片 / 视频理解与多轮对话 2.0；第 3 页还包含**评论考核项**，只对通过前两层的内容采集评论（D-D12）；
5. ASR 与大模型能力必须 smoke 验证后启用；未验证时第 3 层 disabled（D-D15）。

**表现类与刷流量判定也在这一层**（2026-10-28 决策）：

- 互动相对账号基线的比较、刷评刷表情、疑似投流，都不放在第 1 层做全量检测；
- 走到第 3 层的内容已经是少数，此时播放量、评论内容、发布内容都已清楚，可以设标准化规则，也可以由大模型判定；
- 基线口径（窗口、倍数、新账号样本不足怎么处理）仍需单独设计。

**2026-10-28 明确不做**：

| 不做 | 原因 |
|---|---|
| 第 1 层做表现类全量检测 | 逻辑复杂，需要综合信息，放在第 3 层 |
| 业务自由配抽帧数量 | 成本不可控，按固定策略抽帧 |

### 2.5 判定结果的落点（做法 B）

2026-10-28 决策（刘学奎）：**判定结果落成信号，D 只读结果。**

```text
配置期：业务在表单填标准        →  产出计划版本（标准 = 一段文字 + 提示词版本）
判定期：C 执行 ASR + 大模型判定   →  结果落库（判定 + 理由 + 模型/提示词版本）
        D 读结果做组合与达标     →  不再调用大模型
```

**为什么不能每次判定都调大模型**：

- 同一条内容重算两次可能结论不同，无法复现；
- 客户质疑时无法解释"上次为什么判不达标"；
- 每次重算都产生费用，成本不可控。

**判定结果必须带四样东西**：结论、理由、模型版本、提示词版本。缺一样就无法复核。

**配置期与判定期必须分开**：1.0 的标准是表单里的一段文字，不经过多轮对话；2.0 再提供对话配置。对话 / 配置只发生在业务定标准的时候（第 3 页），不在每次执行的时候。否则同一条内容每跑一次都可能换一个结论。

**判定信号不等于考核达标**：C 在第 3 层产出的 `*.judgement` 是「这条内容是否符合某个标准」的判据信号，带结论、理由、模型版本与提示词版本；是否达标由 D 组合多个信号后决定。分工细则见 C 域 PRD §11.1。

### 2.6 评论对象（进 1.0）

2026-10-28 决策（刘学奎）：评论作为 D 的判定对象，**进 1.0**。

**层位**（D-D12）：评论考核项放**第 3 层**；只对通过第 1、2 层的内容按需采集评论，A 负责采集与幂等、多计划共享。

| 判定粒度 | 可判定的内容 | 依赖 |
|---|---|---|
| 单条评论 | 评论正文是否含指定词、作者是否为指定账号 | 评论正文、作者 ID |
| 一条内容下的评论集合 | ~~重复率、表情占比、同作者集中度~~ **1.0 不产出（搁置）** | 评论聚合信号（C 域已搁置） |

**前提**：评论作者的平台 ID 与 `external_accounts` 的账号 ID 是否同命名空间尚未验证（见 A→C 供数说明）。未验证前，"作者是否为指定账号"这类条件必须保持禁用。

## 四、搁置项

以下不是"不做"，是**暂不设计**。2026-10-28 决策（刘学奎）：刷流量相关先全部搁置，等业务后续提出。

| 疑似投流的判定方式与校准样本 | 业务先搁置 |
| 互动基线的窗口、倍数、新账号样本不足的处理 | 属于表现类，随刷流量一起搁置 |

> 第 3 层仍然保留"表现类判定"的位置，只是这三项的具体标准暂不定。
>
> **"互动基线"指什么**：判断某条内容是否异常，需要拿它和这个账号自己的常态比。三个参数未定——**窗口**（用近期多少条或多少天算常态）、**倍数**（超过几倍算异常）、**新账号样本不足**（只有两三条内容时，均值/中位数不具代表性，是放弃判定还是放宽）。这三项都随刷流量一起搁置。

## 六、验收标准

用业务人员照着就能判断真假的语言写。`[自动]` 可由测试脚本验证，`[手工]` 需要人在界面上操作确认。

### 第 1 层

- [ ] `[自动]` 只配第 1 层条件时，试运行不产生任何外部接口调用
- [ ] `[自动]` 播放量、评论正文不能作为第 1 层条件
- [ ] `[自动]` 话题 / 关键词多值可选全含或任一；全含时少一个不通过，任一时任一个通过
- [ ] `[自动]` 非文本条件（时间、时长、图片）不提供多值组合
- [ ] `[手工]` 业务能在一个考核项里配出"时间 + 话题 + 标题关键词"并看到圈定条数
- [ ] `[自动]` 同一层多个考核项全部通过才进入第 2 层；任一不通过，该专员不进入下一层

### 第 2 层

- [ ] `[手工]` 上传标准图后，系统对到达本层的专员内容全量比对并给出连续 0–10 分分布
- [ ] `[自动]` 同一图像对象只能配一张标准图；模板项每对象最多一个
- [ ] `[自动]` 元素图按元素条件多张；换元素图后旧结果不复用
- [ ] `[自动]` 匹配结果返回连续得分与版本，不返回"匹配 / 不匹配"
- [ ] `[自动]` 小红书范围下头像、背景不可选
- [ ] `[自动]` 素材未归档的对象按三值阈值处理：通过数 + 未获取数 < N 时记不达标，否则记未获取成功

### 第 3 层

- [ ] `[自动]` 1.0 只开放音频 ASR + 大模型判定与评论项；图片 / 视频理解不可选
- [ ] `[自动]` 表单填标准后，C 用固定提示词 + 标准 + 模型版本判定，产出结论 / 理由 / 模型版本 / 提示词版本
- [ ] `[自动]` 每计划最多一个 ASR 考核项；第二个被拒绝
- [ ] `[自动]` ASR 转写文本全局共享；判定结果按「标准 + 提示词版本 + 模型版本」参数化，不同标准不互相复用
- [ ] `[自动]` ASR / 大模型 capability 未验证时，第 3 层不可执行，记未获取成功 / 不支持，不发起付费调用
- [ ] `[自动]` 评论考核项只对通过前两层的内容采集评论
- [ ] `[自动]` 评论作者 ID 对齐验证通过前，「作者是否为指定账号」保持禁用

### 专员级判定与完成率

- [ ] `[自动]` 至少 N 条：6 条通过、N=5 → 成功；4 条通过 → 不达标
- [ ] `[自动]` 全部通过：任一不通过 → 不达标；有未获取成功但无不通过 → 未获取成功
- [ ] `[自动]` 任一条通过：任一条通过 → 成功；无通过但有未获取 → 未获取成功；否则不达标
- [ ] `[自动]` 比例阈值：按三值逻辑判断
- [ ] `[自动]` 账号级项直接按匹配分阈值判定
- [ ] `[自动]` 零内容专员的内容级项判不达标，不是未获取成功
- [ ] `[自动]` 分项完成率分母 = 到达该层的专员数；计划总完成率分母 = 参与专员数
- [ ] `[自动]` 计划总结果三值 AND，不达标优先于未获取成功
- [ ] `[自动]` stale 旧值使用时结果带 stale 标记，仍可成功 / 不达标

### 计划流程与版本

- [ ] `[自动]` 配置变更并发布产生新版本；同一版本重复执行 / 重算 / 试跑不升版
- [ ] `[自动]` 回退一层删除后续结果，不保留旧版本
- [ ] `[自动]` 执行期间名单锁定；移出账号不参与本次执行
- [ ] `[自动]` 按执行时归属算，历史结果不因改绑改写
- [ ] `[自动]` 删除活动计划，判定计划与结果进回收站 30 天，期满物理删除
- [ ] `[自动]` 有在途执行时不能删除，提示等待或取消
- [ ] `[自动]` 第 1 页圈定结果下载与最终结果下载都走 E6
- [ ] `[自动]` 结果文件包含汇总、明细、未获取成功三个 sheet

### 评论对象

- [ ] `[自动]` 评论可按正文关键词判定
- [ ] `[自动]` 评论作者 ID 对齐验证通过前，「作者是否为指定账号」保持禁用
