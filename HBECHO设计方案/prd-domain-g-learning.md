## 一、这个域管什么

### 1.1 四个问题

1. **谁能上传课程？** 上传后谁能看到？跨品牌的课程由谁建？
2. **学员在哪里看课？** 看到的是本品牌还是全部？看一半退出后怎么继续？
3. **系统记住什么？** 记了以后总部能回答什么问题，回答不了什么问题？
4. **撤权、离职、下架之后**，已有的学习记录怎么办？

### 1.2 不管什么

- **不出题、不考试、不打分、不积分、不排名、不下发学习任务**。G3–G7 全部不在 1.0，见总 PRD §7.1 与 §7.3。
- **不定义"学完"**。1.0 只有进度事实，没有完成状态（G-D02）。
- **不复制 A 域的账号与媒资**。课程视频与资料是平台自有素材，不进 A 域的 `MediaAsset`，不参与采集媒资的 SHA-256 判同与保留规则；A 域也不得读取课程素材充当采集结果。
- **不按组织层级下发**。可见性只有**品牌 × 人员级别**两个维度，没有"某分公司的必修课"；分公司不可见汇总，也不能定向发课（G-D03、G-D06、G-D40）。
- **不做防刷、防盗录、版权水印**。这些只在积分与考核落地后才有意义；1.0 的进度数据只用于续播与总量，见 §6.6。
- **不承接 F 域的任务闭环**。F6 在 2.0；届时学习任务由 F6 编排、G 提供课程，不反向由 G 建任务体系。

### 1.3 一条主线

```text
总部上传一门课（视频或资料）
  → 填标题、选品牌（可含「全部品牌」）、打标签
  → 保存即发布
  → 学员在自己的品牌范围内看到
  → 播放视频或预览资料
  → 系统记录进度与续播位置
  → 总部看本品牌的累计总量
```

## 二、用户与场景

### 2.1 谁在用

| 角色 | 在 G 域做什么 | 依据 |
|---|---|---|
| `platform_admin` | 维护全部品牌的课程；创建「全部品牌」课程；看全部品牌汇总 | B 域 `learning.manage` |
| `hq_manager` | 维护**授权品牌**的课程；看授权品牌汇总 | B 域 `learning.manage`，品牌范围 |
| `branch_manager` | 看本品牌课程并学习；**看不到汇总** | B 域 `learning.read` |
| `store_staff` | 看本商店品牌的课程并学习；看自己的学习记录 | B 域 `learning.read` |

> 学习是四类角色共同的动作，不是经销商专属；`branch_manager` 也要能看课。B 域 §7.3 的 `learning.read` 已按此登记。

### 2.2 三条真实路径

1. **总部上传新产品培训课**：`hq_manager` 上传一段 20 分钟的视频，选「海信」「日立」两个品牌，打标签 `新品`、`导购话术`，保存。两个品牌的学员刷新课程列表即可看到，无需再点发布。
2. **门店专员看一半**：`store_staff` 在手机上看到第 8 分钟被叫走，关闭页面。第二天再进来，课程卡片显示"继续学习"，点开后从第 8 分钟附近接着播放。
3. **总部月底看总量**：`hq_manager` 打开学习汇总，看到授权品牌合计：课程 37 门、学习人数 1,842 人、累计观看 2,310 小时、累计播放 9,470 次。看不到是哪些人、哪个门店。

### 2.3 规模

- 学员规模：3,500+ 名 `store_staff`，加总部与分公司人员（总 PRD §2.3）。
- 课程规模：1.0 预计**数百门以内**，具体数量由业务给出；超过这个量级需要重新评估分类与检索。
- 并发：学习流量以浏览与短视频播放为主，不按高并发直播设计；准确容量待实测，不在本文冻结。
- 单文件上限：视频 2 GB / 60 分钟；资料 50 MB；封面 5 MB（G-D44）。

### 2.4 1.0 的边界

| 做 | 不做 |
|---|---|
| G1 课程与资料的上传、品牌与标签、替换、下架 | 草稿箱、审核流、定时发布、批量导入、多语言 |
| G2 目录、标签筛选、搜索、视频播放、资料预览、下载 | 多课节课程、收藏、问答、评论区、笔记 |
| 学习进度与续播位置 | 完成判定、证书、学分 |
| 总部总量汇总 | 按人/按店/按分公司/按课程的明细，完成率，排行榜 |

## 三、概念

### 3.1 课程（Course）

一门课 = **一个视频或一份资料**（G-D05），不是容器。字段只有：标题、类型（视频 / 资料）、品牌范围、标签、简介、封面（必填，视频与资料一样，G-D48）、文件、状态（已发布 / 已下架）。

不建"章节/小节"层。需要系列课时，业务建多门课并用同一个标签串联。

### 3.2 课程可见性 = 品牌范围 × 人员级别

课程的可见性由**两个正交维度**共同决定，两个都要满足：

**维度一：品牌范围**

- 只有两种形态，**互斥且都必须显式选择**：
  1. **指定品牌集合**：明确列出 N 个品牌（N ≥ 1）；
  2. **全部品牌**：一个独立标记，表示"现有及将来新增的所有品牌"。
- 两种形态都不是"空值 / 默认全部"：既没选任何品牌、也没勾「全部品牌」时，保存被拒绝。

**维度二：适用人员级别**（G-D40，2026-10-30）

| 档位 | 谁能看 | 典型内容 |
|---|---|---|
| `all` | 四类角色都能看 | 导购话术、产品知识、操作规范 |
| `branch_and_above` | 分公司及以上（`branch_manager` / `hq_manager` / `platform_admin`） | 区域管理、活动组织、本区数据分析 |
| `hq_and_above` | 总部及以上（`hq_manager` / `platform_admin`） | 总部分析方法、管理流程、内部策略 |

- 默认 `all`，创建时必须显式确认；
- 级别是**最低门槛**：`hq_and_above` 的课程对 `platform_admin` 同样可见；
- 级别与品牌**取交集**，不是二选一：一门「海信 × 分公司以上」的课，只有海信品牌的 `branch_manager` 及以上能看到。

- 学员能看到的课程 = 课程品牌范围 ∩ 本人品牌范围 ∩ 本人级别 ≥ 课程级别。本人品牌范围由 B 域 DataScope 给出（`store_staff` 取门店品牌，`hq_manager` 取授权品牌，`platform_admin` 为全部）；本人级别由 B 域的 `RoleCode` 映射，不另建职级字段。

> 这条防的是"没选品牌 = 大家都看得见"或"没选品牌 = 谁也看不见"的静默二义。「全部品牌」是一个真实的标记，不是"集合为空"或 null；四态不互转的纪律在这里同样适用。
>
> **「全部品牌」是动态的**（G-D15，2026-10-29）：勾选后，平台将来新增的品牌**自动**获得这门课，维护者不需要回来补选。品牌列表缓存 5 分钟（G-D39），因此新品牌最多延迟 5 分钟生效。
>
> 这个选择的代价必须让维护者看见：一门标了「全部品牌」的老课，会在新品牌上线的那一刻出现在该品牌所有学员的列表里。**内容只适合部分品牌时不要用「全部品牌」**，改用指定品牌集合；已经误用的，改回指定品牌或下架。
>
> 因此维护界面在勾选「全部品牌」时必须显示这句话，不能只放一个复选框。这是本文档对界面提出的唯一硬性文案要求。
>
> **品牌停用不影响课程可见性**（G-D26）：可见性只取决于课程品牌范围与学员本人的 grant，不检查品牌在 A 域是否停用。品牌停用通常伴随人员停用，grant 消失后自然看不到。

### 3.3 标签（Tag）

- ~~扁平、无层级、多对多~~（**由 G-D49 于 2026-11-16 修订**：两级——一级标签 + 二级标签，课程多对多引用二级标签；一级标签下可以没有二级标签，课程不要求每个一级标签都选）；**标签集合是预设的，由超管统一维护**（G-D16，2026-10-29）。总部人员只能从现有标签中选，不能新建、改名或删除。
- 1.0 的初始集合（可由超管增删）：`新品`、`产品知识`、`导购话术`、`操作规范`、`案例分享`、`活动政策`、`售后与服务`、`培训制度`、`品牌规范`。
- **每门课至少选一个标签**（G-D21，2026-10-29），否则保存拒绝。保证筛选永远有结果。
- 理由：自由建标签在几百门课之后必然出现同义词（`新品` / `新产品` / `新品推荐`），筛选随即失效；而标签的合并与重命名是不可逆的数据操作，1.0 没有能力承担。
- 1.0 的用途只有两个：课程列表上的展示与筛选（品牌、课程类型两个固定下拉，加每个一级标签一个下拉；每个下拉单选，不同下拉取「且」，G-D49），以及标题关键词搜索的补充。
- 迁移（G-D49）：旧标签按第一个 `-` 拆成「一级-二级」（如 `平台-抖音`），没有前缀的归入「未分类」；`tag_id` 与课程引用不变。二级标签名在本版暂时全局唯一，下一个发布再放开为「同一一级标签内唯一」。
- 标签不做权限：标签不构成可见性，不能用来给某个门店定向发课。

### 3.4 课程文件替换（不保留旧版本）

- 替换课程文件时**直接覆盖当前内容**，不保留旧文件、不建版本表（G-D10，2026-10-29）。
- **审计记录旧文件标识**、替换时间、操作者；旧文件本体在切换成功后删除（视频删除 VOD 中的旧资源，资料删除 OSS 旧对象），审计里的标识保留。
- 学员立即看到新内容；学习进度按**课程**记录，**不因替换清零**。
- 后果要说清楚：**无法回滚到旧文件**。替换错了只能再传一次；上传前由维护者自己确认内容。

### 3.5 学习进度（LearningProgress）

- 是"看到哪里、看了多久、什么时候看的"，**不是"是否学完"**（G-D02）。
- 一个 `User` 对一门课程只有一条当前进度；进度按课程聚合，不按底层文件分裂。

### 3.6 观看记录（ViewRecord）

- 视频播放期间由播放器按固定间隔上报心跳，累计为观看时长；暂停、退出、切后台都停止累计。
- 心跳不是审计，不做防刷判定；异常心跳只记录、不修正、不拦截（G-D02 的直接后果：1.0 没有任何奖励依赖这个数）。

### 3.7 汇总（LearningSummary）

- 只有**总量**（G-D03）：课程数、学习人数、累计观看时长、累计播放次数。
- 时间口径见 §7.3；1.0 不做时间范围筛选（G-D43）。

### 3.8 与 A 域媒资的区别

| | A 域 `MediaAsset` | G 域课程素材 |
|---|---|---|
| 来源 | 供应商采集（抖音/小红书/快手） | 总部人工上传 |
| 存储 | 私有 OSS `hbecho-media` | 视频进 VOD；资料与封面进私有 `hbecho-course` 桶（G-D17、G-D48） |
| 身份 | 完整字节 SHA-256 判同 | VOD VideoId / OSS object key |
| 保留 | 正式媒资长期 | 课程存续期间；替换后旧视频删除 |
| 访问 | 源对象 DataScope + 签名 URL | 课程品牌范围 + VOD 播放凭证 / OSS 签名 URL |
| 关系 | 互不引用 | 互不引用 |

课程素材不得复用 A 域的判同、carry-forward 或"临时 URL 不是身份"的处理逻辑；两者只是都属于私有存储的访问模式相同。

## 四、G1 · 学习内容管理

### 4.1 上传什么

| 类型 | 1.0 支持 | 说明 |
|---|---|---|
| 视频 | ✅ | **强制 MP4 / H.264 / AAC**（G-D33）；不符合在上传前拒绝。上传到 VOD 后按**转码模板组**自动转码，码率档位由模板组决定（G-D09，前置验证见 §10.1） |
| 图文资料 | ✅ | **仅 PDF 与 JPG/PNG**；在线预览，不做 Office（G-D12） |

**明确不做**：Word / PPT / Excel 等 Office 文档、压缩包、外部链接课程、直播、音频单独成课、多文件合集。

### 4.2 保存时必填的信息

| 字段 | 规则 |
|---|---|
| 标题 | 必填；同一品牌范围内允许重名，但列表要能凭标题与标签区分 |
| 类型 | 视频 / 资料；保存后不可改类型 |
| 品牌 | 至少一个；`platform_admin` 与 `hq_manager` 均可选「全部品牌」（见 §8.2） |
| 适用人员级别 | `all` / `branch_and_above` / `hq_and_above`，默认 `all`（G-D40） |
| 标签 | **至少一个**；只能从预设标签集合中选，不能新建（G-D16、G-D21） |
| 简介 | **必填**，纯文本（G-D22） |
| 封面 | **必填**，视频与资料一样（JPG/PNG 人工上传，≤ 5 MB）（G-D48，修订 G-D11） |
| 文件 | 必填；上传完成并校验通过后才算保存成功 |

### 4.3 上传即发布（G-D07）

- 保存成功即对品牌范围内的学员可见，**没有草稿态、没有待审态、没有定时发布**。
- 理由：1.0 的维护者是总部与超管两类可信角色，审核层没有第三方可审；增加草稿态只会制造"为什么学员看不到"的支持问题。
- 代价与对策：上传错了只能**替换或下架**，不能撤回成草稿；因此替换与下架必须一步可达（§4.4）。

### 4.4 替换、修改与下架

| 动作 | 规则 |
|---|---|
| 替换文件 | **直接覆盖**；旧文件删除、审计保留其标识；学员立即看到新内容；学习进度不清零；**不可回滚** |
| 修改标题 / 简介 / 标签 / 品牌 | 直接生效并记审计；品牌减少时，已不在范围内的学员**立即看不到**这门课，但历史进度不删除 |
| 下架 | 学员列表不再出现；已持有链接的访问被拒绝（不是空页面）；历史进度与观看记录保留。**「全部品牌」课程的下架是全局的**（G-D28），对所有品牌同时生效，不按品牌分别下架 |
| 重新上架 | 下架后 **30 天内**恢复可见，进度继续使用 |
| 自动归档 | **下架满 30 天**：删除视频/资料文件（存储真正释放），课程状态转为「已归档」（G-D37）。归档课程不可见、不可重新上架；进度、汇总与审计全部保留 |
| 删除 | 课程记录**仍不物理删除**。归档只是删除媒体文件，记录、进度与审计都在 |

### 4.5 谁能改哪门课

- `platform_admin`：全部课程，含「全部品牌」课程。
- `hq_manager`：可改**指定品牌完全落在自己授权品牌内**的课程，以及「全部品牌」课程；1.0 不区分「全部品牌」课程由谁创建。B v1.18 的 `learning.manage` 范围含「全部品牌」课程（G-D42）。
- 不能把课程改到超出自己的品牌范围：`hq_manager` 只能选自己授权品牌，或直接选「全部品牌」；**不能逐个勾选自己未授权的品牌**。这条保证「全部品牌」是一个明确的、可审计的整体动作，而不是绕开授权逐个加品牌。

### 4.6 明确不做

草稿箱、审核流、定时发布、批量上传、课程复制、多语言、版本历史与回滚（替换即覆盖）、课程评论与评分、Office 文档在线预览。

## 五、G2 · 学习中心

### 5.1 学员看到什么

- **课程列表**：只含本人品牌范围内、状态为已发布的课程；按最近更新排序；可按**单个标签**筛选（不做多标签组合）、按标题关键词搜索（子串匹配，与 C 域 `contains_any` 的朴素口径一致，不引入分词）；本人有进度的课程带「在学」标记（§5.5）。
- **课程详情**：标题、简介、标签、更新日期、**上传者姓名**（G-D29）；视频显示时长与续播位置，资料显示文件大小与类型（**不解析页数**）；
- **空结果**：品牌内确实没有课程时显示空状态；**无权限与无内容是两种不同结果**，不能都显示成"暂无课程"。

### 5.2 视频播放

- 视频通过 VOD 播放：服务端签发**短期有效的播放凭证**，浏览器用 VOD 播放器 SDK 播放；不返回视频原始文件地址，不提供下载。
- 1.0 播放器能力：播放 / 暂停、进度拖动、倍速、全屏、音量；断点续播；**一律点击播放，不做自动播放**（G-D38）。
- **微信内置浏览器**：视频可播、资料可预览；但微信不允许网页触发文件下载，因此微信内的下载按钮改为「复制链接，在浏览器打开」提示（G-D35）。不接微信 JS-SDK，也不依赖公众号。
- 清晰度由播放器按网络自动选择，不向学员暴露手动切换；字幕、弹幕、投屏、离线缓存不做。
- 播放期间按固定间隔上报心跳用于累计观看时长；VOD 播放器事件可作为心跳来源，但**业务进度以本系统落库为准**，不依赖 VOD 的播放统计。

### 5.3 资料预览

- PDF 与图片在线预览；不做全文检索、不做批注、不做打印控制。
- 预览与下载是**两个动作**：预览对全部有 `learning.read` 的人生效；下载按 §5.4 记录审计。

### 5.4 下载与审计（G-D04）

- 资料默认允许下载原件（G-D50：维护者可按课程关闭，对所有人一样；关闭后下载入口与附件链接都不提供，只能在线预览，尝试下载记一条拒绝审计）。**每次下载都记审计**：谁、何时、哪门课、文件标识、结果。
- **关闭下载不等于防截屏 / 防录屏**：在线预览的内容仍可被截屏、录屏或另存；产品不承诺阻止，只承诺不提供下载入口。
- 下载审计保留期跟随 B 域审计口径（1.0 为一年）；审计只有超管可查（B 域 `audit.read`）。
- 下架课程的已下载文件无法回收；下架只阻止新的下载与预览，这点必须对业务说清楚。
- 下载动作复用 `learning.read` + 审计，不单独拆 Capability（§10.4 已关闭）。

### 5.5 在学标记（并入课程列表，不建独立页面）

- 课程列表中，本人有进度的课程显示「在学」标记与最近学习时间；视频另显示续播位置。
- 列表支持按「在学」筛选；默认排序仍按最近更新，不因在学改变顺序（G-D13）。
- **不做**：独立的「我的学习」页面、收藏、错题本、学习时长统计页、证书。

### 5.6 边界

- 学员不能看到别人的进度，也不能看到汇总。
- 同一账号换设备后，进度以服务端记录为准；不做多端冲突合并（取更晚的进度）。

## 六、学习进度

### 6.1 记什么

| 课程类型 | 记录字段 |
|---|---|
| 视频 | 最后播放位置（秒）、累计观看时长、播放次数、首次学习时间、最近学习时间 |
| 资料 | 首次打开时间、最近打开时间、打开次数 |

不记录：完成状态、完成时间、得分、评价。

### 6.2 续播

- 再次打开视频时从**最后播放位置**附近继续，容差由实现定（建议数秒级）。
- **不做回退保护**（G-D18）：始终以最后上报位置为准。用户拖到开头后，下次从开头继续。这是有意的简单化——代价是误拖一次会丢掉续播点，收益是行为可预测、没有隐藏规则。
- 位置接近片尾（最后若干秒）时是否回到开头，属于播放器细节，由 spec 定，本文不冻结。
- 替换文件后位置保留：若新内容时长变短，位置截断到新时长范围内。

### 6.3 不定义"学完"（G-D02）

- 原因：1.0 没有考试、积分与学习任务，完成状态没有任何下游用途；过早定义"播到 90% 算学完"会让后续考核被迫继承一个未经验证的阈值。
- 因此：**任何页面、任何接口、任何报表都不得出现"已完成"字样**。谁需要完成度，必须先改本文档。
- 完成阈值、判定口径与防刷要求，与 G4/G5/G6 一起在 2.0 定。

### 6.4 进度归属

- 进度属于 **`User`**（登录主体），不绑定 `MediaStaff`。
- 原因：总部与分公司人员没有 `MediaStaff`，绑定会使他们无法记录进度；`store_staff` 的 User 与 `MediaStaff` 一对一（B 域 §8.3）已足以在需要时关联到人。
- 品牌范围取 `User` 当前的 grant；**授权收缩后，超范围课程立即不可见，但历史进度不删除**（与总 PRD §3.4 一致）。
- **换门店 / 换品牌按 B-D09 删旧建新**：旧 `User` 停用、新 `User` 用同一手机号重建并重新激活；旧 `User` 的进度保留但不能继续，新 `User` 从零开始。进度**不跟人迁移**，也不因换门店清空旧记录；汇总按 `User` 计数，换店后同一自然人在总量里可能出现两次（G-D41）。
- 换店后旧课程是否可见，取决于新 `User` 的 grant；旧 `User` 的进度记录不删除。

### 6.5 保留

- 学习进度与观看记录**长期保留**，不随 ODS 一年清理；具体清理策略随 I 域数据生命周期（I5）统一处理。
- **学员不能删除或清空自己的学习记录**（G-D31）：一是汇总数字会因此回落，二是 1.0 没有提出这类隐私要求。
- 用户停用后进度保留；用户恢复后可继续。

### 6.6 异常与不可信

- **只记录、不判定、不拦截**：心跳丢失、挂机播放、多设备并发、后台播放，1.0 都只如实记录。
- **唯一的例外是单次增量截断**（G-D19）：前端每 15 秒上报一次增量，单次超过 60 秒的部分不计入累计时长，但播放位置照常更新。目的是防止标签页被浏览器节流后一次性补报、或前端异常导致汇总虚高；正常的 15 秒心跳不会被截断。
- 锁屏与切后台期间不计时，观看时长会偏低。这是接受的结果：宁少算，不高估。
- 多设备同时学习取"最近时间"的那条进度，不做冲突提示。
- 汇总里的观看时长因此**不能当作考核依据**；这条必须在汇总页面写明，避免被直接拿去考核。

### 6.7 已知风险（已接受，不再讨论）

| 风险 | 具体后果 | 为什么接受 |
|---|---|---|
| **并发编辑后写覆盖**（G-D24） | 课程无版本历史（G-D10）且不能物理删除，两个维护者同时编辑时，被覆盖的内容**无法找回** | 当前总部维护者人数少，同时编辑同一门课概率低；加乐观锁的成本被认为高于收益 |
| **授权与审计**（G-D24） | 审计写失败时不阻断业务，只写日志并告警；可能产生「有变更、无审计」的记录 | 优先保证上传与编辑不被审计故障挡住；代价是可追溯性存在缺口 |
| **短期链接可被转发**（G-D25） | 播放凭证与下载签名 URL 在有效期内可被转发给未授权的人 | 内部培训内容，风险低；绑定用户校验会增加一次服务端往返，收益不明显 |
| **课程素材无独立备份**（G-D32） | VOD 与 OSS 只依赖云自身多副本；地域级故障时课程内容无法恢复，只能重新上传 | 备份成本高于重传成本；课程是内部资料，不是不可再生的业务事实 |

> 这两条不是「以后再说」，而是**已知且明确接受**。若将来出现一次实际丢失或审计缺口，应优先把这两条改成强约束，而不是临时补救。

## 七、总部汇总

### 7.1 能看什么（G-D03）

| 指标 | 口径 |
|---|---|
| 课程数 | 当前已发布、**且学员可播**（视频需转码完成）、品牌范围与查看者范围有交集的课程数（G-D27） |
| 学习人数 | 范围内课程上产生过进度的**去重 `User` 数**，含总部与分公司人员 |

> 换店删旧建新后，同一自然人对应两个 `User`，学习人数按 `User` 去重会计两次；这是 B-D09 与「进度按 `User`」的直接结果（G-D41）。
| 累计观看时长 | 视频心跳累计时长之和（不含资料预览） |
| 累计播放次数 | 视频播放开始次数之和 |

> **历史只增不减（G-D20）**：学习人数、累计时长、累计播放次数三项统计**所有课程（含已下架）**；只有「课程数」只算已发布。理由：叫「累计」的数字不应该因为下架一门课而变小，否则业务月底会看到无故下降且无法解释。代价是下架课程的历史仍计入分母，页面需注明。

- `platform_admin` 看全部品牌；`hq_manager` 只看授权品牌。**多品牌时默认显示合计**，可切换单品牌（G-D20）；合计按人去重，页面标明「合计已去重」。
- 「全部品牌」课程在统计时**按查看者的品牌范围计入**，不重复计数。

### 7.2 不能看什么

- 按人：谁学了、谁没学。
- 按门店 / 分公司 / 大区：任何组织层级下钻。
- 按课程：哪门课没人看。
- 完成率、排行榜、学习时长排名。

这些属于 G6 / G7（2.0）。1.0 的汇总只回答"这个品牌有没有人在学"，不回答"谁在学"。

### 7.3 口径要求

- 同一数字在汇总页与将来的报表、导出中必须**同口径**；1.0 只有一个入口，接口设计时也按同一口径实现。
- 时间范围：1.0 只给**累计总量**，不提供日 / 周 / 月筛选（G-D43）。若后续增加时间筛选，"累计"与"区间"必须分字段命名，不能混用一个数字。
- 「全部品牌」课程与具体品牌课程的合计要写明是否去重；默认按人去重计算学习人数。
- **播放次数的口径**：每次打开播放器并真正开始播放记一次，续播重新打开也计一次，暂停后继续不计。它衡量的是「打开次数」，不等于观看人数，也不等于观看时长；汇总页要用一句人话写明这一点，避免被当成"多少人看过"。

### 7.4 边界

- 汇总不返回任何个人标识，也不能通过参数下钻到个人。
- `branch_manager` 与 `store_staff` 调用汇总一律拒绝（不是返回空数据）。
- **1.0 不提供汇总导出**（G-D30）：导出能力归 E 域报表，G 不重复实现；总部需要数字时看页面。
- **VOD 与 OSS 的成本看阿里云账单**，1.0 不在平台内做学习域成本看板（G-D34）；成本看板归 I 域 2.0。

- 1.0 不做「跨品牌分发需审批」；若将来要求，再在 G 域加审核，不用改 B 域。

### 8.3 已登记的 Capability

- `learning.report.read`（查看学习汇总）：仅 `platform_admin` 与 `hq_manager`；B 域 v1.2 已登记，v1.18 保持。

- 下载复用 `learning.read` + 审计，**不新增 `learning.download`**（§10.4 已关闭）。

## 十一、验收标准

每条都必须能被业务人员判断真假；`[自动]` 指可由测试脚本验证，`[手工]` 指需要人在界面上操作确认。

### 汇总

- [ ] [自动] `platform_admin` 看全部品牌，`hq_manager` 只看授权品牌；
- [ ] [自动] 学习人数按 `User` 去重，多个品牌重复观看同一门「全部品牌」课程不重复计数；
- [ ] [自动] `branch_manager` 与 `store_staff` 调用汇总被拒绝，返回拒绝而非空数据；
- [ ] [自动] 汇总不返回任何个人标识，参数中无下钻到个人的入口；
- [ ] [手工] 汇总页明确标注「观看时长不可作为考核依据」。

### 2026-11-03 盘问新增验收

- [ ] `[自动]` 视频替换成功后旧 VOD 视频立即删除；删除失败进入重试，24 小时仍失败产生告警并进入孤儿清理
- [ ] `[自动]` 视频超 2 GB 或超 60 分钟、资料超 50 MB、封面超 5 MB 时，上传前被拒绝
- [ ] `[自动]` 汇总页没有日 / 周 / 月 / 自定义时间筛选；只有累计总量
- [ ] `[自动]` 学习汇总不进入 E 域指标字典，也不在点检表出现
- [ ] `[自动]` `hq_manager` 可编辑「全部品牌」课程；仍不能逐个勾选未授权品牌
- [ ] `[自动]` 换门店后旧 `User` 停用、新 `User` 重建；旧 `User` 进度保留但不能继续，新 `User` 从零开始；汇总按 `User` 计数
- [ ] `[自动]` 换店后同一自然人对应两个 `User`，学习人数计两次，页面有说明
- [ ] `[环境]` VOD 播放需要自有播放域名 + ICP；未备案时不进入生产验收，仅在测试环境用 OSS 签名 URL 联调

### 边界

- [ ] [自动] 同一 `User` 只能看到品牌范围内的课程，客户端无法通过改参数越权；
- [ ] [自动] 撤权后下一次请求即生效：看不到课程、不能播放、不能下载、汇总同步缩小；
- [ ] [自动] 课程素材不出现在 A 域 `MediaAsset` 查询结果中，两者互不引用。
