# 新媒体赋能平台 — 项目重构规划文档

**整理日期：** 2026年6月25日  
**状态：** 已确认

---

## 一、背景

### 业务背景

海信日立公司旗下三大品牌（海信、日立、约克），全国 42 个分公司，近万家门店。每逢五一、618、双11 等营销节点，需要约 2000 名门店新媒体专员在抖音发布 3-5 条短视频，更换主页背景图，为活动造势、扩大品牌声量、促进线下销售。

### 现有痛点

- 点检全靠人工，总部和分公司员工每周手动核查 2000 个账号，一个活动需要点检 4 次，耗费大量人力
- 没有精确的视频数据（点赞、评论、互动量），无法做效果评估
- 总部提供的脚本建议基本不被采纳，内容质量参差不齐
- 没有优化反馈机制，发布即结束，没有闭环

### 现有系统（lxk-BigSpard）

已有一套内部工具，解决了部分问题：

- 抖音账号自动爬取（Puppeteer，XHR 拦截）
- 背景图自动比对（Python + OpenCV SIFT）
- 活动关键词匹配（三层 OR-of-AND 体系）
- 视频数据采集和活动点检
- AI 脚本仿写（ASR + qwen-plus，基础版本）
- OSS 图片卸载（阿里云 OSS）

**局限：** 这套系统是总部内部工具，仅有 admin/viewer 两级权限，约 10-20 人使用，无法扩展到分公司和经销商，也无法支撑近万门店的规模。

## 二、目标产品

### 产品定位

**"新媒体赋能平台"** — 供总部、分公司、经销商三级人员使用的完整平台，实现从数据采集、内容分析、脚本赋能，到优秀内容筛选、广告投放记录的全链路覆盖。

### 六大核心功能模块

**模块一：自动化数据采集 + 智能点检**

通过 Puppeteer 自动化爬取 2000 个账号的公开数据（粉丝数、视频列表、点赞/评论/转发、主页背景图）。总部和分公司实时查看数据排名和点检结果，替代人工核查。

**模块二：账号质量分析评分**

基于账号的视频数据，从 6 个维度对账号质量进行 AI 评分，给出具体的优化建议，帮助专员提升内容质量。

**模块三：行业热点追踪**

接入 RSS 和蝉妈妈数据，实时展示抖音平台关于"中央空调""空调"等关键词的热点内容，为总部、分公司、经销商提供及时的内容参考。

**模块四：AI 脚本分析 + 仿写 + 分发**

从所有视频中筛选点赞量前 30 的优秀视频，通过 AI Agent Pipeline（视频画面分析 → 音频转写 → 脚本分析 → 脚本仿写 → 审核）生成高质量脚本，分发给适合的经销商专员。

**模块五：数字人带货视频生成（增值功能）**

脚本审核通过后，对接数字人生成平台（HeyGen/D-ID 等），自动生成带货视频。

**模块六：优秀视频筛选 + 广告投放记录**

从平台中筛选出优秀视频供总部参考，总部人员在广告平台（巨量引擎等）手动完成投放操作。平台提供轻量的投放记录登记和不定期的成单数据录入功能，用于统计投放效果和计算相应奖励。

> 此模块为轻量实现，不做程序化自动投流，仅作数据记录和汇总。

## 三、技术选型

### 整体架构

```
新平台（media-platform）              现有项目（lxk-BigSpard）
────────────────────────              ────────────────────────
Vue 3 前端（新建）                    继续运行（过渡期）
Node.js 后端（新建）                  爬虫继续采集数据
BullMQ 任务队列（新增）               活动点检继续使用
Dify AI 平台（新增）        ←─────── 共用同一个 MySQL
Redis 缓存 + 队列（新增）
```

### 技术栈

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端 | Vite + Vue 3 + Element Plus + Vue Router + Pinia | 企业后台 UI，替代现有纯 HTML |
| 后端 API | Node.js + Express | 复用现有路由结构，扩展权限中间件 |
| 任务队列 | BullMQ + Redis | 替代手动触发爬虫，支持 2000 账号并发调度 |
| 数据库 | MySQL 8.0（继续用，不切换 PostgreSQL） | 扩展现有 15 张表，新增用户/任务相关表 |
| AI 平台 | Dify（私有化部署） | 编排 AI Agent 工作流，含知识库管理 |
| AI 模型 | 阿里云 DashScope（qwen-plus + qwen-vl + qwen3-asr-flash） | 文本分析、多模态视频分析、语音转写 |
| 图片存储 | 阿里云 OSS（继续用） | 封面图、头像、背景图全部卸载到 OSS |
| 部署 | Docker Compose + Nginx + 阿里云 ECS | 新服务器：4核8G，50G ESSD，香港节点 |
| 登录方式 | 邀请制 + 手机号 + 密码 | 管理员批量导入用户，用户设置密码 |

### 关于数据库的决策

Dify 自带独立的 PostgreSQL，仅供 Dify 内部使用（存工作流配置、知识库索引）。业务数据（门店、视频、活动、用户）继续使用 MySQL，两者完全隔离，不需要迁移数据库。

## 四、旧项目的处置方案

**过渡期（新平台开发阶段）：** 旧项目继续运行，爬虫继续采集数据，活动点检继续使用，为新平台积累数据。

**新平台稳定后：**
- GitHub 仓库打 Tag（`v1.0-archive`），设为只读归档状态
- 云服务器停掉 `douyin-web` 和 `douyin-scraper` 容器
- MySQL 数据保留，新平台共用同一实例

## 五、服务器规划

| 项目 | 配置 |
|------|------|
| 服务器型号 | 阿里云 ECS ecs.e-c1m2.xlarge |
| CPU / 内存 | 4 vCPU / 8 GB |
| 存储 | 50 GB ESSD AutoPL |
| 网络 | 按使用流量，带宽峰值 10 Mbps |
| 地域 | 中国香港 |
| 预估月费 | ¥411/月（按月）/ ¥301/月（2年包年） |
| 图片存储 | 阿里云 OSS（独立计费，不占磁盘） |

**内存占用评估（峰值约 5GB，8G 够用）：**

```
MySQL（升配后）      300MB
Redis               50MB
两个 Node 服务      250MB
Dify 全套         1,500MB
Chromium 爬虫       800MB（爬取期间）
Linux 系统          400MB
──────────────────────────
日常待机          ≈ 2,800MB
爬取 + AI 同时工作 ≈ 5,000MB
```

8G 有充足缓冲，无需升配（除非后期要在服务器本地运行开源 LLM）。

## 七、分阶段开发计划

> **开发原则：** 每个阶段结束都有可交付的功能，旧项目在新平台稳定前持续运行不中断。

---

### 阶段零：搭环境（1周）

**目标：** 本地 Mac Docker 开发环境跑通，新项目骨架建好。

- 创建 `media-platform` 项目目录
- 配置 `docker-compose.dev.yml`（MySQL + Redis）
- Vue 3 + Element Plus 前端骨架（登录页能渲染）
- Express 后端骨架（`/api/auth/login` 能通）
- 数据库执行新的 `init.sql`（复用旧表 + 新建核心表）

**验收：** 用测试账号能登录，看到空首页。

---

### 阶段一：数据库改造 + 三级权限体系 + 数据看板（3-4周）

**目标：** 三级用户都能登录，看到属于自己权限范围内的数据。

数据库改造（与权限体系同步进行，具体方案见 `docs/database-design-v2.md`）：
- 修复现有表的已知问题
- 新增分公司主档表、三级用户表等核心表

后端：
- 邀请制注册流程（管理员批量导入手机号 + 角色）
- `getDataScope` 数据范围中间件（同一接口自动返回不同范围数据）
- 账号列表、活动点检接口（带权限过滤）

前端：
- 登录页（手机号 + 密码）
- 根据角色动态渲染侧边菜单
- 账号列表页（总部看全国，分公司看本区，专员看自己）
- 活动点检表页（复用现有数据，新前端展示）

**验收：** 三级用户登录后看到正确范围的数据。

---

### 阶段二：账号质量分析评分（2-3周）

**目标：** 每个账号有 AI 6维度评分和优化建议。

- 部署 Dify，配置 DashScope API Key
- 建立知识库（品牌规范文档、优秀案例、话术库）
- 搭 Dify 工作流：账号数据 → LLM 分析 → 6维度评分 + 建议
- 后端接入 Dify API，结果存回数据库
- 前端：账号详情页增加 AI 评分雷达图（ECharts）

**验收：** 点击任意账号，能看到 AI 评分结果和具体建议。

---

### 阶段三：爬虫迁移 + 自动化点检升级（2-3周）

**目标：** 爬虫从手动触发改为队列调度，支持 2000 账号批量处理。

- 引入 BullMQ + Redis 任务队列
- 爬虫从命令行触发改造为队列消费模式（核心逻辑不动，只改触发方式）
- Web 界面触发爬取任务，SSE 实时进度推送
- 点检看板升级（支持大区 / 分公司维度的完成率统计）

**验收：** Web 界面点击触发，后台自动调度爬取，前端实时看到进度。

---

### 阶段四：AI 脚本分析 + 分发（4-6周）

**目标：** 筛出优秀视频，AI 生成脚本，分发给经销商专员。

Dify 工作流：
- 视频多模态分析（画面 + 音频 + 文本三路合并）
- 脚本仿写工作流
- 审核工作流（品牌规范检查、违禁词过滤）

业务流程：
- 总部圈选优秀视频 → 触发 Dify 分析 → 生成仿写脚本 → 审核通过 → 分发给指定专员
- 经销商专员登录后看到「我的任务」，接收并查看脚本

**验收：** 完整跑通「视频分析 → 脚本生成 → 审核 → 经销商收到任务」全链路。

---

### 阶段五：热点追踪（1-2周）

**目标：** 展示抖音平台相关词的热点内容，供各级用户参考。

- 接入 RSS 数据源（行业媒体、抖音热榜）
- 蝉妈妈数据接口（需商务对接或爬虫方案）
- 前端热点信息展示页

---

### 阶段六：优秀视频筛选 + 广告投放记录（1-2周）

**目标：** 提供优秀视频汇总展示，支持手动录入投放记录和成单数据。

- 优秀视频筛选列表（按点赞/互动量排序，支持导出）
- 广告投放记录登记（视频链接、投放时间、预算、平台）
- 成单数据不定期录入（线下收集后手动回填）
- 投放效果汇总统计

> 此模块为轻量实现，不做程序化自动投流，仅作数据记录。

---

### 阶段七以后（按业务优先级推进）

- 数字人带货视频生成（对接 HeyGen/D-ID API）

---

## 八、开发环境说明

**本地开发（Mac）：**
- MySQL + Redis 跑在 Docker 容器里
- Node.js 后端和 Vue 前端直接在 Mac 上运行（支持热更新）
- Dify 独立 Docker Compose 本地启动
- 本地连接从旧服务器导出的数据库副本

**云服务器生产：**
- 所有服务打包成 Docker 镜像部署
- Nginx 反代（宝塔管理）
- HTTPS（Let's Encrypt）
- 旧项目和新平台共存于同一台服务器，共用 MySQL
