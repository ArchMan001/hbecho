## MAN-1 圈定条数与人工核对

1. 页面：判定计划 → 新建 → 选「日立双11-家装」→ 别名随意（例如「走查 MAN-1」）。
2. 第 1 页：时间窗保持默认；添加「文本识别」，关键词填一个你能人工数的词（例如「日立」）；添加「话题识别」填一个话题；确认圈定。
3. 记录：圈定内容（C1）、参与内容、未获取成功，及未获取成功的原因分布。

## MAN-4 零内容与同步缺口

在同一次执行里各找一位：

- **零内容 + 同步完整**：应是「不达标」（确实没发）。筛选「不达标」，找「零内容」标记的专员。
- **零内容 + 同步失败 / 有缺口**：应是「未获取成功」，原因显示「同步失败」，并有「同步缺口」徽标。筛选「同步不完整」。
- **有内容但同步有缺口**：若出现「不达标」，执行详情顶部应有「同步不完整」的提示。

| 检查 | 结果 | 备注 |
|---|---|---|
| 零内容 + 同步完整 → 不达标 | 是 / 否 | |
| 零内容 + 同步失败 → 未获取成功，原因可读 | 是 / 否 | |
| 同步不完整的提示读得懂，不会误导 | 是 / 否 | |

## 5. 命令

```bash
# 在 ECS 上，经 Workbench（实例 i-2zef8qpi1d2mldntjgrv）
J='docker exec hbecho-judgement-worker ./node_modules/.bin/tsx src/worker/judgement-main.ts'
$J plan list                       # 判定计划
$J run list --plan <planId>        # 执行记录
$J result circle <圈定 runId> --limit 20    # MAN-1 抽样：圈定明细
$J result participants <执行 ID> --result not_met --limit 20
$J explain --execution <执行 ID> --staff <专员 ID>

# 新同步进来的内容要再算一次文本信号（一次性容器，不需要 OSS 与能力服务）
T=hbecho-registry-registry-vpc.cn-beijing.cr.aliyuncs.com/hbecho/app:9bb35b580bc5
docker run --rm --network app_default --env-file /data/app/web.env --env-file /data/app/judgement.env \
  -e HBECHO_SIG_ACTOR=user:1 -e HBECHO_SIG_CAPABILITIES=rule.definition.manage,rule.definition.read -e HBECHO_SIG_BRAND_SCOPE=all \
  $T ./node_modules/.bin/tsx src/worker/signals-main.ts scan --once
```
