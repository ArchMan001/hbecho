# ADR-0010 · 组织范围与品牌集合同等求交

- **状态**：accepted
- **日期**：2026-11-02
- **决策人**：刘学奎
- **推翻**：ADR 未决选型 #7「Branch 范围是否与显式品牌 grant 求交」的未决状态；「组织范围自己就决定了可见品牌」的读法

## 背景

v2 的组织树里，**品牌不是组织树的父节点**：

- 大区、分公司、板块、经销商都不带 `brand_id`，是跨品牌共享对象；
- 只有门店带 `brand_id`，门店是单品牌；
- 账号、内容、媒资挂在门店或专员之下，因此才带品牌。

一个用户的 `DataScope` 由两部分组成：组织范围（如「北京分公司」子树）与显式的品牌集合。由于分公司可以同时挂多个品牌的门店，这两部分不一定是包含关系。

例：北京分公司下有海信门店 A 与科龙门店 B。某分公司经理组织范围=北京分公司，品牌授权=海信。

- 若组织范围自己决定可见品牌，他能看到门店 B 及其账号——这是跨品牌数据泄露；
- 若两者求交，他只看得到门店 A。

B 域 PRD 与 G 域 PRD 早已按「组织 × 品牌」写，但 ADR 一直把它列为未决选型，导致实现时仍可能被读成「组织范围内全品牌可见」。

## 决定

### 1. DataScope 是交集，不是推导

```text
DataScope = 组织范围（子树） ∩ 显式品牌集合
            + 是否仅本人
```

- 品牌集合必须显式授予，不从组织推导；
- 组织在范围内、但品牌未授予的对象**不可见**；
- 需要跨品牌时，显式授予多个品牌；不提供「因为组织大，所以自动获得全部品牌」的捷径。

### 2. 对象的品牌位置按 v2

| 层级 | 是否带品牌 | 说明 |
|---|---|---|
| 大区 / 分公司 / 板块 / 经销商 | 否 | 跨品牌共享对象，只有超管可改其结构 |
| 门店 | 是 | 门店单品牌，`brand_id` 是门店身份的一部分 |
| 账号 / 内容 / 媒资 | 继承门店或专员的品牌 | 交集在门店及以下生效 |

### 3. 停用与无法映射分开处理

- 品牌或组织**停用**不影响已授予的读范围；停用只影响新业务与采集，恢复收窄时不去掉停用对象；
- 组织或品牌**不存在、无法映射**时，DataScope 解析失败：返回 403 并记可处理问题，不返回空列表、不回退成「同品牌全量」。

## 备选方案与不选原因

| 方案 | 不选原因 |
|---|---|
| 不求交：组织范围内全品牌可见 | 跨品牌共享的分公司会默认泄露其他品牌数据；要收窄只能靠拆组织，无法用授权表达 |
| 按角色区分：分公司只按组织、总部只按品牌 | 规则分角色，实施与解释都多一层；且分公司经理同样会遇到多品牌分公司 |
| 给组织树上的节点加品牌 | 会把品牌塞进组织身份，与 v2「门店单品牌、上层跨品牌」的基线冲突，并造成同一分公司多条记录 |

## 后果

- 创建 `hq_manager` / `branch_manager` 时必须同时指定组织范围与品牌集合；品牌集合为空时只能看到空结果（合法空集），不是全量；
- 用户管理、批量导入的授权校验必须同时验证「组织 ⊆ 管理者组织」与「品牌 ⊆ 管理者品牌」；
- 各资源的 `ScopeStrategy` 必须显式实现交集，未注册策略仍然默认拒绝；
- 验收覆盖：组织在范围内但品牌未授权的对象不可见；跨品牌分公司不泄露；停用对象仍可读；无法映射返回 403。
